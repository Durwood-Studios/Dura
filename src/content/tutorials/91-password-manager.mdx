## Overview

Build a complete local teaching CLI, then try to break its storage assumptions. Use fictional credentials throughout. The project encrypts bounded records, prompts for hidden input, searches entries, generates passwords, copies temporarily, deletes entries, and exports encrypted snapshots. It is not an audited password manager for daily credentials.

The runnable JavaScript project uses Node.js built-ins and no runtime dependencies. Read its source alongside these ten steps; all helpers and commands are included. The files are ECMAScript modules, so no generated TypeScript configuration or missing build step is required.

[Download the complete password-vault lab](/api/labs/password-vault) · [Source and operating limits](/labs/password-vault/README.md)

## Step 1: Run the verified project

Extract the download into a private disposable directory with Node.js 22 or later:

```bash
npm ci
npm test
npm start -- help
```

The eight tests cover authentication failure, malformed data, failed and stale writes, input handling, generation bounds, and clipboard changes. They use fictional fixture data and temporary files. A passing fixture suite is evidence about these cases, not a security certification.

## Step 2: Define the bounded record

Read `validateVault` in `vault.mjs`. Version 1 allows at most 1,000 uniquely identified entries, each with a name, username, and password. It rejects oversized fields, C0/C1 terminal control characters and DEL, unknown fields, and duplicate IDs. The encrypted file is capped at two megabytes. Missing data is distinct from damaged data: corruption never means “start an empty vault.”

Try adding a duplicate ID in a test fixture. Explain why validation belongs after decryption as well as before saving.

## Step 3: Derive an encryption key

`encryptVault` creates a fresh 32-byte salt and uses PBKDF2-HMAC-SHA256 with 600,000 iterations to derive a 32-byte key. This is a fixed format parameter, not a value supplied by an untrusted vault file. Changing it requires an explicit format migration.

A salt does not need secrecy. Its purpose is to make the same passphrase produce independently derived keys. The passphrase remains the main protection against offline guessing. Measure derivation latency on your hardware; this lesson does not promise an unlock time.

Consult [Node's PBKDF2 documentation](https://nodejs.org/docs/latest-v22.x/api/crypto.html#cryptopbkdf2syncpassword-salt-iterations-keylen-digest) and [OWASP's work-factor guidance](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). Password-storage recommendations do not certify an encrypted vault.

## Step 4: Authenticate before trusting plaintext

AES-256-GCM uses a fresh 12-byte nonce for every encryption. The authentication tag protects ciphertext, and additional authenticated data binds this implementation's format identifier. Decryption validates the envelope before derivation, verifies the tag, then parses and validates plaintext.

Run the tampering test. Change one ciphertext hex digit and verify decryption fails without modifying the file. Wrong-passphrase and damaged-data failures deliberately give the same message.

## Step 5: Save without overwriting a newer snapshot

Follow `saveVault`: obtain the exclusive cooperative lock; compare the current bytes with the loaded snapshot; write encrypted bytes to a new same-directory file; synchronize that file; replace the destination by rename; release the lock. Only a successful return permits a success message.

The failure-injection test throws before rename and proves the previous encrypted bytes remain intact. The stale-writer test proves a second app session cannot overwrite a newer app save. A malicious local process is outside this cooperative protocol. Parent-directory synchronization and complete power-loss recovery remain outside this teaching implementation.

## Step 6: Enter fictional secrets through a terminal

```bash
npm start -- init
npm start -- add Example student
npm start -- list Example
```

Use a fictional master passphrase of at least 12 characters. The hidden input handler enables raw mode before printing its prompt, handles whole pasted chunks, and restores the previous mode after completion or cancellation. Piped passphrases are rejected. Entry names and usernames remain visible command arguments, so use fictional values there too.

Every command ends its own session; the program does not cache an unlocked vault between commands. JavaScript cannot guarantee erasure of every in-memory string copy.

## Step 7: Generate within explicit limits

```bash
npm start -- generate 24
npm start -- generate NaN
```

The first command generates 24 independent characters using `crypto.randomInt`; the second fails. Length must be an integer from 16 through 128. The generator does not assign a strength score from character-class counts or promise compatibility with every website's policy. Generated output appears in terminal scrollback.

## Step 8: Treat the clipboard as shared state

Use the exact ID printed by `list`:

```bash
npm start -- copy ENTRY_ID
```

Keep the process open for 30 seconds. It compares the clipboard with the copied value before requesting a clear; a changed value is preserved. That comparison and clear are not atomic OS operations, and clipboard history may retain old values. Cancellation or missing utilities can prevent clearing.

The adapters require macOS `pbcopy`/`pbpaste`, Windows PowerShell, or Wayland `wl-copy`/`wl-paste`. Linux X11 is not supported. Automated tests use injected adapters, not your actual clipboard; verify your platform manually with fictional text.

## Step 9: Back up and delete deliberately

```bash
npm start -- backup fictional-backup.enc
npm start -- delete ENTRY_ID
npm start -- list
```

Backup refuses to overwrite an existing destination and preserves encrypted bytes. Deleting an entry changes the current vault, not older backups. To test recovery, work in a separate disposable directory, create `.teaching-vault`, and copy the fictional encrypted backup there as `vault.enc`; then, while your working directory is that separate directory, run `node /absolute/path/to/extracted/password-vault/cli.mjs list` with the same passphrase. Replace the example absolute path with the actual extracted CLI path; `npm start` in an empty recovery directory has no package to run. Do not overwrite the original while testing recovery.

The lab does not read the old tutorial's `~/.pwmanager` location or migrate existing personal vaults. Unix creation permissions are defaults, not universal Windows ACL guarantees.

## Step 10: Review the failure contract

Explain why these outcomes differ: wrong passphrase, corrupt JSON, stale writer, failed replacement, orphaned lock, changed clipboard, and missing clipboard utility. For each, identify which committed bytes remain and whether a user can safely retry.

The completed project demonstrates encryption and explicit failure handling using fictional data. Its README records unresolved platform, power-loss, memory-erasure, and adversarial-filesystem boundaries. Keep using an independently reviewed password manager for actual credentials; this project teaches how to evaluate such systems without claiming to replace them.
