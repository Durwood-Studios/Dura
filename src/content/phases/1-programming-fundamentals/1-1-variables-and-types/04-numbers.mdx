## Why this matters

Every counter, price, score, timer, pixel coordinate, and loop index in a program is a number. JavaScript makes numbers look simple — the number type handles both integer and decimal values. That simplicity hides a few sharp edges you will hit eventually.

## Start with something familiar

Imagine a ruler with fixed markings: some lengths land exactly on a mark and others must be rounded. A numeric representation also has finite precision.

## The mental model

> JavaScript number values use finite-precision binary arithmetic. Remainders classify divisibility; approximate results need comparison rules appropriate to their scale.

## The number type

Unlike languages that separate integers from decimals, JavaScript uses `number` for the integer and decimal examples here. A separate `bigint` type represents arbitrary-size integers and is outside this lesson. Under the hood it is a 64-bit floating-point value (IEEE 754).

```javascript
console.log(typeof 42); // "number"
console.log(typeof 3.14); // "number"
console.log(typeof -7); // "number"
```

This means you can mix integers and decimals freely. It also means floating-point math applies to everything.

## Arithmetic

The basic operators work like a calculator:

```javascript
console.log(10 + 3); // 13
console.log(10 - 3); // 7
console.log(10 * 3); // 30
console.log(10 / 3); // 3.3333...
console.log(10 % 3); // 1   (remainder)
console.log(10 ** 3); // 1000 (exponent)
```

`%` is the **remainder** operator. It tells you what is left over after division. Useful for checking even/odd, cycling through a list, or formatting clocks.

## The floating-point trap

```javascript
console.log(0.1 + 0.2); // 0.30000000000000004
```

This is not a JavaScript bug. It is how every language that uses IEEE 754 floating-point works. `0.1` cannot be represented exactly in binary, as `1/3` cannot be represented exactly in decimal.

**Rule of thumb:** when an operation can introduce rounding and the requirement allows approximate results, compare within an appropriate tolerance. For example, `Math.abs(0.1 + 0.2 - 0.3) < 0.0001` checks the absolute difference. Math.abs removes a negative sign; the tolerance must fit the scale and requirements. Exact equality is still appropriate for exact-value requirements. For money, use integers (the smallest unit of the currency, not the major unit) or a dedicated library.

## Special number values

```javascript
console.log(1 / 0); // Infinity
console.log(-1 / 0); // -Infinity
console.log("abc" * 2); // NaN  — "Not a Number"
console.log(typeof NaN); // "number"  — yes, really
```

`NaN` is the result of math that does not make sense. The joke is that `typeof NaN` is `"number"`. Check for it with `Number.isNaN(value)`.

## Parsing strings to numbers

```javascript
console.log(Number("42")); // 42
console.log(parseInt("42px")); // 42 — stops at the first non-digit
console.log(parseFloat("3.14 degrees")); // 3.14
console.log(Number("hello")); // NaN
```
