## Why this matters

Imagine a checkout showing a price of 2 and a delivery charge of 3. You expect a total of 5. A program can accidentally display 23 instead if it treats one of those amounts as text. By the end of this lesson, you can explain that mistake and predict which result JavaScript will produce.

No programming syntax is assumed here. We will introduce every symbol needed for the exercises.

## Start with something familiar

On a shopping receipt, a quantity such as 2 is something you can count. A product name such as “apple” is text. A question such as “paid?” has a yes-or-no answer. All three carry information, but you use them differently.

A **value** is one piece of information a program can work with. A **type** is its category. JavaScript is the programming language we will use to describe these values.

## The mental model

> Picture each value with a category label attached. The label tells JavaScript whether `+` should add quantities or join text. Two values that look similar to you can have different labels.

## Writing and inspecting values

These are the three categories we will practice:

- A **number** represents a quantity: `42`, `-3.14`, or `0`. Do not put quotation marks around it.
- A **string** represents text: `"hello"` or `"42"`. Matching single or double quotation marks mark its boundaries; the quotation marks are not part of the text.
- A **boolean** represents one of two answers: `true` or `false`. These words have no quotation marks. `"true"` is a string instead.

An **expression** is code that produces a value. For example, `2 + 3` produces `5`. The symbol `+` adds two numbers. With strings, it joins their text, an operation called **concatenation**.

`typeof` asks for a value's type and produces its name as a string. For example, `typeof 42` produces `"number"`.

To display a result, use `console.log(...)`. The **console** is a text-output area; `log` means display a message there. Put the expression to display inside the parentheses. A semicolon ends the instruction. You can run these complete lines in a JavaScript console:

```javascript
console.log(typeof 42);
console.log(typeof "42");
console.log(typeof true);
```

The output is `number`, then `string`, then `boolean`. The console may display strings without their quotation marks; `typeof` still gives you the category.

## How the category changes the result

```javascript
console.log(2 + 3);
console.log("2" + "3");
console.log(2 + "3");
```

The first line adds two quantities and displays `5`. The second joins two strings and displays `23`. The third also displays `23`: because one operand (a value beside `+`) is a string, JavaScript converts the number `2` into the string `"2"` and joins the text.

This automatic conversion is **type coercion**. For the numbers and strings in this lesson, `+` adds when both are numbers and joins when either is a string. Changing `"3"` to `3` fixes the checkout example by making both operands numbers.

JavaScript has other categories too. Its seven **primitive** types (types whose values are not objects) are number, string, boolean, undefined, null, bigint, and symbol. `null` represents intentional absence; `undefined` commonly represents a value that has not been supplied. Objects group information, and functions are callable objects. You do not need to create these other values to complete this lesson. Also, `typeof` has historical exceptions: `typeof null` returns `"object"`, and it reports callable functions as `"function"`; its output is not a complete list of the language's types.

## What you learned

- Classify quantities as numbers, quoted text as strings, and unquoted `true` or `false` as booleans.
- Use `typeof` to identify these three categories; use `console.log(...)` to display a result.
- Predict addition when both operands are numbers and concatenation when either is a string.
- Explain number-to-string coercion and remove unintended quotation marks when the task requires numeric addition.
