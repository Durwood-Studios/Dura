## Why this matters

Imagine you are building software for an animal shelter. You have `Dog`, `Cat`, and `Bird` classes. All three need `name`, `age`, and a `describe()` method — you would copy that code into each class. Now a bug appears in `describe()`. You fix it in `Dog`... but forget `Cat` and `Bird`. The shelter's system is now inconsistent.

<VocabTooltip slug="inheritance">Inheritance</VocabTooltip> solves this. You write the shared
behavior once in a parent class, and child classes automatically get everything from it. Fix the
parent, and every child benefits. This is not just a convenience — it is how large codebases stay
maintainable over time.

## The "specialized version" analogy

Think about vehicles. Every vehicle has wheels, a fuel source, and can move. A car is a vehicle that also has doors and a steering wheel. A motorcycle is a vehicle that also has handlebars. Both are vehicles — they share the common vehicle traits — but each adds its own specialized features.

<VocabTooltip slug="inheritance">Inheritance</VocabTooltip> models this: a
<VocabTooltip slug="subclass">subclass</VocabTooltip> (child) extends a
<VocabTooltip slug="superclass">superclass</VocabTooltip> (parent), receiving all of the parent's
properties and methods plus any new ones the subclass defines.

> **A subclass IS a superclass — plus more. `Dog extends Animal` means every Dog is also an Animal.**

## A parent class

```javascript
// Animal is the parent (superclass) — shared behavior lives here
class Animal {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  describe() {
    console.log(`${this.name} is ${this.age} years old.`);
  }

  sleep() {
    console.log(`${this.name} is sleeping.`);
  }
}
```

## Extending with `extends` and `super`

```javascript
// Dog IS an Animal — it inherits everything Animal has
class Dog extends Animal {
  // The constructor must call super() first — this runs the parent constructor
  // so that this.name and this.age get set before Dog adds its own properties
  constructor(name, age, breed) {
    super(name, age); // Run Animal's constructor first
    this.breed = breed; // Then add Dog-specific properties
  }

  // Dog adds its own method on top of Animal's methods
  bark() {
    console.log(`${this.name} says: Woof!`);
  }

  // Dog also overrides describe() — but we will cover that in the next lesson
}

class Cat extends Animal {
  constructor(name, age, isIndoor) {
    super(name, age);
    this.isIndoor = isIndoor;
  }

  purr() {
    console.log(`${this.name} purrs contentedly.`);
  }
}

const luna = new Dog("Luna", 3, "Labrador");
const whiskers = new Cat("Whiskers", 5, true);

// Dog inherits Animal's methods
luna.describe(); // Luna is 3 years old.
luna.sleep(); // Luna is sleeping.
luna.bark(); // Luna says: Woof!

// Cat also inherits them
whiskers.describe(); // Whiskers is 5 years old.
whiskers.purr(); // Whiskers purrs contentedly.

// But Cat cannot bark — that's Dog-specific
// whiskers.bark(); // TypeError: whiskers.bark is not a function
```

## Why `super()` is required

When a subclass has a constructor, JavaScript requires you to call `super()` before accessing `this`. This is because the parent class is responsible for initializing the core identity of the object — if you skip it, `this` does not yet exist.

```javascript
class Vehicle {
  constructor(make, model) {
    this.make = make;
    this.model = model;
    this.speed = 0; // All vehicles start stopped
  }

  accelerate(amount) {
    this.speed += amount;
    console.log(`${this.make} ${this.model} is going ${this.speed} mph`);
  }

  brake(amount) {
    // Never let speed go negative — a car stopped is not reversing
    this.speed = Math.max(0, this.speed - amount);
    console.log(`${this.make} ${this.model} slowed to ${this.speed} mph`);
  }
}

class ElectricVehicle extends Vehicle {
  constructor(make, model, batteryKwh) {
    // super() must come before any reference to `this`
    super(make, model);
    this.batteryKwh = batteryKwh;
    this.chargePercent = 100;
  }

  charge() {
    this.chargePercent = 100;
    console.log(`${this.make} ${this.model} is fully charged.`);
  }

  status() {
    console.log(
      `${this.make} ${this.model} — Speed: ${this.speed} mph, Battery: ${this.chargePercent}%`
    );
  }
}

const tesla = new ElectricVehicle("Tesla", "Model 3", 82);

// Inherits Vehicle's methods
tesla.accelerate(60); // Tesla Model 3 is going 60 mph
tesla.brake(20); // Tesla Model 3 slowed to 40 mph

// Has its own methods too
tesla.charge(); // Tesla Model 3 is fully charged.
tesla.status(); // Tesla Model 3 — Speed: 40 mph, Battery: 100%
```

## Checking the inheritance chain

You can verify that an object is an instance of a parent class using `instanceof`:

```javascript
console.log(tesla instanceof ElectricVehicle); // true
console.log(tesla instanceof Vehicle); // true — it IS a Vehicle
console.log(luna instanceof Dog); // true
console.log(luna instanceof Animal); // true — Dog IS an Animal
console.log(luna instanceof Cat); // false — Dog is not a Cat
```

## What you learned

- `extends` creates an inheritance relationship — the subclass automatically receives all parent properties and methods.
- `super()` in a subclass constructor runs the parent constructor and must come before any use of `this`.
- Subclasses can add new properties and methods without touching the parent.
- `instanceof` lets you check whether an object belongs to a class or any of its ancestors.
- Use inheritance when a class truly IS a specialized version of another — not just when they share a few fields.

The next lesson goes deeper: what happens when a subclass defines a method that the parent already has? That is <VocabTooltip slug="polymorphism">polymorphism</VocabTooltip>, and it is one of the most powerful ideas in object-oriented programming.
