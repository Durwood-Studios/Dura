## Why this matters

Every program models something — users, products, orders, characters, sensors. Without a way to group related data and behavior together, you end up with scattered variables and functions that are hard to keep in sync. When you add a new user, do you really want to remember to update `userName`, `userEmail`, and `userAge` separately? Or would it be better to have one `User` thing that holds all of that?

<VocabTooltip slug="class">Classes</VocabTooltip> solve this. They let you define a template for
related data and behavior once, then stamp out as many copies as you need — each independent, each
carrying its own data. This is how professional codebases manage complexity at scale.

## The blueprint analogy

Imagine a house blueprint. The blueprint itself is not a house — you cannot live in it. But you can use it to build houses. Every house built from the same blueprint has the same rooms in the same places, but each house has different paint colors, different furniture, different people living in it.

A <VocabTooltip slug="class">class</VocabTooltip> is that blueprint. An <VocabTooltip slug="object">object</VocabTooltip> (also called an <VocabTooltip slug="instance">instance</VocabTooltip>) is a house built from it. The class describes the shape; the object is the real thing with real data.

> **A class is a blueprint. An object is one specific thing built from that blueprint.**

## Defining a class

```javascript
// A class describes the shape of a thing — its properties and behaviors
class Dog {
  // Properties are the data each dog carries
  name = "";
  breed = "";
  age = 0;

  // Methods are the behaviors a dog can perform
  bark() {
    // `this` refers to the specific dog instance calling this method
    console.log(`${this.name} says: Woof!`);
  }

  describe() {
    console.log(`${this.name} is a ${this.age}-year-old ${this.breed}.`);
  }
}
```

## Creating objects from the class

```javascript
// The `new` keyword builds a new object using the class blueprint
const luna = new Dog();
luna.name = "Luna";
luna.breed = "Labrador";
luna.age = 3;

const rex = new Dog();
rex.name = "Rex";
rex.breed = "Beagle";
rex.age = 7;

// Each object is independent — changing rex doesn't affect luna
luna.bark(); // Luna says: Woof!
rex.bark(); // Rex says: Woof!

luna.describe(); // Luna is a 3-year-old Labrador.
rex.describe(); // Rex is a 7-year-old Beagle.
```

## Properties and methods

A <VocabTooltip slug="property">property</VocabTooltip> is data stored on an object — the adjectives of a thing (`name`, `age`, `color`).

A <VocabTooltip slug="method">method</VocabTooltip> is a function stored on an object — the verbs of a thing (`bark()`, `run()`, `save()`).

```javascript
class BankAccount {
  owner = "";
  balance = 0;

  // A method can read and change the object's own properties
  deposit(amount) {
    // Guard against negative deposits — bad data should fail loudly
    if (amount <= 0) {
      console.error("Deposit amount must be positive");
      return;
    }
    this.balance += amount;
    console.log(`Deposited $${amount}. New balance: $${this.balance}`);
  }

  withdraw(amount) {
    // Reject withdrawals that would overdraft — business rule lives here
    if (amount > this.balance) {
      console.error("Insufficient funds");
      return;
    }
    this.balance -= amount;
    console.log(`Withdrew $${amount}. New balance: $${this.balance}`);
  }
}

const account = new BankAccount();
account.owner = "Alice";
account.balance = 1000;

account.deposit(500); // Deposited $500. New balance: $1500
account.withdraw(200); // Withdrew $200. New balance: $1300
account.withdraw(2000); // Insufficient funds
```

## What you learned

- A class is a blueprint; an object (instance) is one specific thing built from that blueprint.
- Properties store data on an object; methods define what that object can do.
- The `new` keyword creates a fresh, independent object from a class.
- Multiple objects built from the same class do not share data — changing one never affects the others.
- Grouping related data and behavior into a class makes code easier to manage as complexity grows.

In the next lesson, you will learn how to set property values at creation time using a special method called a <VocabTooltip slug="constructor">constructor</VocabTooltip>, so you never have to set each property manually after calling `new`.
