## Why this matters

A robotics example gives you a Python script, but your earlier exercises used JavaScript. Familiar ideas are present behind different punctuation. A focused translation lets you read the script and distinguish language mistakes from mistakes in the data contract.

## Start with something familiar

Two kitchens can follow the same recipe using different labels on their equipment. The steps still matter: check ingredients, repeat a preparation step, return a result. Python expresses those programming steps with different syntax, including indentation that the interpreter actually reads.

## The mental model

> Keep the input/output contract in your head while changing the language. Python indentation defines which statements belong to a function, loop or condition; it is not only formatting.

## The mechanism

`def` introduces a function. A colon begins its body, and consistently indented lines belong to that body. `return` sends a value back. A Python list uses square brackets; a **dictionary** associates keys with values using braces. `row["rpm"]` reads a required key; `row.get("rpm")` instead returns `None` if it is absent. `None` represents no value, not the number zero.

`for row in rows` visits each list element. `if` selects a branch; `and` combines conditions, and Python uses `True` and `False` for Boolean values. There is no `let` declaration or required semicolon. The example below accepts decimal RPM strings representing nonnegative integers. It rejects signs, decimal points, blank fields and missing values deliberately; this is a teaching input format, not every valid physical measurement format.

Save as `sensor_rows.py` and run with `python3 sensor_rows.py` in an environment with Python 3 installed:

```python
def total_rpm(rows):
    total = 0
    for row in rows:
        text = row.get("rpm")
        if not isinstance(text, str) or not text.isascii() or not text.isdecimal():
            raise ValueError("rpm must be an ASCII nonnegative integer string")
        total += int(text)
    return total

assert total_rpm([{"rpm": "1200"}, {"rpm": "0"}]) == 1200
assert total_rpm([]) == 0
for invalid in [{}, {"rpm": ""}, {"rpm": "-1"}, {"rpm": "unknown"}]:
    try:
        total_rpm([invalid])
    except ValueError:
        pass
    else:
        raise AssertionError("invalid row was accepted")
print("row contract passed")
```

`isinstance` checks the value's type before string methods are called. `int` converts the validated text into an integer. `raise` creates an **exception**, an explicit failure that interrupts the ordinary return path. The `try`/`except` block in the test expects that failure; its `else` runs only when no exception occurred. The empty list totals zero because there were no rows, which is different from inventing zero for an invalid row. Callers must decide whether an empty dataset is meaningful for their application.

These tests assume `rows` is a list of dictionaries; arbitrary objects remain outside the declared input contract. Production ingestion should validate that outer shape and bound input size. Python integers are not fixed-width C integers, but time and memory remain finite.

## What you learned

- Python function, branch and loop bodies are defined by indentation.
- Lists hold ordered values; dictionaries provide named fields.
- Validation and exceptions keep malformed data separate from real zero readings.
- Assertions reveal boundary mistakes and premature returns.
