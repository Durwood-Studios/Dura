## Why this matters

A sensor export contains a location named “North, Annex.” Splitting each line at commas silently invents an extra column. Before converting readings to numbers, preserve the file format’s actual field boundaries and validate its schema.

## Start with something familiar

An address can contain a comma without starting a new envelope. CSV quotation marks similarly protect separators inside a field. Reading punctuation as a delimiter without reading the quoting rules changes the data.

## The mental model

> CSV parsing answers where fields and records end. Schema validation then answers whether the expected fields and values are present. Correct parsing does not imply valid domain data.

## The mechanism

CSV is a family of delimited text conventions, so agree the delimiter, quoting, encoding and header contract with the producer. Use a CSV parser rather than splitting on commas or newline characters. A quoted field can contain commas or line breaks, and doubled quotes represent a quote within a quoted field.

This complete Python fixture accepts UTF-8 text already decoded by its caller. Its schema is exactly station,rpm, in that order, with a nonempty station and an ASCII nonnegative integer RPM string. A missing or extra field is rejected; a missing RPM is not converted to zero.

```python
import csv
import io

def read_readings(text):
    reader = csv.DictReader(io.StringIO(text, newline=""), strict=True)
    if reader.fieldnames != ["station", "rpm"]:
        raise ValueError("unexpected header")
    result = []
    for row in reader:
        rpm = row.get("rpm")
        if None in row or not row.get("station"):
            raise ValueError("extra field or empty station")
        if not isinstance(rpm, str) or not rpm.isascii() or not rpm.isdecimal():
            raise ValueError("invalid rpm")
        result.append((row["station"], int(rpm)))
    return result

assert read_readings('station,rpm\n"North, Annex",12\n') == [("North, Annex", 12)]
assert read_readings('station,rpm\n"Line\nTwo",0\n') == [("Line\nTwo", 0)]
assert read_readings('station,rpm\n') == []
for bad in ['station,rpm\nA,\n', 'station,rpm\nA,1,extra\n', 'rpm,station\n1,A\n']:
    try:
        read_readings(bad)
    except ValueError:
        pass
    else:
        raise AssertionError("invalid schema accepted")
print("CSV checks passed")
```

When opening an actual file, use the agreed encoding and newline="" so the CSV reader handles embedded newlines correctly. csv.Error indicates malformed CSV syntax; ValueError here indicates the application schema contract. A caller should report either as a failed import, with safe diagnostic context, rather than claim all rows loaded.

This example rejects the whole batch when a bad record appears. A different quarantine policy needs explicit accepted/rejected counts and record identities. Very large or untrusted files also need size, field-length and resource limits. CSV text later exported to a spreadsheet needs a separate formula-injection policy; parsing a field does not make every downstream interpretation safe.
