## Why this matters

Changing a brand color should not require searching fifty unrelated files. Yet replacing every blue with green can also turn an informational link into something that looks like a success message. Consistency needs meaning and behavior, not only matching hex codes.

## Start with something familiar

A transit system uses the same signs, route names and boarding rules at every station. A sign template alone would not tell staff when to display a closure notice. A **design system** similarly combines reusable visual choices, component behavior, usage guidance and a process for changing them.

## The mental model

> A token names a reusable decision; a component contract says where that decision applies and how the component behaves. The system is the shared agreement, not only a gallery of attractive screenshots.

## The mechanism

A **design token** is a named reusable value. A primitive token might be `--blue-700`; a **semantic token** names its job, such as `--action-background`. Separating them lets a theme change the value without making every component care which hue was selected.

CSS custom properties begin with `--`. `var(--action-background)` substitutes the property's computed value. Ordinary custom properties inherit from a parent unless overridden. A nearer declaration can therefore theme one region without rewriting every button. This mechanism does not guarantee that the selected colors have enough contrast: that must be checked for the actual state and background.

This complete document uses native button behavior and a focus outline:

```html
<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Button contract</title>
<style>
  :root {
    --action-background: #174ea6;
    --action-text: #ffffff;
    --focus-ring: #111111;
    --control-radius: 0.5rem;
  }
  body { background: white; color: black; font-family: sans-serif; }
  .action {
    background: var(--action-background);
    color: var(--action-text);
    border: 2px solid transparent;
    border-radius: var(--control-radius);
    min-height: 3rem;
    padding: 0.75rem 1rem;
    font: inherit;
  }
  .action:focus-visible {
    outline: 3px solid var(--focus-ring);
    outline-offset: 3px;
  }
  .action:disabled { opacity: 0.55; cursor: not-allowed; }
</style>
<p>Review is available after a draft is saved.</p>
<button class="action" type="button">Save draft</button>
<button class="action" type="button" disabled>Review draft</button>
</html>
```

The **component contract** includes more than these styles: it says this is an action, requires a descriptive label, uses a native button rather than a clickable `div`, and exposes disabled behavior through the HTML attribute. `type="button"` prevents an accidental form submission when the example is moved into a form. `:focus-visible` lets the browser identify when a visible focus indicator is needed, commonly during keyboard navigation. Do not remove all outlines as a visual cleanup.

This teaching fixture does not save anything: it demonstrates appearance and native state behavior. A real implementation must connect the Save action and announce its result appropriately. Disabled controls are skipped in ordinary keyboard tab navigation, so explain why the action is unavailable in nearby text rather than hiding the only explanation inside that control.

A useful change process names an owner, records what changed, previews affected states, and gives consumers migration instructions if the public contract changes. Renaming a token without updating its consumers can break styling even though the component markup is untouched. `var(--missing, black)` supplies a fallback when a variable is missing; it does not validate every possible supplied value or make a bad theme accessible.

## What you learned

- Semantic tokens preserve purpose when literal visual values change.
- A component contract includes HTML behavior, states and usage guidance as well as CSS.
- Native disabled behavior needs an explanation learners can still reach.
- Token changes require state, accessibility and consumer checks before rollout.
