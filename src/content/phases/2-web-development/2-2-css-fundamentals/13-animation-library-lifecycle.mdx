## Why this matters

A panel animates correctly once, then moves twice after navigation. An animation has a lifetime like an event listener. A library can coordinate motion, but the application still owns cleanup and access to content.

## Start with something familiar

A stage manager starts cues and cancels them when the scene ends. Leaving old cues running makes the next performance unpredictable. A timeline or tween similarly needs an owner and an end to its lifetime.

## The mental model

> Keep the usable final layout as the baseline. Animate only when appropriate, and remove the animation work when its owning view disappears.

## The mechanism

A tween changes selected properties over time. GSAP is one animation library; its `gsap.to` starts from current values and moves toward supplied values. Prefer transforms such as x for motion rather than continuously changing layout dimensions when the visual result permits it. A library does not make every animated property cheap.

The following complete ES module assumes GSAP3.11+ is installed in a separate practice project. The host calls mountMotion with an existing DOM element and calls the returned cleanup before removing the view. The element remains visible with or without motion.

```javascript
import { gsap } from "gsap";
export function mountMotion(panel) {
  const media = gsap.matchMedia();
  media.add("(prefers-reduced-motion: no-preference)", () => {
    gsap.fromTo(panel, { x: -12 }, { x: 0, duration: 0.25 });
  });
  return () => media.revert();
}
```

`matchMedia` manages animations created within its matching callback. Reverting restores their prior inline state and removes that registration's work. It is not the same as merely pausing an old animation and retaining its effects forever. The reduced-motion branch does not create the entrance movement; the panel is still present and usable. If the host adds unrelated listeners or timers, those need their own cleanup too.

Use CSS transitions when a small state change is enough; choose a library for coordination that merits the dependency and lifecycle work. Test keyboard focus during animation, preference changes while the page is open, and repeated mount/unmount. A decorative entrance must not be a prerequisite for reading the content.
