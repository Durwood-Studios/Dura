## Why this matters

Every application you ship eventually runs in front of real users. When it crashes, those users leave. When data goes missing or a button stops working, support tickets pile up and trust erodes. A significant portion of production JavaScript bugs share a common trait: they happen because a function received a value it was not designed to handle — a string where a number was expected, `undefined` where an object was required, a typo in a property name that JavaScript silently ignores.

TypeScript is a language built to catch these bugs before your code ever runs. It is the difference between finding a problem at 2am when users are awake and finding it the second you type it. Every major JavaScript project — VS Code, Slack, Airbnb's web client, Angular, Vue 3, Svelte — runs on TypeScript. Understanding why it exists tells you what category of problems it solves and what trade-offs it introduces.

## The problem TypeScript was built to solve

Imagine you are building a function that calculates a user's discount. A colleague calls your function with the wrong argument type — passing a string `"10"` instead of a number `10`. JavaScript will not warn you. It will run the code and produce a silently wrong answer.

```javascript
// Plain JavaScript — no errors thrown, just wrong output
function applyDiscount(price, discountPercent) {
  // JavaScript will coerce "10" to a number here, giving 90
  // But what if discountPercent is "abc"? NaN. Silently.
  return price - (price * discountPercent) / 100;
}

// This call looks fine but discountPercent is a string
const total = applyDiscount(100, "abc");
console.log(total); // NaN — no crash, just silent garbage
```

This bug might travel through your system for hours — written to a database, displayed in a UI, billed to a customer — before anyone notices. By then it is a data integrity problem, not just a code problem.

**TypeScript is just JavaScript with a layer that verifies types before your code runs.**

> _TypeScript is a spell-checker for the shape of your data — it reads your code before execution and flags mismatches._

When you add types to the `applyDiscount` function, TypeScript catches the wrong argument at the moment you type it, in your editor, before the code ever runs.

## What TypeScript actually is

TypeScript is a **superset** of JavaScript. Every valid JavaScript program is a valid TypeScript program. TypeScript adds a syntax for declaring the shapes of values and then checks those declarations. When you build for the browser, a step called **transpilation** removes all the TypeScript-specific syntax — the output is plain JavaScript that any browser can run.

The type information exists only for the developer and the build tool. It disappears at runtime. This means TypeScript has zero cost at runtime — it cannot slow down your running application.

```
Your TypeScript source
        ↓  tsc (TypeScript compiler) or Babel
Plain JavaScript (types stripped out)
        ↓  browser / Node.js
Your running app
```

The compiler's job is to read your code and report any **type errors** — places where the shape of a value does not match what you declared. If it finds errors, it tells you before you ship. This is called **static analysis**: analysis that happens without running the code.

## Two kinds of errors TypeScript catches

### 1. Wrong value types

```typescript
function calculateArea(width: number, height: number): number {
  // The ": number" annotations tell TypeScript what to expect
  return width * height;
}

// TypeScript catches this immediately — no need to run the code
calculateArea("5", 10);
//            ^^^
// Argument of type 'string' is not assignable to parameter of type 'number'.
```

### 2. Accessing properties that do not exist

```typescript
interface User {
  id: number;
  name: string;
  email: string;
}

function greetUser(user: User): string {
  // TypeScript knows the shape of User — it flags the typo before runtime
  return `Hello, ${user.naem}`;
  //                    ^^^^
  // Property 'naem' does not exist on type 'User'. Did you mean 'name'?
}
```

Both of these bugs would be invisible to plain JavaScript until the code ran — and possibly until a specific code path was hit in production.

## Type inference: TypeScript is smarter than you might think

You do not have to annotate every variable. TypeScript watches what you assign and infers the type automatically.

```typescript
// TypeScript infers "count" is a number — no annotation needed
const count = 42;

// TypeScript infers "greeting" is a string
const greeting = "Hello";

// TypeScript infers the return type from the function body
function double(n: number) {
  return n * 2; // TypeScript knows this returns number
}
```

**Type inference** means TypeScript does most of the work. You only add explicit annotations when TypeScript cannot figure it out on its own, or when you want to document intent clearly for other developers.

## The compile-time / runtime distinction

A **runtime error** crashes your program while it is running. A **compile-time error** is caught before the code runs. TypeScript converts many runtime errors into compile-time errors.

| Error type   | When caught                      | Impact                                |
| ------------ | -------------------------------- | ------------------------------------- |
| Runtime      | When users trigger the code path | Users see crashes or wrong data       |
| Compile-time | When you type the code           | You see it in your editor immediately |

TypeScript cannot catch every bug — logic errors, network failures, and unexpected API responses still happen at runtime. But it eliminates an entire class of errors that arise from mismatched expectations about what shape a value has.

## What you learned

- JavaScript's dynamic nature lets type mismatches — the wrong kind of value passed to a function — slip through silently, often creating runtime bugs that reach users.
- TypeScript is a **superset of JavaScript** that adds optional type annotations and then **removes them at build time**, leaving plain JavaScript for the browser.
- The TypeScript compiler catches **compile-time errors** — wrong argument types, misspelled properties — before code ever runs, converting runtime bugs into editor feedback.
- **Type inference** means TypeScript deduces most types automatically; you add explicit annotations where TypeScript needs help or where you want to communicate intent.
