## Why this matters

A page passes a desktop demo but consumes a learner’s limited data allowance before showing its main content. A useful performance budget counts the assets actually needed for the task and tests the resulting experience.

## Start with something familiar

A traveler packs essentials before optional equipment. Initial page resources should similarly prioritize the user’s immediate task instead of shipping every possible feature at startup.

## The mental model

> Budget transferred bytes and main-thread work separately. Optimize the critical experience using measured resource sizes and representative constraints; compression alone does not remove parsing, decoding or execution costs.

## The mechanism

The synthetic initial-load inventory is JavaScript240KB, CSS40KB, fonts120KB and a hero image600KB, all decimal transferred kilobytes. Total is 1000KB. A proposed change defers140KB of optional JavaScript, uses40KB of fonts and serves a120KB appropriately sized image. The revised initial transfer is 100+40+40+120=300KB, saving700KB. These are supplied fixture values, not typical guaranteed savings.

For images, supply appropriate intrinsic dimensions and responsive source candidates so the browser can choose an asset suited to rendered size and pixel density. A modern format may reduce transfer, but verify visual quality and decode cost. Do not lazy-load the primary above-the-fold image merely because lazy loading sounds efficient; delaying discovery can harm the main visual result.

A bundle analyzer or browser network panel should identify what ships initially, why a dependency is included and which route needs it. Code splitting is useful when it delays genuinely optional work; a chain of tiny serial requests can also add latency. Measure cold and warm loads and preserve the caching assumptions.

At an idealized1 megabit/second,300KB requires at least2.4 seconds of payload transfer alone:300000*8/1000000. Actual task readiness also includes latency, connection setup, contention, decompression, parsing, execution and rendering. Do not present that lower bound as a page-load prediction.

Write an acceptance budget for a specific task, then test on a representative constrained device and network. Keep offline/retry and readable-content behavior visible. A tiny bundle that omits required functionality is not success; the budget should protect the user outcome, not optimize a number in isolation.
