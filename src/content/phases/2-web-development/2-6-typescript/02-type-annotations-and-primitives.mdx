## Why this matters

Type annotations are the vocabulary you use to tell TypeScript what shape your data has. Without them you are writing JavaScript with a TypeScript extension — you get no safety. With them, your editor becomes a co-pilot: it autocompletes property names, flags wrong argument types as you type, and documents intent for every developer who reads your code later.

Learning to annotate well is a skill that pays compounding dividends. Every annotation you add is a constraint that future-you, and teammates, cannot accidentally violate. It is also one of the fastest ways to explore an unfamiliar codebase — the type annotations tell you what each function expects and returns without reading the implementation.

## TypeScript's primitive types

JavaScript has seven primitive value types. TypeScript names them with lowercase keywords:

| TypeScript type | JavaScript values it covers        |
| --------------- | ---------------------------------- |
| `string`        | `"hello"`, `''`, template literals |
| `number`        | `42`, `3.14`, `NaN`, `Infinity`    |
| `boolean`       | `true`, `false`                    |
| `null`          | `null`                             |
| `undefined`     | `undefined`                        |
| `bigint`        | `9007199254740993n`                |
| `symbol`        | `Symbol("id")`                     |

Two additional types are specific to TypeScript's type system:

- `any` — opts out of type checking entirely (avoid it)
- `unknown` — a value whose type is not yet known (safe to use, must narrow before using)

Think of a type annotation as a **label you stick on a box** before you ship it. The label tells anyone who receives the box what it contains and how to handle it.

> _A type annotation is a contract between the code that creates a value and the code that uses it._

## Variable annotations

Add a type annotation after the variable name with a colon:

```typescript
// Annotating a variable explicitly
const userName: string = "Alice";
const age: number = 28;
const isActive: boolean = true;

// TypeScript infers these just as well — explicit annotation is optional here
const userName2 = "Alice"; // TypeScript infers: string
const age2 = 28; // TypeScript infers: number
```

Prefer inference for local variables where the type is obvious from the value. Use explicit annotations for variables that are declared without an immediate assignment:

```typescript
// Annotation is necessary here — no value to infer from
let currentUserId: number;

// TypeScript would widen this to "any" without the annotation
// Making it explicit protects you from accidentally assigning the wrong type later
currentUserId = 42; // fine
currentUserId = "alice"; // Error: Type 'string' is not assignable to type 'number'.
```

## Function parameter and return type annotations

This is where annotations matter most. Functions are the boundaries of your program — the places where data crosses from one context to another. Annotating the parameters and return value documents the contract of the function.

```typescript
// Parameters annotated with ":" after the name
// Return type annotated with ":" after the closing parenthesis
function formatPrice(amount: number, currency: string): string {
  return `${currency}${amount.toFixed(2)}`;
}

formatPrice(9.99, "$"); // fine: returns "$9.99"
formatPrice("9.99", "$"); // Error: 'string' not assignable to 'number'
formatPrice(9.99); // Error: Expected 2 arguments, got 1
```

### The `void` return type

When a function performs an action but does not return a meaningful value, annotate its return type as `void`:

```typescript
// This function logs a side effect — callers should not use its return value
function logAction(action: string): void {
  console.log(`[${new Date().toISOString()}] ${action}`);
  // No return statement needed; TypeScript enforces that nothing is returned
}
```

### Optional parameters

Add `?` after a parameter name to make it optional. TypeScript gives the parameter the type `string | undefined` when marked optional:

```typescript
function greet(name: string, title?: string): string {
  // title is string | undefined here — must handle both cases
  if (title) {
    return `Hello, ${title} ${name}`;
  }
  return `Hello, ${name}`;
}

greet("Alice"); // fine: "Hello, Alice"
greet("Alice", "Dr."); // fine: "Hello, Dr. Alice"
```

## Union types

A **union type** says "this value can be one of these types." Use the pipe character `|` to build one:

```typescript
// A user ID might come from a URL (string) or a database record (number)
function findUser(id: string | number): void {
  // Cannot call id.toUpperCase() here — TypeScript does not know if it is a string
  console.log(`Looking up user: ${id}`);
}

findUser(42); // fine
findUser("u-123"); // fine
findUser(true); // Error: Argument of type 'boolean' is not assignable
```

### Type narrowing

When you have a union type, TypeScript tracks which branch of an `if` statement you are in. Inside the branch, the type is narrowed to just the possible type:

```typescript
function formatId(id: string | number): string {
  if (typeof id === "string") {
    // TypeScript knows id is string here — .toUpperCase() is safe
    return id.toUpperCase();
  }
  // TypeScript knows id is number here — .toFixed() is safe
  return id.toFixed(0);
}
```

**Type narrowing** is TypeScript's ability to refine a union type based on a runtime check you write. `typeof`, `instanceof`, and equality checks all narrow types.

## Literal types

You can use a specific value as a type. This is called a **literal type**:

```typescript
// Only these three exact strings are valid
type Direction = "north" | "south" | "east" | "west";

function move(direction: Direction): void {
  console.log(`Moving ${direction}`);
}

move("north"); // fine
move("up"); // Error: Argument of type '"up"' is not assignable to type 'Direction'
```

Literal types are especially useful for function options, status values, and any situation where only a fixed set of values makes sense.

## What you learned

- TypeScript's **primitive types** — `string`, `number`, `boolean`, `null`, `undefined` — map directly to JavaScript's primitives; annotate with `: type` after the variable or parameter name.
- **Function parameter and return type annotations** are the most important annotations you write — they document the contract of every function boundary.
- A **union type** (`string | number`) accepts multiple types; you must use **type narrowing** (`typeof`, `instanceof`) before accessing type-specific methods.
- **Literal types** (`"pending" | "active"`) restrict a value to a fixed set of allowed strings or numbers, eliminating entire categories of invalid state.

Next, you will learn to describe the shape of objects using **interfaces** and **type aliases** — TypeScript's tools for defining custom data structures.
