## Why this matters

A team wants to measure data use and failures, but its analytics event copies a learner’s notes and URL query into a third-party system. Useful telemetry should answer a defined question with the least necessary information.

## Start with something familiar

A traffic counter can count vehicles without photographing every passenger’s notebook. Product measurement likewise needs a purpose and a bounded schema, not unrestricted capture.

## The mental model

> Define the decision the metric supports, allowlist event fields and gate optional collection appropriately. Counts and transfer buckets can reveal experience problems without copying user-authored content.

## The mechanism

The fixture measures whether a lesson download succeeds and its transferred-byte bucket. Allowed fields are event_name, outcome and byte_bucket. It excludes lesson response text, account identifiers, full URLs and arbitrary properties. This is a teaching schema, not a universal claim that every anonymous-looking event is nonidentifying.

```python
def download_event(outcome, transferred_bytes, has_consent):
    if not has_consent:
        return None
    if outcome not in ("success", "failure") or type(transferred_bytes) is not int or transferred_bytes < 0:
        raise ValueError("invalid event")
    bucket = "under_100KB" if transferred_bytes < 100000 else "100KB_or_more"
    return {"event_name": "lesson_download", "outcome": outcome, "byte_bucket": bucket}

assert download_event("success", 50000, False) is None
assert download_event("success", 50000, True) == {"event_name": "lesson_download", "outcome": "success", "byte_bucket": "under_100KB"}
print("analytics schema checks passed")
```

Actual transfer instrumentation must state what it measures: compressed network bytes, decoded resource size and cached reuse are different. Browser timing visibility can be limited by origin and server headers. Do not silently interpret unavailable timing as zero bytes.

Specify retention, destination, access and consent/withdrawal behavior. A local data-budget display can remain useful without exporting events. Sampling and aggregation reduce volume but do not automatically erase privacy risk. Test the event schema against accidental extra fields and confirm that denied collection does not load the external collector or transmit a request.

The fixture validates only a local event constructor. It does not install an analytics SDK or prove a remote provider’s handling. A real integration needs network-level consent/egress tests and an accurate disclosure of the fields and purposes.
