## Why this matters

You've learned the theory: why polling fails, how WebSockets work, when to choose SSE. Now you build something real. A live chat app is the canonical real-time project for good reason — it touches every challenge that makes real-time hard: concurrent connections, message routing, dropped connections, system events, and the gap between what the user sees and what the server knows. Solving these problems in a concrete application is what moves knowledge from "I read about this" to "I know how to do this."

This capstone is intentionally more complete than a tutorial snippet. The code you write here is architecturally similar to what powers production chat systems — the scale differs, but the structure does not. Every decision is annotated with the why, not just the what, so you can apply the same reasoning to your own projects.

A chat app with:

- A <VocabTooltip slug="connection-registry">connection registry</VocabTooltip> that cleans up closed connections without leaking memory

## The message envelope protocol

Before writing any connection code, define your message format. Every message in the system is a JSON object with a `type` field. This is the contract both sides honor.

```typescript
// Shared types (client and server both use these shapes)
type MessageType =
  | "join" // Client → Server: join a room
  | "leave" // Client → Server: leave a room
  | "chat" // Client → Server: send a message
  | "chat-received" // Server → Client: deliver a message
  | "user-joined" // Server → Client: notify room that someone arrived
  | "user-left" // Server → Client: notify room that someone left
  | "error" // Server → Client: something went wrong
  | "ping" // Client → Server: heartbeat
  | "pong"; // Server → Client: heartbeat response

interface BaseMessage {
  type: MessageType;
}

interface JoinMessage extends BaseMessage {
  type: "join";
  room: string;
  username: string;
}

interface ChatMessage extends BaseMessage {
  type: "chat";
  room: string;
  text: string;
}

interface ChatReceivedMessage extends BaseMessage {
  type: "chat-received";
  room: string;
  username: string;
  text: string;
  timestamp: number;
}

interface SystemMessage extends BaseMessage {
  type: "user-joined" | "user-left";
  room: string;
  username: string;
}

type ClientMessage = JoinMessage | ChatMessage | { type: "ping" } | { type: "leave"; room: string };
type ServerMessage =
  | ChatReceivedMessage
  | SystemMessage
  | { type: "pong" }
  | { type: "error"; reason: string };
```

Defining the protocol as types first prevents the most common bug in real-time systems: server and client silently disagreeing on field names.

## Server: connection registry

```javascript
// server.js — Node.js WebSocket server using the "ws" package
// Install: npm install ws

import { WebSocketServer, WebSocket } from "ws";
import { createServer } from "http";

// Each connected client gets a record in this map.
// Key: the WebSocket instance itself (identity by reference)
// Value: client metadata
const clients = new Map(); // Map<WebSocket, { username, room }>

// Room registry: roomName → Set<WebSocket>
// We use a Set because order doesn't matter, and membership checks are O(1)
const rooms = new Map(); // Map<string, Set<WebSocket>>

function getOrCreateRoom(name) {
  if (!rooms.has(name)) rooms.set(name, new Set());
  return rooms.get(name);
}

// Send a well-typed message to a single client
function send(ws, message) {
  // Check readyState before every send — the connection may have dropped
  // between when we queued the send and when we execute it
  if (ws.readyState === WebSocket.OPEN) {
    ws.send(JSON.stringify(message));
  }
}

// <VocabTooltip slug="broadcast">Broadcast</VocabTooltip> to everyone in a room, optionally excluding the sender
function broadcast(room, message, exclude = null) {
  const members = rooms.get(room);
  if (!members) return;

  for (const member of members) {
    if (member !== exclude) {
      send(member, message);
    }
  }
}

// Remove a client from all registries — called on disconnect
function cleanup(ws) {
  const client = clients.get(ws);
  if (!client) return; // Already cleaned up — idempotent

  const { username, room } = client;

  // Remove from room
  const members = rooms.get(room);
  if (members) {
    members.delete(ws);
    // Delete empty rooms so we don't accumulate keys indefinitely
    if (members.size === 0) rooms.delete(room);
  }

  // Remove from global client registry
  clients.delete(ws);

  // Notify remaining room members
  broadcast(room, { type: "user-left", room, username });

  console.log(`${username} disconnected from #${room}`);
}
```

## Server: message routing

```javascript
const httpServer = createServer();
const wss = new WebSocketServer({ server: httpServer });

wss.on("connection", (ws) => {
  // New connection — not yet in any room; wait for a "join" message
  console.log("New connection established");

  ws.on("message", (rawData) => {
    let message;
    try {
      message = JSON.parse(rawData.toString());
    } catch {
      // Malformed JSON — reject and continue; don't crash the server
      send(ws, { type: "error", reason: "Invalid JSON" });
      return;
    }

    switch (message.type) {
      case "join": {
        const { username, room } = message;

        // Store client metadata
        clients.set(ws, { username, room });

        // Register in the room
        const members = getOrCreateRoom(room);
        members.add(ws);

        // Notify everyone else in the room
        broadcast(room, { type: "user-joined", room, username }, ws);

        console.log(`${username} joined #${room} (${members.size} members)`);
        break;
      }

      case "chat": {
        const client = clients.get(ws);
        if (!client) {
          // Client sent a chat before joining a room — reject
          send(ws, { type: "error", reason: "Must join a room first" });
          return;
        }

        const { room, text } = message;

        // Validate: prevent empty messages from being broadcast
        if (!text?.trim()) return;

        const envelope = {
          type: "chat-received",
          room,
          username: client.username,
          text: text.trim(),
          timestamp: Date.now(),
        };

        // Broadcast to everyone in the room INCLUDING the sender
        // so the sender's message is confirmed and timestamped by the server
        broadcast(room, envelope);
        break;
      }

      case "ping":
        // Respond immediately — the client uses this to detect silent drops
        send(ws, { type: "pong" });
        break;

      case "leave": {
        cleanup(ws);
        break;
      }

      default:
        send(ws, { type: "error", reason: `Unknown message type: ${message.type}` });
    }
  });

  ws.on("close", () => {
    // Clean up regardless of whether we received a "leave" message
    // Networks drop without warning — always handle this event
    cleanup(ws);
  });

  ws.on("error", (error) => {
    console.error("WebSocket error:", error.message);
    // "close" always follows "error" — cleanup happens there
  });
});

// Graceful shutdown: close all connections before the process exits
// so clients receive the proper close frame and can reconnect cleanly
process.on("SIGTERM", () => {
  console.log("Shutting down — closing all connections");
  wss.clients.forEach((ws) => {
    ws.close(1001, "Server shutting down");
  });
  httpServer.close(() => process.exit(0));
});

httpServer.listen(8080, () => {
  console.log("WebSocket server listening on ws://localhost:8080");
});
```

## Client: full implementation

```javascript
// chat-client.js — runs in the browser

class ChatClient {
  #url;
  #username;
  #room;
  #socket = null;
  #retryCount = 0;
  #messageQueue = []; // Messages queued while disconnected
  #connected = false;
  #onMessage; // Callback for incoming messages

  constructor({ url, username, room, onMessage }) {
    this.#url = url;
    this.#username = username;
    this.#room = room;
    this.#onMessage = onMessage;
    this.#connect();
  }

  #connect() {
    this.#socket = new WebSocket(this.#url);

    this.#socket.addEventListener("open", () => {
      this.#connected = true;
      this.#retryCount = 0; // Healthy connection — reset backoff

      // Announce ourselves to the server
      this.#send({ type: "join", username: this.#username, room: this.#room });

      // Drain any messages that queued up while we were disconnected
      // Important: drain AFTER joining — the server rejects chats before join
      while (this.#messageQueue.length > 0) {
        const queued = this.#messageQueue.shift();
        this.#send(queued);
      }
    });

    this.#socket.addEventListener("message", (event) => {
      const message = JSON.parse(event.data);
      this.#onMessage(message);
    });

    this.#socket.addEventListener("close", () => {
      this.#connected = false;

      // Exponential backoff with jitter — jitter prevents thundering herd
      // when many clients reconnect simultaneously after a server restart
      const base = Math.min(1000 * 2 ** this.#retryCount, 30_000);
      const jitter = Math.random() * 1000; // Up to 1s of random delay
      const delay = base + jitter;

      this.#retryCount++;
      console.log(`Reconnecting in ${Math.round(delay)}ms…`);
      setTimeout(() => this.#connect(), delay);
    });
  }

  // Internal send — assumes the socket is open
  #send(message) {
    if (this.#socket?.readyState === WebSocket.OPEN) {
      this.#socket.send(JSON.stringify(message));
    }
  }

  // Public send — queues if disconnected
  sendMessage(text) {
    const message = { type: "chat", room: this.#room, text };

    if (!this.#connected) {
      // Queue it — it'll be sent once we reconnect and rejoin
      this.#messageQueue.push(message);
      return;
    }

    this.#send(message);
  }

  disconnect() {
    // Remove the close listener first — we don't want to auto-reconnect on intentional close
    this.#socket.removeEventListener("close", this.#connect);
    this.#socket.close(1000, "User left");
    this.#connected = false;
  }
}
```

## Client: UI wiring

```html
<!-- index.html — minimal chat UI -->
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <title>Live Chat</title>
  </head>
  <body>
    <div id="messages"></div>
    <form id="form">
      <input id="input" type="text" placeholder="Type a message…" autocomplete="off" />
      <button type="submit">Send</button>
    </form>

    <script>
      const messagesEl = document.querySelector("#messages");
      const formEl = document.querySelector("#form");
      const inputEl = document.querySelector("#input");

      function appendMessage(text, type = "chat") {
        const el = document.createElement("p");
        el.textContent = text;
        // System messages (join/leave) get different styling
        el.dataset.type = type;
        messagesEl.appendChild(el);
        // Scroll to bottom — new messages should always be visible
        messagesEl.scrollTop = messagesEl.scrollHeight;
      }

      const client = new ChatClient({
        url: "ws://localhost:8080",
        username: prompt("Enter your username:") || "Anonymous",
        room: "general",
        onMessage(message) {
          switch (message.type) {
            case "chat-received":
              // Show an optimistic message that the server confirmed
              appendMessage(`${message.username}: ${message.text}`, "chat");
              break;
            case "user-joined":
              appendMessage(`${message.username} joined the room`, "system");
              break;
            case "user-left":
              appendMessage(`${message.username} left the room`, "system");
              break;
            case "error":
              appendMessage(`Error: ${message.reason}`, "error");
              break;
          }
        },
      });

      formEl.addEventListener("submit", (event) => {
        event.preventDefault();
        const text = inputEl.value.trim();
        if (!text) return;

        // Optimistic update: show the message immediately, don't wait for the server echo
        // The server will broadcast it back to everyone including us — we de-duplicate by
        // username to avoid showing our own message twice
        // (A full implementation would use message IDs for deduplication)
        client.sendMessage(text);
        inputEl.value = "";
      });
    </script>
  </body>
</html>
```

## The full data flow

```
User types "Hello" and presses Enter
        │
        ▼
ChatClient.sendMessage("Hello")
  └─ socket.send({ type:"chat", room:"general", text:"Hello" })
        │
        ▼  (over WebSocket)
Server receives message
  └─ Validates: client is in the room
  └─ Adds timestamp and username to envelope
  └─ broadcast(room, { type:"chat-received", username:"Alice", text:"Hello", timestamp:… })
        │
        ▼  (to every client in #general)
All browsers receive "chat-received"
  └─ onMessage callback fires
  └─ appendMessage("Alice: Hello") runs
  └─ Message appears in the UI
```

## What you learned

- A production WebSocket server maintains a connection registry (client Map) and room registry (room Map) — every connection change must be reflected in both, or data integrity breaks
- A typed <VocabTooltip slug="message-envelope">message envelope</VocabTooltip> protocol — with a `type` field as a discriminant — is the foundation that makes routing, validation, and debugging tractable as a chat app grows
- Cleanup must handle both graceful disconnects ("leave" message) and ungraceful drops ("close" event) — the `cleanup` function should be idempotent so running it twice causes no harm
- Message queuing on the client preserves messages sent during brief disconnects, and exponential backoff with jitter prevents many reconnecting clients from thundering a restarting server simultaneously

You now have the full real-time toolkit: you understand the trade-offs between polling, SSE, and WebSockets, you can implement the WebSocket protocol on both sides, and you've built a complete system that handles the hard parts — reconnection, room routing, cleanup, and graceful shutdown.
