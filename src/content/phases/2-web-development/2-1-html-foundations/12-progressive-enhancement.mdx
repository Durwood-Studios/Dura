## Why this matters

A search page shows a blank shell when its framework bundle fails. A lightweight interface should make the core task available with the least necessary machinery, then add richer behavior when supported.

## Start with something familiar

A shop can serve a customer at the counter even if its self-service kiosk is unavailable. Enhancement should improve the route to the task rather than replace the only route with a fragile dependency.

## The mental model

> Start with meaningful HTML and a working baseline interaction. Add JavaScript where it improves the task, preserving validation, navigation and failure behavior when the enhancement is absent.

## The mechanism

A normal search form can submit to a real server endpoint without JavaScript. The following static page declares that contract; its /search endpoint must be implemented by the host, so opening the file alone does not create a search backend.

```html
<!doctype html>
<html lang="en">
<head><meta charset="utf-8"><title>Lesson search</title></head>
<body>
  <main>
    <h1>Find a lesson</h1>
    <form action="/search" method="get">
      <label for="query">Search terms</label>
      <input id="query" name="q" required maxlength="80">
      <button type="submit">Search</button>
    </form>
  </main>
</body>
</html>
```

The server validates q and returns an accessible results page. A JavaScript enhancement might fetch and replace a results region, but it should activate only when its prerequisites are available and provide a recoverable failure path. Client validation helps users; it does not replace server validation.

Choosing a lightweight framework, or no framework, is a trade-off among interaction complexity, initial transfer, maintenance and accessible behavior. Do not add a runtime merely to generate a static form. Conversely, a complex shared state model may justify a framework if its benefits and costs are measured. The goal is appropriate machinery, not a universal ban on libraries.

Test the baseline with JavaScript disabled, a failed script request, a slow connection, keyboard-only input and server validation errors. Enhancement should preserve the form’s action/method and meaningful labels. If a fetch fails after interception, display a clear retry or ordinary-submit path rather than stranding the user behind a spinner.

This exercise evaluates a real HTML/browser contract and a host endpoint requirement. It does not claim that the isolated file implements a complete search service. The acceptance record must distinguish what the browser provides from what the server must supply.
