## Why this matters

A user edits a record on a train, reconnects and sees the change duplicated or overwritten. Local saving, remote acknowledgement and conflict resolution are separate events; treating them as one Saved flag hides important failure states.

## Start with something familiar

A postal clerk keeps a copy of an order until delivery is confirmed. If the acknowledgement disappears, sending the same identified order again should not create a second purchase.

## The mental model

> Persist the local mutation before attempting delivery, retain its stable identity until acknowledgement, and detect conflicts against a known base version. Offline durability is not the same as remote convergence.

## The mechanism

A local record needs owner identity, schema version and durable content. An outbox stores pending mutations with a stable mutation_id, target record and base_version. Local storage failure must leave the draft visible and report that it is not safely saved. Do not queue another account’s data after sign-out or silently merge owners.

The complete Python fixture models a server-side version check and duplicate acknowledgement for one record. It is not a browser persistence implementation; use IndexedDB or a platform-appropriate durable store for the actual outbox.

```python
state = {"version": 1, "title": "Old"}
receipts = {}

def apply_mutation(mutation_id, base_version, title):
    if mutation_id in receipts:
        return receipts[mutation_id]
    if base_version != state["version"]:
        return {"status": "conflict", "version": state["version"]}
    state.update(version=state["version"] + 1, title=title)
    receipt = {"status": "applied", "version": state["version"]}
    receipts[mutation_id] = receipt
    return receipt

assert apply_mutation("m1", 1, "New")["version"] == 2
assert apply_mutation("m1", 1, "New")["version"] == 2
assert apply_mutation("m2", 1, "Other")["status"] == "conflict"
assert state == {"version": 2, "title": "New"}
print("sync contract passed")
```

In production, mutation identity must also be bound to the authenticated owner and request content; reusing an ID for a different payload should be rejected, not treated as a new request. Store state and deduplication receipt transactionally. An in-memory dictionary does not survive a restart or establish concurrent safety.

If acknowledgement is lost after apply, retry m1, not a newly generated ID. If another device changes the base version, retain both the local draft and remote version for an explicit conflict policy. Blind last-write-wins may be acceptable for some fields but can discard meaningful edits. Test app termination after local save, unavailable storage, duplicate delivery, stale base version and account switching.
