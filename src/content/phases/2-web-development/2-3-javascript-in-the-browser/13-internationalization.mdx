## Why this matters

A price displays correctly in one locale and is misread in another because separators differ. Translating labels does not solve number, date, plural or layout behavior. The stored meaning must remain independent of the formatted text.

## Start with something familiar

The same distance can be written with different units and notation on different road signs. You do not recover the original measurement reliably by stripping unfamiliar punctuation from the sign.

## The mental model

> Store a value with its meaning, then format it for the selected locale and context. Do not treat human-readable output as a universal machine interchange format.

## The mechanism

Internationalization prepares software for multiple locales; localization supplies language and regional choices. A locale identifier such as en-US or de-DE influences formatting, but it does not identify a person's nationality or authorize guessing their currency. Currency, unit and time-zone choices need their own context.

The following complete JavaScript example runs in a modern browser console or Node with the relevant Intl locale data:

```javascript
const amount = 1234.5;
const us = new Intl.NumberFormat("en-US", { style: "currency", currency: "EUR" });
const de = new Intl.NumberFormat("de-DE", { style: "currency", currency: "EUR" });
console.log(us.format(amount));
console.log(de.format(amount));
console.assert(amount === 1234.5);
```

Both strings describe the same amount and currency. Their separators, ordering or spacing differ. Keep1234.5 and EUR as data; do not parse either display string by deleting commas. Exact formatted spacing can vary with locale data, so tests should distinguish semantic expectations from incidental Unicode spacing.

Translation messages should be complete phrases with named values rather than fragments concatenated in English word order. Plurals vary by language. Dates need explicit time-zone behavior where a calendar date could differ across zones. A short English button label may become longer after translation; test wrapping, control access and right-to-left layouts where supported.

An explicit fallback language is better than silently returning an internal message key. Retain the user's preference without assuming the browser's first locale is always what they want. Locale formatting does not itself translate lesson prose, validate a numeric input or establish accessibility; each needs its own contract.

## Practice
