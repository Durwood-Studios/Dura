## Where this lesson sits

M6 established GD&T as the model for part conformance, embedded in 2D drawings. M7 takes the next step: the annotated 3D CAD model itself becomes the authoritative product definition, and the 2D drawing — if it exists at all — is a derived view, not the source of truth.

This is **Model-Based Definition** (MBD), governed by ASME Y14.41 (current edition: Y14.41-2019). The transition is well underway in aerospace and automotive; M7 builds the literacy to participate in MBD programs.

## What 2D drawings actually do, and don't

A 2D engineering drawing is a 2D projection of a 3D part, annotated with dimensions, tolerances, GD&T feature control frames, notes, and a title block. The 3D part is what gets manufactured; the drawing is the SPECIFICATION the part must conform to.

What 2D drawings do well:

- Compact specification — a few sheets describe a complex part.
- Print-friendly — a drawing is reviewable on paper or a small screen.
- Format-stable — paper drawings from 1970 are still readable.

What 2D drawings do poorly:

- **Projection ambiguity.** A 3D shape doesn't always have an unambiguous 2D projection. Multiple views are required; complex parts need many views; some geometry is hard to communicate in 2D at all.
- **Re-creation overhead.** Every time a supplier or downstream user needs a 3D model from the drawing, they re-create it in CAD. The re-creation is error-prone; the re-created model has no guarantee of matching the original designer's intent.
- **Inspection ambiguity.** Inspectors measuring against a 2D drawing must mentally reconstruct the 3D part. CMM programming starts from a model the inspector built; if that model differs from the designer's intent, inspection results are wrong.

The 2D drawing was the only practical specification format in the pre-CAD era. Once 3D CAD became universal, the drawing's role as authoritative source of truth started looking like an accident of history.

## What MBD changes

Model-Based Definition makes the annotated 3D CAD model the AUTHORITATIVE product definition. The model carries:

- The 3D geometry of the part.
- **PMI** (Product Manufacturing Information) — Y14.5 GD&T feature control frames, dimensions, tolerances, notes, datums — directly annotated on the 3D model.
- The Technical Data Package elements — material specs, finish, heat treatment, assembly references.

A 2D drawing, if one exists at all, is a DERIVED view of the model — for shop-floor printability or legacy compatibility — and explicitly NOT authoritative. The title block on a Y14.41-compliant drawing states this directly.

Consequences:

- **Single source of truth.** The model is the spec. Inspection programs the CMM against the model. Manufacturing programs CAM against the model. Suppliers manufacture from the model. No re-creation step exists.
- **Disambiguation.** Geometry that's ambiguous in 2D (compound curves, draft angles, asymmetric features) is unambiguous in 3D. The model is the only required source.
- **Programmatic consumption.** Inspection, CAM, CMM, and quality-system tools consume the model directly via STEP AP242 or similar formats — a programmatic interface, not a human-interpreted document.

## STEP AP242 — the interoperability format

The Y14.41 model is a 3D CAD model with annotated PMI. The CAD authoring tool (Siemens NX, CATIA, SOLIDWORKS, Creo, Inventor) creates it; downstream consumption requires an interoperability format because no supplier has the same CAD installation as the designer.

The dominant interoperability format for MBD is **STEP AP242** (ISO 10303-242), titled "Managed model-based 3D engineering." Earlier STEP application protocols (AP203, AP214) carried geometry but not PMI; AP242 was specifically developed to carry PMI as machine-readable data, not just as graphical annotation.

The structural difference: an AP203 file carries the 3D geometry as B-rep surfaces; an AP242 file carries the geometry AND the PMI as semantically-tagged data. A downstream CMM software reading an AP242 file can extract the feature control frames programmatically; reading an AP203 file, it can only extract the geometry and the human must re-enter the PMI.

AP242 is the format that makes MBD operational. An OEM committing to MBD typically standardizes on AP242 as the supplier-delivery format and requires conformance to a Recommended Practice (the MBE / MBD recommended practices published by AIA, NIST, and MBE Capability Index references).

## The 3D PDF and JT alternatives

Two adjacent formats appear in MBD environments:

- **3D PDF** — a PDF that embeds a 3D model viewable in Adobe Reader. Used as a shop-floor-printable derived view of the model. NOT a substitute for AP242 — the PDF is human-readable but not programmatically reliable for inspection or CAM.
- **JT** — the Jupiter Tessellation format, originally from Siemens. Used for visualization, mark-up review, and lightweight collaboration. Carries PMI similarly to AP242 but is owned by Siemens (vs AP242 as the open ISO standard); the choice between JT and AP242 in a specific program is a procurement decision.

In a well-structured MBD program, AP242 is the authoritative interchange format; JT and 3D PDF are derived views for specific use cases. Receiving JT or 3D PDF as the only supplied data is a downgrade — you've lost the programmatic-consumption affordance.

## The supplier obligation in MBD programs

When an OEM commits to MBD-first procurement, the supplier obligation shifts:

- **No 2D drawing re-creation.** The supplier consumes the model authoritatively. Producing internal 2D drawings from the model is permitted but the drawings are NOT authoritative for inspection or manufacturing — the model is.
- **CAM and CMM programmed against the model.** The supplier's manufacturing and inspection tooling must accept STEP AP242 (or the OEM's specified format) and consume the PMI programmatically.
- **Quality records reference the model.** Inspection results trace to specific PMI elements in the model, not to dimensions on a regenerated drawing.
- **Change management at the model level.** When the OEM revises the model, the supplier accepts the revised model; the OEM does not separately issue a revised 2D drawing as the change record.

Suppliers who attempt to "regenerate the 2D drawing and use that as authoritative" are operating contrary to the OEM's documented procurement requirements. The OEM's quality team will surface this during supplier audits.

## What this lesson teaches you to do

After this lesson you should be able to:

- Read a Y14.41-compliant drawing's title block and recognize the statement that the drawing is non-authoritative and the model is the source of truth.
- Identify PMI annotations on a 3D model and trace each to its Y14.5 (GD&T) equivalent.
- Recognize when a supplier-delivery format (AP242, JT, 3D PDF) is sufficient for programmatic consumption and when it's only good for visualization.
- Articulate the supplier obligation under an OEM's MBD program and identify processes (drawing re-creation, manual PMI re-entry) that would violate that obligation.
