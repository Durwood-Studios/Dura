## Why this matters

The moment your system involves more than two things that interact, you have a graph. Package managers compute dependency graphs to determine install order. Navigation apps find shortest paths in weighted road graphs. Social networks expose friend-of-friend queries that are graph reachability problems. Compilers detect circular imports by checking for cycles. Kubernetes schedules containers by computing topological orderings. Every one of these problems has a known, efficient solution — but only if you recognize the structure as a graph and reach for the right algorithm.

Graph theory is also where the previous lessons in this module converge. Sets of <VocabTooltip slug="vertex">vertices</VocabTooltip> and <VocabTooltip slug="edge">edges</VocabTooltip> are just sets. Relations between nodes are the same relations you studied in lesson 3. Counting paths and cycles applies the combinatorial reasoning from lesson 4. Proving algorithm correctness uses the inductive arguments from lesson 2. This lesson is the payoff.

## Cities and roads

Before naming anything, picture a map. Cities are dots. Roads between them are lines. Some roads are one-way (like highway on-ramps). Some have distance labels. The map does not tell you which city is "first" — the structure is entirely in the connections.

That is a <VocabTooltip slug="graph">graph</VocabTooltip>: a set of <VocabTooltip slug="vertex">vertices</VocabTooltip> (the dots) connected by <VocabTooltip slug="edge">edges</VocabTooltip> (the lines). Nothing more. The power comes from the algorithms you can run on that structure.

> **A graph is just a set of things (vertices) and a set of relationships between pairs of those things (edges). Every network is a graph.**

## Graph varieties

### Directed vs. undirected

In an <VocabTooltip slug="undirected-graph">undirected graph</VocabTooltip>, an edge between A and B means the connection goes both ways — like a two-way road or a "friends" relationship. In a <VocabTooltip slug="directed-graph">directed graph</VocabTooltip> (digraph), each edge has an arrow: it goes from A to B but not necessarily back. Twitter follows, HTTP redirects, and task dependencies are all directed.

### Weighted graphs

A <VocabTooltip slug="weighted-graph">weighted graph</VocabTooltip> attaches a number to each edge — distance, cost, latency, or capacity. Dijkstra's algorithm and minimum spanning trees operate on weighted graphs.

### Degree

The <VocabTooltip slug="degree">degree</VocabTooltip> of a vertex is the count of edges incident to it. In a directed graph, distinguish in-degree (edges arriving) from out-degree (edges leaving). A vertex with degree 0 is **isolated**. The sum of all degrees in an undirected graph always equals twice the number of edges — every edge contributes to two vertices.

## Representing graphs in code

Two standard representations trade space for lookup speed differently.

### Adjacency list

An <VocabTooltip slug="adjacency-list">adjacency list</VocabTooltip> stores, for each vertex, the list of its neighbors. Space: O(V + E). Neighbor lookup: O(degree). Best for sparse graphs (few edges relative to V²).

```javascript
// Adjacency list — the standard representation for most algorithm problems
// Each key is a vertex; each value is the array of neighbors
const graph = {
  A: ["B", "C"],
  B: ["A", "D", "E"],
  C: ["A", "F"],
  D: ["B"],
  E: ["B", "F"],
  F: ["C", "E"],
};

// Add an undirected edge: update both directions
function addEdge(g, u, v) {
  if (!g[u]) g[u] = [];
  if (!g[v]) g[v] = [];
  g[u].push(v);
  g[v].push(u); // omit this line for a directed graph
}

// Degree of a vertex: just the length of its neighbor list
const degree = (g, v) => (g[v] ? g[v].length : 0);

console.log("Degree of B:", degree(graph, "B")); // 3
console.log("Neighbors of C:", graph["C"]); // ["A", "F"]
```

### Adjacency matrix

An <VocabTooltip slug="adjacency-matrix">adjacency matrix</VocabTooltip> is a V×V grid where `matrix[i][j] = 1` (or the edge weight) if there is an edge from i to j, and 0 otherwise. Space: O(V²). Edge existence check: O(1). Best for dense graphs or when frequent "does edge (u,v) exist?" queries are needed.

```javascript
// Adjacency matrix for a 4-vertex graph (vertices 0, 1, 2, 3)
// 0-indexed; matrix[i][j] = weight, or 0 for no edge
const V = 4;
const matrix = Array.from({ length: V }, () => Array(V).fill(0));

function addEdgeMatrix(mat, u, v, weight = 1) {
  mat[u][v] = weight;
  mat[v][u] = weight; // omit for directed graphs
}

addEdgeMatrix(matrix, 0, 1);
addEdgeMatrix(matrix, 0, 2);
addEdgeMatrix(matrix, 1, 3);
addEdgeMatrix(matrix, 2, 3);

// Edge existence is an O(1) array lookup — the main advantage over adjacency list
console.log("Edge (0,1) exists:", matrix[0][1] === 1); // true
console.log("Edge (1,2) exists:", matrix[1][2] === 1); // false

// Print the matrix for inspection
console.log("\nAdjacency matrix:");
matrix.forEach((row, i) => console.log(`${i}: [${row.join(", ")}]`));
```

## Paths, cycles, and connectivity

A <VocabTooltip slug="path">path</VocabTooltip> is a sequence of vertices where each consecutive pair is connected by an edge and no vertex repeats. A <VocabTooltip slug="cycle">cycle</VocabTooltip> is a path that starts and ends at the same vertex.

A <VocabTooltip slug="connected-graph">connected graph</VocabTooltip> has a path between every pair of vertices — you can reach any vertex from any other. An undirected graph with V vertices and no cycles that is connected is called a <VocabTooltip slug="tree">tree</VocabTooltip>; it has exactly V−1 edges.

## Graph traversal: BFS and DFS

Two algorithms explore every reachable vertex from a start node. They differ only in which vertex they process next.

### Breadth-first search (BFS)

BFS uses a **queue** (FIFO). It explores all neighbors of the current vertex before going deeper — level by level. This guarantees shortest paths (in terms of hop count) in unweighted graphs.

```javascript
function bfs(graph, start) {
  const visited = new Set();
  const queue = [start];
  const order = [];

  visited.add(start);

  while (queue.length > 0) {
    // Dequeue from the front — FIFO is what makes this BFS, not DFS
    const vertex = queue.shift();
    order.push(vertex);

    for (const neighbor of graph[vertex] ?? []) {
      if (!visited.has(neighbor)) {
        visited.add(neighbor); // Mark before enqueuing to prevent duplicates
        queue.push(neighbor);
      }
    }
  }

  return order;
}

// BFS visits vertices layer by layer: A, then B and C, then D E F
console.log("BFS from A:", bfs(graph, "A"));
// ["A", "B", "C", "D", "E", "F"]
```

### Depth-first search (DFS)

DFS uses a **stack** (LIFO) — or equivalently, recursion. It goes as deep as possible along one branch before backtracking. DFS is used for cycle detection, topological sorting, and finding connected components.

```javascript
function dfs(graph, start) {
  const visited = new Set();
  const order = [];

  function explore(vertex) {
    visited.add(vertex);
    order.push(vertex);

    for (const neighbor of graph[vertex] ?? []) {
      if (!visited.has(neighbor)) {
        explore(neighbor); // Recurse deeper before checking siblings
      }
    }
  }

  explore(start);
  return order;
}

console.log("DFS from A:", dfs(graph, "A"));
// ["A", "B", "D", "E", "F", "C"] — goes deep down B→D, E→F before C
```

## Cycle detection with DFS

In a directed graph, detecting cycles is essential for topological sort (task scheduling, build systems). DFS uses three colors: **white** (unvisited), **gray** (currently on the call stack), **black** (fully processed). A back edge — an edge to a gray vertex — means a cycle exists.

```javascript
function hasCycle(directedGraph) {
  const WHITE = 0,
    GRAY = 1,
    BLACK = 2;
  const color = {};

  // Initialize all vertices as unvisited
  for (const v of Object.keys(directedGraph)) color[v] = WHITE;

  function dfsVisit(v) {
    color[v] = GRAY; // Mark as in-progress — on the current DFS path

    for (const neighbor of directedGraph[v] ?? []) {
      if (color[neighbor] === GRAY) {
        // Back edge: neighbor is already on our current path → cycle
        return true;
      }
      if (color[neighbor] === WHITE && dfsVisit(neighbor)) {
        return true;
      }
    }

    color[v] = BLACK; // Fully explored — no cycle through this vertex
    return false;
  }

  for (const v of Object.keys(directedGraph)) {
    if (color[v] === WHITE && dfsVisit(v)) return true;
  }
  return false;
}

// Acyclic dependency graph
const acyclic = { A: ["B", "C"], B: ["D"], C: ["D"], D: [] };
console.log("Acyclic has cycle:", hasCycle(acyclic)); // false

// Circular dependency: A → B → C → A
const cyclic = { A: ["B"], B: ["C"], C: ["A"] };
console.log("Cyclic has cycle:", hasCycle(cyclic)); // true
```

## Trees and spanning trees

A <VocabTooltip slug="tree">tree</VocabTooltip> is a connected, acyclic undirected graph. Every tree on V vertices has exactly V−1 edges. This tight relationship between edges and vertices is what makes trees tractable for recursive algorithms — you always know how much structure you have.

A <VocabTooltip slug="spanning-tree">spanning tree</VocabTooltip> of a connected graph G is a subgraph that includes all V vertices but only V−1 edges — enough to keep the graph connected without any cycles. A **minimum spanning tree** (MST) is the spanning tree whose total edge weight is minimized.

MSTs solve real engineering problems: laying the minimum-cost cable to connect all offices in a building, finding the cheapest network backbone, or computing the minimum road network to connect all cities. Kruskal's algorithm builds an MST greedily by sorting edges by weight and adding each edge that does not create a cycle.

```python
# Kruskal's algorithm: minimum spanning tree via greedy edge selection
# Uses a Union-Find data structure to detect cycles in O(α(n)) per operation

class UnionFind:
    def __init__(self, vertices):
        # Each vertex is its own parent initially — no connections
        self.parent = {v: v for v in vertices}
        self.rank = {v: 0 for v in vertices}

    def find(self, x):
        # Path compression: flatten the tree during find for future speed
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])
        return self.parent[x]

    def union(self, x, y):
        px, py = self.find(x), self.find(y)
        if px == py:
            return False  # Already in the same component — adding this edge creates a cycle
        # Union by rank: attach smaller tree under larger to keep depth shallow
        if self.rank[px] < self.rank[py]:
            px, py = py, px
        self.parent[py] = px
        if self.rank[px] == self.rank[py]:
            self.rank[px] += 1
        return True

def kruskal(vertices, edges):
    """
    edges: list of (weight, u, v)
    Returns MST edges and total weight.
    """
    uf = UnionFind(vertices)
    mst = []
    total_weight = 0

    # Sort edges by weight — greedily pick the cheapest edges first
    for weight, u, v in sorted(edges):
        if uf.union(u, v):
            # This edge connects two separate components — safe to add
            mst.append((u, v, weight))
            total_weight += weight

    return mst, total_weight

# Example: 5-city network, costs in thousands of dollars
vertices = ["A", "B", "C", "D", "E"]
edges = [
    (4, "A", "B"),
    (8, "A", "C"),
    (7, "B", "C"),
    (11, "B", "D"),
    (9, "C", "D"),
    (2, "C", "E"),
    (6, "D", "E"),
    (1, "D", "B"),  # cheapest edge
]

mst, cost = kruskal(vertices, edges)
print("Minimum spanning tree edges:")
for u, v, w in mst:
    print(f"  {u} — {v}  (cost: {w})")
print(f"Total MST cost: {cost}k")
```

## What you learned

- A graph is a set of vertices connected by edges; directed graphs model one-way relationships, undirected graphs model mutual ones, and weighted graphs attach costs or capacities to edges.
- Adjacency lists (O(V + E) space) suit sparse graphs; adjacency matrices (O(V²) space) enable O(1) edge lookups for dense graphs.
- BFS uses a queue to explore level by level, guaranteeing shortest hop-count paths; DFS uses a stack or recursion to explore deep before wide, enabling cycle detection and topological sort.
- Cycle detection in directed graphs uses three-color DFS: back edges to gray vertices reveal cycles in O(V + E) time.
- A spanning tree connects all vertices with exactly V−1 edges; minimum spanning trees minimize total edge weight and solve least-cost network connection problems via Kruskal's greedy algorithm.
