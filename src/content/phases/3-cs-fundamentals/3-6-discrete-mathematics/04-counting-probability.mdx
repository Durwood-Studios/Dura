## Why this matters

When you pick a random UUID to use as a primary key, how confident can you be two records will never collide? When you write a randomized test that picks 100 inputs from a space of 10,000, how likely is it that you test the same value twice? When a cryptographic hash function is described as "2¹²⁸ security," what does that number actually mean? All of these questions reduce to counting — how many distinct outcomes exist, and what fraction of them are the one you care about.

Counting arguments also underlie algorithm complexity analysis. The reason merge sort is O(n log n) and not something else comes from counting how many comparisons the merge step makes. Understanding how to count precisely is the difference between an engineer who can reason about their system's behavior in advance and one who waits for a production incident to find out.

## Counting seats on a plane

Before using any formula, think about booking seats on a small plane. The plane has 4 seats in a row and you have 4 passengers to seat. How many arrangements exist? Passenger 1 can sit in any of 4 seats. Once seated, passenger 2 has 3 remaining seats. Then 2. Then 1. Total: 4 × 3 × 2 × 1 = 24.

Now: same plane, but only 2 of the 4 seats are being filled. How many ways? 4 choices for the first person, 3 for the second: 4 × 3 = 12.

Now: you do not care who sits where — you just want to know how many pairs of passengers can be picked for two upgrade seats. The order of selection does not matter: picking Alice then Bob is the same as picking Bob then Alice. So 12 ÷ 2 = 6 pairs.

That is the entire intuition for permutations and combinations.

> **Counting is the art of multiplying choices at each step, then dividing out arrangements that are identical for your purpose.**

## The multiplication principle

The <VocabTooltip slug="multiplication-principle">multiplication principle</VocabTooltip>: if a process has k independent steps with n₁, n₂, ..., nₖ choices respectively, the total number of outcomes is n₁ × n₂ × ... × nₖ.

```javascript
// How many 8-character passwords using lowercase letters and digits?
// Each position: 26 + 10 = 36 choices, chosen independently
const choices = 36;
const length = 8;
const total = Math.pow(choices, length);
console.log(`Total passwords: ${total.toLocaleString()}`);
// 2,821,109,907,456 — about 2.8 trillion

// How many if the first character must be a letter?
const firstChar = 26; // only letters
const remaining = 36; // letters + digits for positions 2-8
const constrainedTotal = firstChar * Math.pow(remaining, 7);
console.log(`Constrained: ${constrainedTotal.toLocaleString()}`);
```

## Permutations — order matters

A <VocabTooltip slug="permutation">permutation</VocabTooltip> P(n, k) counts ordered arrangements of k items chosen from n distinct items.

```
P(n, k) = n! / (n − k)!
```

Where <VocabTooltip slug="factorial">n!</VocabTooltip> ("n factorial") = n × (n−1) × ... × 2 × 1.

- Arranging all 5 runners in a race: P(5, 5) = 5! = 120
- Awarding gold/silver/bronze from 10 runners: P(10, 3) = 10! / 7! = 10 × 9 × 8 = 720

```javascript
function factorial(n) {
  // Iterative to avoid stack overflow on large n
  let result = 1n; // BigInt because factorials grow fast
  for (let i = 2n; i <= BigInt(n); i++) result *= i;
  return result;
}

function permutations(n, k) {
  // P(n,k) = n! / (n-k)! — choosing k from n where order matters
  return factorial(n) / factorial(n - k);
}

function combinations(n, k) {
  // C(n,k) = n! / (k! * (n-k)!) — choosing k from n, order doesn't matter
  return factorial(n) / (factorial(k) * factorial(n - k));
}

console.log("P(10, 3):", permutations(10, 3).toString()); // 720
console.log("C(10, 3):", combinations(10, 3).toString()); // 120

// Why is C(10,3) smaller than P(10,3)?
// Each combination of 3 items corresponds to 3! = 6 orderings,
// so P(10,3) = C(10,3) × 3! = 120 × 6 = 720
```

## Combinations — order does not matter

A <VocabTooltip slug="combination">combination</VocabTooltip> C(n, k) (also written `n choose k` or `(n k)`) counts unordered subsets of size k from n items.

```
C(n, k) = n! / (k! × (n − k)!)
```

- Choosing 3 toppings from 8 options: C(8, 3) = 56
- Choosing a 5-card hand from a 52-card deck: C(52, 5) = 2,598,960

The relationship: P(n, k) = C(n, k) × k! — every combination can be arranged in k! ways, so permutations overcounts combinations by exactly k!.

## Basic probability

A <VocabTooltip slug="sample-space">sample space</VocabTooltip> S is the set of all possible outcomes. An <VocabTooltip slug="event">event</VocabTooltip> E is a subset of S — a set of outcomes we care about. For a uniform probability model (each outcome equally likely):

```
P(E) = |E| / |S|
```

```javascript
// Probability of a 5-card flush (all same suit) from a 52-card deck
// |S| = C(52, 5) — all possible 5-card hands
// |E| = 4 × C(13, 5) — pick a suit (4 ways), then pick 5 from 13 cards

function bigIntCombinations(n, k) {
  let result = 1n;
  for (let i = 0n; i < BigInt(k); i++) {
    result = (result * (BigInt(n) - i)) / (i + 1n);
  }
  return result;
}

const totalHands = bigIntCombinations(52, 5);
const flushHands = 4n * bigIntCombinations(13, 5); // one per suit

// Convert to float for division — precision sufficient for display
const prob = Number(flushHands) / Number(totalHands);
console.log(`Total 5-card hands: ${totalHands}`);
console.log(`Flush hands: ${flushHands}`);
console.log(`P(flush) ≈ ${(prob * 100).toFixed(4)}%`); // ≈ 0.1965%
```

## The birthday paradox

The <VocabTooltip slug="birthday-paradox">birthday paradox</VocabTooltip>: in a room of just 23 people, the probability that at least two share a birthday exceeds 50%. This feels wrong — there are 365 days and only 23 people. The catch: you are not asking whether someone shares a birthday with a specific person; you are asking whether any two people among the 23 share a birthday. The number of pairs is C(23, 2) = 253 — each pair is an independent collision opportunity.

The calculation uses the complement:

```
P(no collision among k people) = (365/365) × (364/365) × (363/365) × ... × (365-k+1)/365
P(at least one collision) = 1 − P(no collision)
```

```javascript
// Birthday paradox: compute k where collision probability exceeds 50%
function birthdayProbability(k, days = 365) {
  // P(no collision) = product of (days - i) / days for i = 0..k-1
  let noCollision = 1;
  for (let i = 0; i < k; i++) {
    noCollision *= (days - i) / days;
  }
  return 1 - noCollision;
}

// Find the threshold
for (let k = 2; k <= 60; k++) {
  const prob = birthdayProbability(k);
  if (prob >= 0.5) {
    console.log(`With k=${k} people, P(collision) = ${(prob * 100).toFixed(1)}%`);
    break;
  }
}
// Output: With k=23 people, P(collision) = 50.7%

// Why this matters for UUIDs (128-bit space = 2^128 possible values):
// To reach 50% collision probability you need roughly sqrt(2^128) ≈ 2^64 ≈ 18 quintillion UUIDs
console.log("\nHash collision threshold for 128-bit space:");
console.log("50% collision at ~2^64 ≈", (2 ** 64).toExponential(2), "values");
```

The birthday paradox explains why hash tables need good collision handling even with large address spaces, and why cryptographic hash outputs need to be large (SHA-256 uses 256 bits so the collision threshold is 2¹²⁸ — enough for practical security).

## The pigeonhole principle

The <VocabTooltip slug="pigeonhole-principle">pigeonhole principle</VocabTooltip>: if you put n+1 or more items into n bins, at least one bin must contain 2 or more items. This is a combinatorial proof by contradiction — assuming all bins have at most 1 item leads to n as the maximum total, contradicting n+1 items.

Applications in CS:

- **Hash collision guarantee**: if a hash function maps an infinite domain into a finite codomain, collisions are not just possible — they are inevitable.
- **Compression limits**: you cannot losslessly compress all files shorter — there are more files than shorter representations.
- **Duplicate detection**: if you read 257 values each in range 0–255, at least two must be the same.

```python
# Demonstrate pigeonhole: find the guaranteed duplicate
def find_duplicate_pigeonhole(values, max_value):
    """
    If len(values) > max_value + 1, there must be a duplicate.
    This finds it in O(n) time with O(n) space.
    """
    if len(values) <= max_value + 1:
        return None  # No guarantee of duplicate

    seen = set()
    for v in values:
        if v in seen:
            return v  # Guaranteed to find one by pigeonhole
        seen.add(v)
    return None  # Unreachable if len(values) > max_value + 1

# 256 possible values (0-255), 257 inputs: must have a duplicate
import random
test = [random.randint(0, 255) for _ in range(257)]
dup = find_duplicate_pigeonhole(test, 255)
print(f"Guaranteed duplicate found: {dup}")
```

## What you learned

- The multiplication principle counts multi-step processes by multiplying independent choice counts at each step.
- Permutations P(n, k) count ordered arrangements (order matters); combinations C(n, k) count unordered subsets (order does not matter); P(n, k) = C(n, k) × k!.
- Probability for uniform sample spaces is the number of favorable outcomes divided by the total number of outcomes.
- The birthday paradox shows that collision probability grows much faster than intuition suggests — the relevant count is the number of pairs, not individuals.
- The pigeonhole principle guarantees collisions when more items exist than bins — the mathematical bedrock of why hash collisions are inevitable and compression has limits.
