## Why this matters

Every `if` statement you have ever written is a proposition — a claim that is either true or false. But once you stack several conditions together with `&&`, `||`, and `!`, it gets easy to introduce bugs that are nearly invisible without a formal framework. A security check that should require `A AND (B OR C)` silently becomes `(A AND B) OR C` after a copy-paste, and suddenly the access gate is wide open under conditions nobody intended. Propositional logic gives you a precise language for reasoning about these conditions before they reach production.

Boolean algebra also underlies every digital circuit, every database `WHERE` clause, and every compiler optimization. When a query planner rewrites `NOT (x = 5 OR x = 6)` into `x != 5 AND x != 6`, it is applying the same rules you are about to learn. Understanding those rules means you can read optimized code, spot logical mistakes in conditional expressions, and reason with confidence about correctness.

## Everything is a light switch

Before naming the concept, think of it physically. A light switch is either ON or OFF — there is no third option. A room has a main switch and a dimmer that both have to be in the right position for the light to work: both ON means the light is on. A bathroom has an OR situation: you can turn the light on from the door or from a pull cord — either one alone is enough.

That physical intuition is <VocabTooltip slug="propositional-logic">propositional logic</VocabTooltip>. A <VocabTooltip slug="proposition">proposition</VocabTooltip> is any statement that has exactly one truth value: true (`T`) or false (`F`). <VocabTooltip slug="logical-connective">Logical connectives</VocabTooltip> wire propositions together the same way wires and switches wire circuits together.

> **Propositional logic is just a formal account of how switches, conditions, and constraints combine.**

## The core connectives

### Negation — NOT (¬)

`¬P` flips the truth value of `P`. If `P` is "the file exists," then `¬P` is "the file does not exist."

| P   | ¬P  |
| --- | --- |
| T   | F   |
| F   | T   |

In code: `!p`

### Conjunction — AND (∧)

`P ∧ Q` is true only when **both** are true. Like a circuit in series — both switches must be ON.

| P   | Q   | P ∧ Q |
| --- | --- | ----- |
| T   | T   | T     |
| T   | F   | F     |
| F   | T   | F     |
| F   | F   | F     |

In code: `p && q`

### Disjunction — OR (∨)

`P ∨ Q` is true when **at least one** is true. Like a circuit in parallel — either switch alone is enough.

| P   | Q   | P ∨ Q |
| --- | --- | ----- |
| T   | T   | T     |
| T   | F   | T     |
| F   | T   | T     |
| F   | F   | F     |

In code: `p || q`

### Implication — IF…THEN (→)

`P → Q` ("if P then Q") is the conditional. It is **only false** when P is true but Q is false — the premise holds but the conclusion fails.

| P   | Q   | P → Q |
| --- | --- | ----- |
| T   | T   | T     |
| T   | F   | F     |
| F   | T   | T     |
| F   | F   | T     |

The two bottom rows trip people up. "If it is raining, I carry an umbrella" says nothing about what happens when it is not raining — so those rows are vacuously true.

### Biconditional — IF AND ONLY IF (↔)

`P ↔ Q` is true when both have the **same** truth value. In code: `p === q` for booleans.

| P   | Q   | P ↔ Q |
| --- | --- | ----- |
| T   | T   | T     |
| T   | F   | F     |
| F   | T   | F     |
| F   | F   | T     |

## Tautology, contradiction, contingency

A formula that is **always true** — regardless of input — is a <VocabTooltip slug="tautology">tautology</VocabTooltip>. Example: `P ∨ ¬P`. No matter what P is, one of them is true.

A formula that is **always false** is a <VocabTooltip slug="contradiction">contradiction</VocabTooltip>. Example: `P ∧ ¬P`.

A formula that is sometimes true and sometimes false is a **contingency** — most propositions you write are these.

## De Morgan's Laws — the most useful identities

<VocabTooltip slug="De-Morgans-law">De Morgan's laws</VocabTooltip> tell you how negation
distributes over AND and OR:

```
¬(P ∧ Q)  ≡  ¬P ∨ ¬Q
¬(P ∨ Q)  ≡  ¬P ∧ ¬Q
```

In English: "NOT (both P and Q)" means "either not-P or not-Q." Negating the whole flips AND to OR (and OR to AND) and pushes the negation inside.

In code, this rewrite is automatically applied by optimizers and linters:

```javascript
// These two conditions are logically identical — De Morgan's first law
const insecure = !(isAdmin && isVerified);
const insecureEquivalent = !isAdmin || !isVerified;

// These two are also identical — De Morgan's second law
const blocked = !(isBanned || isSuspended);
const blockedEquivalent = !isBanned && !isSuspended;

// Verify with a truth table in code:
function deMorganCheck() {
  const values = [true, false];
  for (const p of values) {
    for (const q of values) {
      // First law: !(p && q) === (!p || !q)
      const law1Left = !(p && q);
      const law1Right = !p || !q;
      // Second law: !(p || q) === (!p && !q)
      const law2Left = !(p || q);
      const law2Right = !p && !q;

      console.log(
        `P=${p} Q=${q}: Law1 ${law1Left === law1Right ? "✓" : "✗"}, Law2 ${law2Left === law2Right ? "✓" : "✗"}`
      );
    }
  }
}

deMorganCheck();
```

## Logical equivalence

Two formulas are <VocabTooltip slug="logical-equivalence">logically equivalent</VocabTooltip> (written ≡) if they have identical truth tables. De Morgan's laws are equivalences. The most useful ones to memorize:

| Name            | Original      | Equivalent |
| --------------- | ------------- | ---------- |
| Double negation | `¬¬P`         | `P`        |
| Commutative AND | `P ∧ Q`       | `Q ∧ P`    |
| Absorption      | `P ∧ (P ∨ Q)` | `P`        |
| De Morgan 1     | `¬(P ∧ Q)`    | `¬P ∨ ¬Q`  |
| De Morgan 2     | `¬(P ∨ Q)`    | `¬P ∧ ¬Q`  |
| Implication     | `P → Q`       | `¬P ∨ Q`   |

The last one is especially handy: `if (user.isAdmin || !requiresAdmin)` is the same as `if (!requiresAdmin || user.isAdmin)` is the same as `if (requiresAdmin → user.isAdmin)`.

## What you learned

- A proposition is a statement with exactly one truth value (T or F); connectives (¬, ∧, ∨, →, ↔) combine them into compound formulas.
- Truth tables enumerate every input combination and reveal whether two formulas are logically equivalent.
- De Morgan's laws let you push negation through AND (flipping to OR) and through OR (flipping to AND) — a transformation compilers and linters apply automatically.
- A formula that is always true is a tautology; one that is always false is a contradiction; most propositions are contingencies that depend on inputs.
- The implication `P → Q` is equivalent to `¬P ∨ Q`, a rewrite that makes many `if` conditions easier to simplify.

In the next lesson you will use propositional logic as a foundation for formal proof — turning these truth-table identities into structured arguments that can establish facts about infinite cases.
