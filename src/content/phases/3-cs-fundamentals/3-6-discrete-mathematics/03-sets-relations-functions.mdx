## Why this matters

Every database JOIN is a Cartesian product filtered by a relation. Every TypeScript type annotation is a function from program expressions to types. Every API endpoint that accepts or returns structured data is implicitly encoding a function between two sets. When data engineers debate whether a foreign-key relationship is many-to-one or one-to-one, they are distinguishing injective functions from general functions without using the formal vocabulary.

Knowing the formal vocabulary means you can look at a schema and immediately ask: is this relation an equivalence relation? Is this mapping a bijection? Those questions have direct consequences — equivalence relations partition data into disjoint classes (the formal reason GROUP BY works the way it does), and bijections are the reason hashing works at all. This lesson gives you the vocabulary to reason precisely about data structures, APIs, and type systems that you will encounter every day.

## Groups of things that have rules about membership

Before naming anything formally, think about a bouncer at a club. The bouncer has a list: if you are on the list, you are in the set. If you are not, you are not. The set does not care how many times you try to get in (no duplicates), and the members of the set can be anything — people, numbers, strings, other sets.

That mental model is a <VocabTooltip slug="set">set</VocabTooltip>: an unordered collection of distinct elements. In code, JavaScript's `Set` and Python's `frozenset` are direct implementations.

> **A set is a collection with two rules: no duplicates, and membership is either yes or no — nothing in between.**

## Sets and operations

Notation: `A = {1, 2, 3}`, `B = {2, 3, 4}`. The empty set is `∅` or `{}`.

**Union** `A ∪ B` — everything in either set:

```
{1, 2, 3} ∪ {2, 3, 4} = {1, 2, 3, 4}
```

**Intersection** `A ∩ B` — only what is in both:

```
{1, 2, 3} ∩ {2, 3, 4} = {2, 3}
```

**Difference** `A \ B` — in A but not in B:

```
{1, 2, 3} \ {2, 3, 4} = {1}
```

**Subset**: `A ⊆ B` means every element of A is also in B. `{1, 2} ⊆ {1, 2, 3}` is true.

**Power set** `P(A)` — the set of all subsets of A:

```
A = {1, 2}
P(A) = { {}, {1}, {2}, {1, 2} }
```

If |A| = n, then |P(A)| = 2ⁿ. This is why checking all subsets of an n-element set is O(2ⁿ) — there are exponentially many of them.

```javascript
// Set operations map directly to JavaScript Set API
const A = new Set([1, 2, 3]);
const B = new Set([2, 3, 4]);

// Union: collect everything from both
const union = new Set([...A, ...B]);
console.log("A ∪ B:", [...union]); // [1, 2, 3, 4]

// Intersection: keep only what appears in both
const intersection = new Set([...A].filter((x) => B.has(x)));
console.log("A ∩ B:", [...intersection]); // [2, 3]

// Difference: keep only what is in A but not B
const difference = new Set([...A].filter((x) => !B.has(x)));
console.log("A \\ B:", [...difference]); // [1]

// Subset check: every element of A must be in B
const isSubset = (small, large) => [...small].every((x) => large.has(x));
console.log("{1,2} ⊆ {1,2,3}:", isSubset(new Set([1, 2]), new Set([1, 2, 3]))); // true
```

## Cartesian product and relations

The **Cartesian product** `A × B` is the set of all ordered pairs (a, b) where a ∈ A and b ∈ B:

```
{1, 2} × {x, y} = { (1,x), (1,y), (2,x), (2,y) }
```

This is why a SQL `CROSS JOIN` produces |A| × |B| rows.

A <VocabTooltip slug="relation">relation</VocabTooltip> R between A and B is any subset of A × B. "User u has permission p" defines a relation between the set of users and the set of permissions. Stored in a database, it is exactly that: a table of (user_id, permission_id) pairs.

### Properties of relations on a single set

When a relation R is between a set and itself (R ⊆ A × A), three properties matter:

- **Reflexive**: every element is related to itself. (a, a) ∈ R for all a.  
  Example: "≤" on integers is reflexive (5 ≤ 5).
- **Symmetric**: if (a, b) ∈ R then (b, a) ∈ R.  
  Example: "is a sibling of" is symmetric.
- **Transitive**: if (a, b) ∈ R and (b, c) ∈ R, then (a, c) ∈ R.  
  Example: "is an ancestor of" is transitive.

An <VocabTooltip slug="equivalence-relation">equivalence relation</VocabTooltip> is reflexive + symmetric + transitive. It partitions A into disjoint **equivalence classes** — groups of elements that are all related to each other.

A <VocabTooltip slug="partial-order">partial order</VocabTooltip> is reflexive + **antisymmetric** (if (a,b) ∈ R and (b,a) ∈ R then a = b) + transitive. Package dependency graphs and task scheduling are partial orders.

```javascript
// Check whether a relation on a finite set is an equivalence relation
function checkRelation(elements, pairs) {
  const pairSet = new Set(pairs.map(([a, b]) => `${a},${b}`));
  const has = (a, b) => pairSet.has(`${a},${b}`);

  // Reflexive: every element must relate to itself
  const reflexive = elements.every((a) => has(a, a));

  // Symmetric: if (a,b) exists, (b,a) must also exist
  const symmetric = pairs.every(([a, b]) => has(b, a));

  // Transitive: if (a,b) and (b,c) exist, (a,c) must exist
  const transitive = elements.every((a) =>
    elements.every((b) => elements.every((c) => !(has(a, b) && has(b, c)) || has(a, c)))
  );

  return { reflexive, symmetric, transitive, isEquivalence: reflexive && symmetric && transitive };
}

// "Same parity" relation on {0,1,2,3}: two numbers are related iff both are even or both are odd
const elements = [0, 1, 2, 3];
const sameParity = [];
for (const a of elements) {
  for (const b of elements) {
    if (a % 2 === b % 2) sameParity.push([a, b]);
  }
}

console.log("Same parity:", checkRelation(elements, sameParity));
// Equivalence classes: {0,2} (even) and {1,3} (odd)
```

## Functions

A <VocabTooltip slug="function">function</VocabTooltip> f: A → B is a relation from A to B where every element of A appears as a first component in exactly one pair. Each input has exactly one output — no ambiguity, no missing inputs.

- **Domain**: the input set A
- **Codomain**: the allowed output set B
- **Range (image)**: the actual outputs produced — always ⊆ codomain

### Injective, surjective, bijective

An <VocabTooltip slug="injective">injective</VocabTooltip> function (one-to-one) maps distinct inputs to distinct outputs. No two elements of A share an output in B. Every username maps to at most one email.

A <VocabTooltip slug="surjective">surjective</VocabTooltip> function (onto) covers the entire codomain — every element of B is the output of at least one input. A hash function that is surjective fills all slots in a table.

A <VocabTooltip slug="bijection">bijection</VocabTooltip> is both injective and surjective: a perfect one-to-one correspondence between A and B. Bijections are reversible — the inverse function exists. Encryption (with a key) is a bijection: every ciphertext decrypts to exactly one plaintext and vice versa.

```python
# Classify a function defined as a dictionary mapping
def classify_function(mapping, domain, codomain):
    # Every domain element must have exactly one output
    for d in domain:
        if d not in mapping:
            return "Not a function: missing input " + str(d)

    outputs = list(mapping.values())

    # Injective: no two inputs share an output
    injective = len(outputs) == len(set(outputs))

    # Surjective: every codomain element is hit
    surjective = all(c in outputs for c in codomain)

    kind = []
    if injective:
        kind.append("injective")
    if surjective:
        kind.append("surjective")
    if injective and surjective:
        kind.append("→ bijection!")

    return ", ".join(kind) if kind else "neither injective nor surjective"

# f: {1,2,3} → {a,b,c,d} — injective but not surjective (d is never hit)
print(classify_function({1:"a", 2:"b", 3:"c"}, [1,2,3], ["a","b","c","d"]))

# g: {1,2,3,4} → {a,b,c} — surjective but not injective (a is hit twice)
print(classify_function({1:"a", 2:"a", 3:"b", 4:"c"}, [1,2,3,4], ["a","b","c"]))

# h: {1,2,3} → {a,b,c} — bijection
print(classify_function({1:"a", 2:"b", 3:"c"}, [1,2,3], ["a","b","c"]))
```

## What you learned

- A set is an unordered collection of distinct elements; union, intersection, difference, and subsets are the core operations with direct JavaScript/Python equivalents.
- The Cartesian product A × B is the set of all ordered pairs, and a relation is any subset of that product — the mathematical model behind database JOIN tables.
- An equivalence relation (reflexive + symmetric + transitive) partitions a set into disjoint classes; a partial order (reflexive + antisymmetric + transitive) defines a ranking or dependency structure.
- A function assigns each input exactly one output; injective means no two inputs share an output, surjective means every codomain element is used, and bijective means both — a reversible one-to-one correspondence.
- These formal objects are the foundation of type theory, relational databases, graph theory, and formal language specifications.
