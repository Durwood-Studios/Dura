## Why this matters

Algorithms deal with unbounded inputs — arrays of any length, trees of any depth, loops that run any number of times. How do you prove that your sorting algorithm produces a sorted array for every possible input, not just the 10 you tested? Testing establishes confidence up to the inputs you thought of. Proof establishes correctness for all inputs forever.

<VocabTooltip slug="mathematical-induction">Mathematical induction</VocabTooltip> is the technique
that makes this possible. It is not just abstract mathematics — every loop invariant in
correctness-critical software is an informal inductive argument. When an avionic systems engineer
writes `// invariant: arr[0..i-1] is sorted`, they are encoding the inductive hypothesis in a
comment. And <VocabTooltip slug="proof-by-contradiction">proof by contradiction</VocabTooltip> is
how computer science established that some problems are fundamentally unsolvable — not hard, but
provably impossible — reshaping what we ask software to do.

## The domino argument

Imagine an infinite row of dominoes. You want to guarantee that all of them will fall. You need exactly two things: someone pushes the **first one** over, and you can prove that **whenever one falls, the next one will too**. Those two facts together guarantee every domino falls, even though you cannot physically touch each one.

That is induction. Replace "domino n falls" with "statement P(n) is true" and you have the definition.

> **Mathematical induction is a domino proof: knock over the first one, show each one topples the next, conclude all of them fall.**

## Proof by induction — the template

To prove that P(n) holds for all integers n ≥ 0, you need three named parts:

1. **Base case**: Prove P(0) (or P(1) — whichever starting value the claim needs) directly.
2. **<VocabTooltip slug="inductive-hypothesis">Inductive hypothesis</VocabTooltip>**: Assume P(k) is true for some arbitrary k ≥ base case.
3. **<VocabTooltip slug="inductive-step">Inductive step</VocabTooltip>**: Using that assumption, prove P(k+1) is true.

### Worked example: sum of first n positive integers

**Claim:** For all n ≥ 1, `1 + 2 + 3 + ... + n = n(n+1)/2`.

**Base case (n = 1):** Left side = 1. Right side = 1×2/2 = 1. Equal. ✓

**Inductive hypothesis:** Assume `1 + 2 + ... + k = k(k+1)/2` for some k ≥ 1.

**Inductive step:** Show `1 + 2 + ... + k + (k+1) = (k+1)(k+2)/2`.

Starting from the left side:

```
1 + 2 + ... + k + (k+1)
= [k(k+1)/2] + (k+1)          // apply inductive hypothesis to the first k terms
= (k+1)[k/2 + 1]               // factor out (k+1)
= (k+1)[(k + 2)/2]             // combine inside the brackets
= (k+1)(k+2)/2                 // matches the right side ✓
```

The inductive hypothesis replaced the sum of the first k terms in one step. That replacement is always where the power of induction lives.

### Induction in code: loop invariants

Every `for` loop that builds a result incrementally has an inductive structure. The <VocabTooltip slug="invariant">invariant</VocabTooltip> is the inductive hypothesis — what is true after each iteration:

```javascript
function sumArray(arr) {
  // Claim: after i iterations, total === sum of arr[0..i-1]
  let total = 0;

  for (let i = 0; i < arr.length; i++) {
    // Inductive hypothesis: total === arr[0] + arr[1] + ... + arr[i-1]
    total += arr[i];
    // Now total === arr[0] + ... + arr[i]  (invariant holds for i+1) ✓
  }

  // After all n iterations: total === sum of arr[0..n-1]
  return total;
}
```

The base case is `i = 0` (total = 0, the empty sum). The inductive step is the loop body. The conclusion is what holds after all iterations.

## Strong induction

In standard induction, the inductive step uses P(k) to prove P(k+1). In **strong induction**, the inductive step may use P(0), P(1), ..., P(k) — all earlier cases — to prove P(k+1). This is useful when a solution depends on more than just the immediately preceding case.

```python
# Example: recursive Fibonacci with strong induction argument
# Claim: fib(n) can be computed in O(n) steps

def fib(n, memo={}):
    # Base cases — required for strong induction with a two-step recurrence
    if n <= 1:
        return n
    # Inductive hypothesis: fib(n-1) and fib(n-2) are already computed (memoized)
    # Inductive step: computing fib(n) takes O(1) additional work given those
    if n not in memo:
        memo[n] = fib(n - 1, memo) + fib(n - 2, memo)
    return memo[n]
```

## Proof by contradiction

Proof by contradiction assumes the **opposite** of what you want to prove, then shows that assumption leads to an impossible or absurd conclusion — proving the original claim must be true.

**Template:**

1. Assume the negation of the claim (the "suppose not" step).
2. Follow logical consequences until you reach a contradiction.
3. Conclude the original claim is true.

### Classic example: √2 is irrational

**Claim:** √2 cannot be expressed as a ratio p/q of integers with no common factor.

**Proof by contradiction:**

Suppose √2 = p/q where p and q share no common factor (the fraction is fully reduced).

```
√2 = p/q
2 = p²/q²              // square both sides
p² = 2q²               // p² is even
→ p must be even        // if p² is even, p is even (proven separately)
→ p = 2m for some integer m
(2m)² = 2q²
4m² = 2q²
q² = 2m²               // q² is even
→ q must be even        // by the same argument
```

But now both p and q are even — they share the factor 2 — contradicting the assumption that p/q was fully reduced. The assumption leads to a contradiction, so √2 cannot be rational. ✓

### Contradiction in CS: the Halting Problem

The most important proof-by-contradiction in computer science proves that no program can decide whether an arbitrary program halts or runs forever. The argument:

1. Suppose a halting-decider H(program, input) exists and always returns true/false correctly.
2. Build a program D that calls H on itself and does the opposite of what H predicts.
3. Ask: what does H(D, D) return?
   - If H says D halts → D loops forever → H was wrong.
   - If H says D loops → D halts → H was wrong.
4. H is wrong in either case — contradiction. No such H can exist. ✓

This proof structure — build a self-referential adversary — appears throughout complexity theory.

## The contrapositive

A close relative of contradiction is the **contrapositive**. To prove `P → Q`, you can equivalently prove `¬Q → ¬P` — both are logically identical (from lesson 1). Contrapositive proofs often feel more natural than direct proofs:

```
Direct:      "If n² is odd, then n is odd."
Contrapositive: "If n is even, then n² is even."

Proof of contrapositive:
  n even → n = 2k
  n² = (2k)² = 4k² = 2(2k²) → n² is even. ✓

Since the contrapositive is proven, the original statement is proven.
```

## What you learned

- A proof by induction has three mandatory parts: a named base case, an inductive hypothesis, and an inductive step that applies the hypothesis to reach the next case.
- Strong induction allows the inductive step to use any earlier proven case, not just the immediately preceding one — required when a recurrence depends on two or more earlier values.
- Proof by contradiction assumes the negation of the claim and derives a logical impossibility; the impossibility forces the original claim to be true.
- The contrapositive (`¬Q → ¬P`) is logically identical to the implication (`P → Q`) and is often the easier direction to prove.
- Loop invariants are informal inductive arguments embedded in code — annotating them makes correctness reasoning explicit and auditable.

Next, you will see how induction applies to the structure of sets and relations — the mathematical foundation of database schemas, type systems, and graph algorithms.
