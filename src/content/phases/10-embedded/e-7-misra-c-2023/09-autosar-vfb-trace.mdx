## Why this matters

A software component diagram shows a clean data flow, but an observed runnable finishes after its deadline. Logical connectivity and runtime timing are different views; neither can substitute for the other.

## Start with something familiar

A subway map shows which stations connect without showing how long today’s trains actually took. A trace adds observed times, but it only covers the recorded journey.

## The mental model

> AUTOSAR’s logical interfaces describe component interaction independently of deployment. Runtime trace evidence ties actual execution events to a configuration and workload, not to a universal timing guarantee.

## The mechanism

AUTOSAR Classic distinguishes application software, a runtime environment called RTE, and basic software called BSW. Its Virtual Functional Bus, VFB, is an abstraction for component interactions independent of a particular ECU deployment. An ECU is an electronic control unit. Mapping those components to actual execution involves configuration and integration; drawing the logical bus does not make every timing assumption true.

TASKING’s documented timing bundle supports trace/profiling workflows, including VFB-related tracing and interchange with timing analysis tools. “TASKING VFB” in a skill list should be read as this trace workflow, not a standalone product named VFB. The exact instrument, exporter, trace format and supported tool versions must be checked for a real project.

Use this synthetic trace, with a common microsecond clock:

```text
jobA release=0 start=20 finish=90 deadline=100
jobB release=100 start=125 finish=215 deadline=200
```

Response time is finish minus release:90us forA and115us forB. A meets its supplied absolute deadline;B misses by15us. Waiting time before execution is20us and25us respectively. Execution elapsed time here is70us and90us, but a trace that includes preemption would need events sufficient to distinguish running from waiting intervals.

Preserve the application/RTE/configuration revision, event definitions, clock units, dropped-event indication and workload. A missing start event makes the local calculation incomplete; do not invent it from an average. A measured maximum over two jobs is not a proven worst-case execution or response-time bound.

A useful review connects the violated timing assumption to the appropriate owner and model. Additional workload coverage, interference analysis or configuration changes may be needed. A trace export does not itself establish AUTOSAR compliance, tool qualification or vehicle safety.
