## The capstone

You will build a real-time sensor pipeline on STM32F4 Discovery (or equivalent Cortex-M4 board) that:

1. Samples an analog input via ADC1, channel 0, at 1 kHz.
2. Uses DMA to copy samples into a double-buffered SRAM region.
3. An RTOS task (FreeRTOS or RTIC) processes each buffer: computes mean, min, max.
4. Telemetry is sent via UART at 115200 baud as JSON lines: `{"ts":12345,"mean":2048,"min":2032,"max":2061}`.
5. The application is MISRA-C:2023 conformant OR written in Rust — your choice.

The complete project source, a recorded video demonstrating it working, and the hash-anchored /verify certificate are the portfolio artifacts.

## The architecture

```
ADC1 ──────────► DMA2 Stream 0 ──────► [buffer A] [buffer B]
                                              │         │
                                              │ TC/HT interrupt
                                              ▼         ▼
                                      ┌──────────────────────┐
                                      │  process_task        │ (RTOS, priority 3)
                                      │  - dequeue buffer    │
                                      │  - compute stats     │
                                      │  - post to telemetry │
                                      └──────────────────────┘
                                                  │
                                                  ▼ queue
                                      ┌──────────────────────┐
                                      │  telemetry_task      │ (RTOS, priority 2)
                                      │  - format JSON       │
                                      │  - send via DMA UART │
                                      └──────────────────────┘
```

Key design choices:

- **Double buffer via half-transfer interrupt** (E3). DMA fills buffer B while the task processes buffer A; on the next half-transfer, the roles flip. Zero data loss at the sample rate.
- **ISR posts to queue; task processes** (E4). The DMA HT/TC ISR enqueues a "buffer ready" message; the process task wakes when the queue has data. ISR work is minimal.
- **Telemetry runs at lower priority than processing**. JSON formatting + UART transmission takes longer than processing; lower priority prevents it from interfering with sample handling.
- **No dynamic allocation** (E7). Buffers, queues, and tasks are statically allocated. Stack sizes are documented. No malloc anywhere.

## Latency budget

The capstone requires a documented end-to-end latency budget:

| Stage                          | Budget                    | Worst case (measured)    |
| ------------------------------ | ------------------------- | ------------------------ |
| ADC conversion                 | 1.0 ms (1 sample @ 1 kHz) | varies                   |
| DMA half-transfer (50 samples) | 50.0 ms                   | 50.0 ms                  |
| ISR latency                    | < 100 µs                  | measure with GPIO toggle |
| Queue post + task wake         | < 1 ms                    | measure                  |
| Statistics compute             | < 5 ms                    | measure                  |
| Telemetry queue post           | < 100 µs                  | measure                  |
| JSON format                    | < 2 ms                    | measure                  |
| UART DMA transmit start        | < 100 µs                  | measure                  |
| **Total end-to-end**           | **~58 ms**                | **measure**              |

A target of `acquisition_complete → telemetry_transmitted < 100 ms` is appropriate for a 1 kHz sensor. The actual measured value goes in the documentation.

## The implementation outline (C, MISRA-conformant)

```c
// main.c — outline
#include "FreeRTOS.h"
#include "task.h"
#include "queue.h"
#include "stm32f4xx_setup.h"

#define BUFFER_SAMPLES  100U
#define HALF_SAMPLES    50U

static uint16_t adc_buffer[BUFFER_SAMPLES];
static QueueHandle_t buffer_queue;
static QueueHandle_t telemetry_queue;

typedef struct {
    uint16_t *start;
    uint16_t  count;
} buffer_msg_t;

typedef struct {
    uint32_t timestamp_ms;
    uint16_t mean;
    uint16_t min;
    uint16_t max;
} telemetry_msg_t;

/* ISR: DMA half-transfer or transfer-complete. Selects which half is
 * ready and enqueues a buffer-ready message. */
void DMA2_Stream0_IRQHandler(void) {
    BaseType_t woken = pdFALSE;
    buffer_msg_t msg;

    if ((DMA2_LISR & DMA_LISR_HTIF0) != 0U) {
        DMA2_LIFCR = DMA_LIFCR_CHTIF0;
        msg.start = &adc_buffer[0];
        msg.count = HALF_SAMPLES;
        (void)xQueueSendFromISR(buffer_queue, &msg, &woken);
    }
    if ((DMA2_LISR & DMA_LISR_TCIF0) != 0U) {
        DMA2_LIFCR = DMA_LIFCR_CTCIF0;
        msg.start = &adc_buffer[HALF_SAMPLES];
        msg.count = HALF_SAMPLES;
        (void)xQueueSendFromISR(buffer_queue, &msg, &woken);
    }
    portYIELD_FROM_ISR(woken);
}

/* Process task: receive buffer, compute mean/min/max, post telemetry */
static void process_task(void *params) {
    (void)params;
    buffer_msg_t buf_msg;
    telemetry_msg_t tlm_msg;

    for (;;) {
        if (xQueueReceive(buffer_queue, &buf_msg, portMAX_DELAY) == pdPASS) {
            uint32_t sum = 0U;
            uint16_t min_val = UINT16_MAX;
            uint16_t max_val = 0U;
            for (uint16_t i = 0U; i < buf_msg.count; i++) {
                uint16_t v = buf_msg.start[i];
                sum += v;
                if (v < min_val) { min_val = v; }
                if (v > max_val) { max_val = v; }
            }
            tlm_msg.timestamp_ms = xTaskGetTickCount();
            tlm_msg.mean = (uint16_t)(sum / buf_msg.count);
            tlm_msg.min  = min_val;
            tlm_msg.max  = max_val;
            (void)xQueueSend(telemetry_queue, &tlm_msg, 0U);
        }
    }
}

/* Telemetry task: format JSON, send via UART DMA */
static void telemetry_task(void *params) {
    (void)params;
    telemetry_msg_t tlm_msg;
    static char json_buf[96];

    for (;;) {
        if (xQueueReceive(telemetry_queue, &tlm_msg, portMAX_DELAY) == pdPASS) {
            int n = snprintf(json_buf, sizeof(json_buf),
                "{\"ts\":%lu,\"mean\":%u,\"min\":%u,\"max\":%u}\n",
                (unsigned long)tlm_msg.timestamp_ms,
                tlm_msg.mean, tlm_msg.min, tlm_msg.max);
            if ((n > 0) && ((size_t)n < sizeof(json_buf))) {
                uart_dma_send((const uint8_t *)json_buf, (uint16_t)n);
            }
        }
    }
}

int main(void) {
    system_clock_init();
    gpio_init();
    uart_init(115200U);
    adc_dma_init(adc_buffer, BUFFER_SAMPLES);

    buffer_queue    = xQueueCreate(4U,  sizeof(buffer_msg_t));
    telemetry_queue = xQueueCreate(8U,  sizeof(telemetry_msg_t));

    (void)xTaskCreate(process_task,   "proc", 384U, NULL, 3U, NULL);
    (void)xTaskCreate(telemetry_task, "tlm",  512U, NULL, 2U, NULL);

    enable_dma2_stream0_irq();
    adc_start();

    vTaskStartScheduler();

    for (;;) { }  /* unreachable */
}
```

This is the skeleton — peripheral init details (system_clock_init, gpio_init, uart_init, adc_dma_init) come from E2/E3/E5 patterns. Everything is statically allocated, ISRs are short, and the task structure matches the architecture diagram.

## What's next — beyond Phase E

You've completed Phase E. You can:

- Build firmware from scratch with a known-good toolchain, linker script, and startup code.
- Write bare-metal C against any Cortex-M chip given its reference manual.
- Use interrupts and DMA correctly, with the deferred-work pattern.
- Structure an application with an RTOS and avoid priority inversion.
- Write drivers for UART, SPI, I2C, ADC with the right traffic-shape decomposition.
- Port a driver to Rust and read embedded-hal + RTIC code.
- Author MISRA-C:2023 conformant code or argue principled deviations.
- Ship a hash-anchored portfolio artifact.

Phase E is the foundation. Beyond it:

- **Robotics SW**: pair Phase E with Phase R (ROS 2 + safety standards).
- **Automotive**: add ISO 26262 / AUTOSAR study; consider Apex.Grace (Rust safety-certified).
- **Medical devices**: pair Phase E with the forthcoming Phase B (IEC 62304, FDA).
- **Hardware verification**: cross over into Phase H (SystemVerilog UVM).

The skills from Phase E transfer across all of these. Standards literacy compounds.
