## Why this matters

FreeRTOS concurrency requires: a task function, a stack allocation, a priority, and a handle. Adding five concurrent peripherals means five task stacks (each 512–2048 bytes), five priority decisions, and five inter-task communication channels.

Embassy concurrency requires: five `async fn`s and one `spawn` call per task. The executor schedules them cooperatively. Stack usage is typically much lower than FreeRTOS because futures only consume stack while actively running (not while awaiting). No RTOS kernel overhead.

The threshold concept: **async/await on embedded is not just syntax — it's a different execution model where the compiler transforms your code into a state machine that yields at every `await` point, and the executor runs whichever future has work to do.**

## How async works on embedded

An `async fn` in Rust is syntactic sugar for a state machine. When you write:

```rust
async fn blink(led: &mut Output<'_>) {
    loop {
        led.set_high();
        Timer::after_millis(500).await;
        led.set_low();
        Timer::after_millis(500).await;
    }
}
```

The compiler generates a struct that represents the state of `blink` at each `await` point. At `Timer::after_millis(500).await`, the future returns `Poll::Pending` to the executor. The executor records a <VocabTooltip slug="waker">waker</VocabTooltip> (a callback that says "wake me when the timer fires") and runs another task. When the timer ISR fires, it calls the waker, which tells the executor to poll the blink future again. No stack space is consumed while waiting — only the future's state struct, which lives on the heap or as a static.

This is <VocabTooltip slug="cooperative-concurrency">cooperative concurrency</VocabTooltip>: tasks voluntarily yield at `await` points, not preempted by a scheduler tick. The implication: a task that never awaits blocks the executor forever. In FreeRTOS, a tight loop in a task still gets preempted; in Embassy, it doesn't.

## Multi-task blink example

```rust
#![no_std]
#![no_main]

use embassy_executor::Spawner;
use embassy_stm32::gpio::{Level, Output, Speed};
use embassy_time::Timer;
use defmt_rtt as _;
use panic_probe as _;

#[embassy_executor::main]
async fn main(spawner: Spawner) {
    let p = embassy_stm32::init(Default::default());

    // Spawn independent concurrent tasks from main
    spawner.spawn(blink_fast(p.PD12)).unwrap();
    spawner.spawn(blink_slow(p.PD13)).unwrap();
    spawner.spawn(uart_logger()).unwrap();

    // main itself is a task — can do work here too
    loop {
        Timer::after_secs(1).await;
        defmt::info!("heartbeat");
    }
}

#[embassy_executor::task]
async fn blink_fast(pin: embassy_stm32::peripherals::PD12) {
    let mut led = Output::new(pin, Level::Low, Speed::Low);
    loop {
        led.set_high();
        Timer::after_millis(100).await;
        led.set_low();
        Timer::after_millis(100).await;
    }
}

#[embassy_executor::task]
async fn blink_slow(pin: embassy_stm32::peripherals::PD13) {
    let mut led = Output::new(pin, Level::Low, Speed::Low);
    loop {
        led.set_high();
        Timer::after_millis(500).await;
        led.set_low();
        Timer::after_millis(500).await;
    }
}

#[embassy_executor::task]
async fn uart_logger() {
    // Placeholder — would use embassy_stm32::usart::UartTx
    loop {
        Timer::after_secs(5).await;
        defmt::info!("logger tick");
    }
}
```

Three concurrent tasks, zero RTOS overhead, zero dynamic allocation at runtime (the futures are statically allocated by the `#[embassy_executor::task]` macro).

## Async UART receive with timeout

```rust
use embassy_stm32::usart::{Config, Uart};
use embassy_time::{Duration, with_timeout};

#[embassy_executor::task]
async fn uart_reader(mut rx: embassy_stm32::usart::UartRx<'static, embassy_stm32::peripherals::USART2, embassy_stm32::mode::Async>) {
    let mut buf = [0u8; 64];
    loop {
        // Receive with a 1-second timeout — doesn't block other tasks while waiting
        match with_timeout(Duration::from_secs(1), rx.read(&mut buf)).await {
            Ok(Ok(n)) => {
                defmt::info!("received {} bytes", n);
            }
            Ok(Err(e)) => {
                defmt::error!("UART error: {:?}", e);
            }
            Err(_) => {
                defmt::warn!("UART receive timeout");
            }
        }
    }
}
```

`with_timeout` wraps any future with a deadline. If the inner future doesn't complete within the duration, it returns `Err(TimeoutError)`. The calling task yields to the executor while waiting — other tasks run normally.

## Embassy channels: async queues

Embassy's `channel` is the async equivalent of a FreeRTOS queue:

```rust
use embassy_sync::channel::{Channel, Receiver, Sender};
use embassy_sync::blocking_mutex::raw::NoopRawMutex;

// Static channel with capacity 8 — declared at module level
static SENSOR_CHANNEL: Channel<NoopRawMutex, u16, 8> = Channel::new();

#[embassy_executor::task]
async fn sensor_producer() {
    let sender: Sender<NoopRawMutex, u16, 8> = SENSOR_CHANNEL.sender();
    loop {
        let reading = adc_read().await;
        sender.send(reading).await;   // Async: yields if channel is full
        Timer::after_millis(10).await;
    }
}

#[embassy_executor::task]
async fn sensor_consumer() {
    let receiver: Receiver<NoopRawMutex, u16, 8> = SENSOR_CHANNEL.receiver();
    loop {
        let reading = receiver.receive().await;  // Async: yields until data available
        process(reading);
    }
}
```

`NoopRawMutex` is correct when tasks run on a single executor (no actual locking needed). For multi-core or interrupt-safe use, replace with `CriticalSectionRawMutex`.

## Embassy vs RTIC vs FreeRTOS

| Aspect             | FreeRTOS (C)           | RTIC (Rust)                   | Embassy (Rust)                 |
| ------------------ | ---------------------- | ----------------------------- | ------------------------------ |
| Scheduling model   | Preemptive             | Preemptive (interrupt-driven) | Cooperative async              |
| Task creation      | `xTaskCreate` runtime  | `#[task]` compile-time        | `spawner.spawn()` static       |
| Heap dependency    | Yes (configurable)     | No (SRP, static)              | Optional (tasks can be static) |
| Priority inversion | Mutex + inheritance    | Impossible by construction    | Cooperative: not a concern     |
| Blocking risk      | None (preemptive)      | Must not block in task        | Must await, never busy-wait    |
| Learning curve     | RTOS concepts (medium) | Rust + RTIC model (high)      | Rust + async concepts (medium) |
| DMA / async IO     | Manual ISR + queue     | Manual ISR + resource         | embassy-dma: native async      |

Embassy's cooperative model means a task that never awaits starves all others — the same discipline required in FreeRTOS with cooperative scheduling. The trade: simpler concurrency model, lower overhead, but the programmer must ensure no task loops without awaiting.
