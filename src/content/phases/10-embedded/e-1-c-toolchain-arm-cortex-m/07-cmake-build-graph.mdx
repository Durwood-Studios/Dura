## Why this matters

A firmware build works only in a developer’s existing directory because stale generated files hide a missing dependency. A reproducible build describes inputs and targets, and keeps generated output separate from source.

## Start with something familiar

A workshop plan lists which parts belong to each assembly. Reusing yesterday’s unfinished assembly can hide a missing part; a clean assembly from the plan reveals it.

## The mental model

> CMake generates a build system from target relationships. Configuration, compilation and testing are separate stages with their own inputs and results.

## The mechanism

A target represents an executable or library and its requirements. In a small host-side C example, add_executable names the source files and target_compile_features declares the language feature requirement for that target. This is a host teaching fixture, not a cross-compiled MCU image.

CMakeLists.txt:

```cmake
cmake_minimum_required(VERSION 3.16)
project(sensor_check LANGUAGES C)
add_executable(sensor_check main.c)
target_compile_features(sensor_check PRIVATE c_std_11)
enable_testing()
add_test(NAME sensor_check COMMAND sensor_check)
```

main.c:

```c
int main(void) {
    const int sample = 12;
    return sample >= 0 ? 0 : 1;
}
```

Run `cmake -S . -B build`, then `cmake --build build`, then `ctest --test-dir build --output-on-failure` with CMake and a C compiler installed. Configuration generates files in build; the second command builds the target; the third executes the registered test. A zero process exit is the declared pass contract here.

PRIVATE applies the feature requirement to this target rather than declaring it as a consumer requirement. A library can instead publish requirements its consumers need through an appropriate interface. Avoid global flag changes when a target-scoped requirement states the intention more precisely.

An embedded cross-build also requires a toolchain/target configuration and hardware-specific inputs such as startup and linker definitions. The host success above does not establish an MCU build or timing correctness. Record compiler, generator, toolchain configuration and source revision. If a cached configuration points to an old compiler, use a fresh build directory rather than assuming changing a shell variable replaces every cached choice.

## Practice

Configuration succeeds but the compiler rejects main.c. Which stage passed, and which stage failed?
