## Why this matters

In Lesson E1, the toolchain exercises used infinite loops. Real firmware communicates. UART is the most universal communication channel — it requires only two wires, needs no clock synchronization, and is universally available as a debug port, GPS interface, Bluetooth UART module, or host communication channel.

Understanding UART at register level means you can configure it for any baud rate, data format, or parity scheme the application demands, and handle the error conditions that HAL functions quietly discard.

## UART fundamentals

UART (Universal Asynchronous Receiver/Transmitter) serializes bytes over two wires: TX (transmit) and RX (receive). There is no clock wire — both ends agree in advance on timing parameters:

- **Baud rate** — bits per second (9600, 115200, 921600, etc.)
- **Data bits** — almost always 8
- **Parity** — None / Even / Odd (almost always None in modern systems)
- **Stop bits** — 1 (sometimes 2 for slow UARTs)

"8N1" means 8 data bits, No parity, 1 stop bit — the universal default.

Each byte is transmitted as: 1 start bit (LOW) + 8 data bits (LSB first) + 1 stop bit (HIGH). At 115200 baud, each bit is 8.68 µs; one byte takes 10 bits = 86.8 µs.

## USART2 on STM32F4 — registers from RM0090

STM32F4 has 3 USARTs and 3 UARTs. USART2 is convenient because it's on the APB1 bus (lower speed peripheral bus) and its TX/RX pins (PA2/PA3) are easy to route.

Key registers (base address 0x40004400):

| Register | Offset | Purpose                                        |
| -------- | ------ | ---------------------------------------------- |
| SR       | 0x00   | Status: TXE, RXNE, ORE, FE flags               |
| DR       | 0x04   | Data: write to send, read to receive           |
| BRR      | 0x08   | Baud rate divisor                              |
| CR1      | 0x0C   | Enable, word length, parity, interrupt enables |
| CR2      | 0x10   | Stop bits                                      |
| CR3      | 0x14   | Flow control, DMA enables                      |

Define them in C:

```c
#include <stdint.h>

#define USART2_BASE  0x40004400UL
#define USART2_SR    (*(volatile uint32_t *)(USART2_BASE + 0x00))
#define USART2_DR    (*(volatile uint32_t *)(USART2_BASE + 0x04))
#define USART2_BRR   (*(volatile uint32_t *)(USART2_BASE + 0x08))
#define USART2_CR1   (*(volatile uint32_t *)(USART2_BASE + 0x0C))

/* SR flag bits */
#define SR_TXE   (1U << 7)   /* TX register empty — safe to write next byte */
#define SR_RXNE  (1U << 5)   /* RX not empty — a byte has arrived */
#define SR_ORE   (1U << 3)   /* Overrun — a byte was lost */
#define SR_FE    (1U << 1)   /* Framing error — bad stop bit */

/* CR1 bits */
#define CR1_UE   (1U << 13)  /* USART enable */
#define CR1_TE   (1U << 3)   /* Transmitter enable */
#define CR1_RE   (1U << 2)   /* Receiver enable */
#define CR1_RXNEIE (1U << 5) /* RX-not-empty interrupt enable */
```

## Baud rate calculation

The BRR register holds a fixed-point divisor: USARTDIV = f_CK / (16 × baud_rate), where f_CK is the peripheral clock.

For STM32F4 with USART2 on APB1 at 42 MHz, targeting 115200 baud:

```
USARTDIV = 42,000,000 / (16 × 115200) = 22.786...
Integer part: 22 (0x16)
Fractional part: 0.786 × 16 = 12.57 → 13 (0xD)
BRR value = (22 << 4) | 13 = 0x16D
```

The GCC ARM toolchain's math is exact enough to compute this at compile time:

```c
#define PCLK1_HZ    42000000UL
#define BAUD        115200UL
#define USARTDIV    ((PCLK1_HZ + (BAUD / 2U)) / BAUD)
/* Rounding in BRR: mantissa in bits[15:4], fraction in bits[3:0] */
```

## Initialization — clocks, pins, USART

Three steps in order: clock enable, pin alternate-function setup, USART configuration.

```c
/* RCC base for clock enables */
#define RCC_BASE    0x40023800UL
#define RCC_AHB1ENR (*(volatile uint32_t *)(RCC_BASE + 0x30))
#define RCC_APB1ENR (*(volatile uint32_t *)(RCC_BASE + 0x40))
#define RCC_AHB1ENR_GPIOAEN (1U << 0)
#define RCC_APB1ENR_USART2EN (1U << 17)

/* GPIOA for PA2 (TX) and PA3 (RX) */
#define GPIOA_BASE    0x40020000UL
#define GPIOA_MODER   (*(volatile uint32_t *)(GPIOA_BASE + 0x00))
#define GPIOA_AFRL    (*(volatile uint32_t *)(GPIOA_BASE + 0x20))

void usart2_init(void) {
    /* 1. Enable clocks */
    RCC_AHB1ENR |= RCC_AHB1ENR_GPIOAEN;
    RCC_APB1ENR |= RCC_APB1ENR_USART2EN;

    /* 2. Configure PA2 (TX) and PA3 (RX) as Alternate Function 7 (USART2) */
    /* MODER bits: 10 = AF mode */
    GPIOA_MODER &= ~((0b11U << (2 * 2)) | (0b11U << (3 * 2)));
    GPIOA_MODER |=  ((0b10U << (2 * 2)) | (0b10U << (3 * 2)));
    /* AFRL: 4 bits per pin; PA2=bits[11:8], PA3=bits[15:12]; AF7=0b0111 */
    GPIOA_AFRL &= ~(0xFFU << 8);
    GPIOA_AFRL |=  (0x77U << 8);   /* AF7 for both PA2 and PA3 */

    /* 3. Configure USART2 — 115200 baud, 8N1 */
    USART2_BRR = ((PCLK1_HZ + (BAUD / 2U)) / BAUD);
    USART2_CR1 = CR1_UE | CR1_TE | CR1_RE;  /* Enable USART, TX, RX */
    /* CR2 and CR3 default to 1 stop bit, no flow control — correct for 8N1 */
}
```

## Polled transmit

Wait for TXE, write the byte, done:

```c
void uart_putc(char c) {
    while (!(USART2_SR & SR_TXE)) { }
    USART2_DR = (uint8_t)c;
}

void uart_puts(const char *s) {
    while (*s) uart_putc(*s++);
}
```

Polled is acceptable for low-bandwidth debug output where timing doesn't matter. At 115200 baud, transmitting a single byte takes ~86 µs in the wait loop. For an application that needs to do useful work while transmitting, use interrupt-driven TX (Module E5 covers the full TX ring buffer).

## Interrupt-driven receive with a ring buffer

For receiving, polling doesn't scale — you'd have to poll faster than bytes arrive. At 115200 baud, a byte arrives every 86 µs. The interrupt-driven pattern:

```c
#define RX_BUF_SIZE 64

static volatile uint8_t rx_buf[RX_BUF_SIZE];
static volatile uint8_t rx_head = 0;   /* Written by ISR */
static volatile uint8_t rx_tail = 0;   /* Read by main */

void usart2_rx_interrupt_enable(void) {
    USART2_CR1 |= CR1_RXNEIE;          /* Enable RXNE interrupt */
    /* Enable USART2 IRQ in NVIC — IRQn = 38, ISER1 bit 6 */
    *(volatile uint32_t *)0xE000E104 |= (1U << (38 - 32));
}

/* ISR — fires when a byte arrives */
void USART2_IRQHandler(void) {
    if (USART2_SR & SR_RXNE) {
        uint8_t byte = (uint8_t)USART2_DR;   /* Read clears RXNE */
        uint8_t next = (uint8_t)((rx_head + 1U) % RX_BUF_SIZE);
        if (next != rx_tail) {              /* Buffer not full */
            rx_buf[rx_head] = byte;
            rx_head = next;
        }
        /* If buffer is full, the byte is dropped — better than overrun */
    }
    if (USART2_SR & SR_ORE) {
        /* Overrun: clear by reading DR */
        (void)USART2_DR;
    }
}

/* Main context: drain the ring buffer */
int uart_getc(uint8_t *out) {
    if (rx_head == rx_tail) return 0;   /* Empty */
    *out = rx_buf[rx_tail];
    rx_tail = (uint8_t)((rx_tail + 1U) % RX_BUF_SIZE);
    return 1;
}
```

The `volatile` on `rx_buf`, `rx_head`, and `rx_tail` is mandatory — the ISR modifies them between main-code instructions (Lesson E1/E3 covered this in detail).

## Error handling

The status register contains two error flags every production driver must check:

**ORE (Overrun Error)** — a new byte arrived before the last one was read. The byte is lost. ORE is set even if RXNE is set. Must be cleared by reading DR (a read to DR clears both RXNE and ORE in most STM32 devices). In the ISR above, we explicitly check and clear ORE.

**FE (Framing Error)** — the received stop bit was not HIGH. Usually means wrong baud rate or line noise. If your UART is receiving garbage, check FE first — it often points to a baud rate mismatch rather than a bug in the driver.

Production drivers count error occurrences (per second or since last reset) and expose them via diagnostics. An error rate above 0.1% usually indicates a hardware problem.
