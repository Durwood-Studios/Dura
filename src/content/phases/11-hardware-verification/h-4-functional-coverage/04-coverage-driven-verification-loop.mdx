## Why this matters

A chip project has a tape-out deadline. The verification lead is asked: "Are we done?" The answer is not "we ran a lot of transactions" — it's "our documented coverage plan is closed at the defined goal, and all unreachable bins are documented with rationale."

This lesson teaches the process from initial random run to that answer.

## Start with something familiar

An explorer uses unvisited map regions to plan the next trip.

## The mental model

> Coverage-driven verification investigates holes, adjusts stimulus or the model, and records justified exclusions without treating every percentage gap as a DUT bug.

## The four loop stages

```
Stage 1: SEED → Run random stimulus with diverse seeds
Stage 2: MEASURE → Read the coverage report, identify holes
Stage 3: DIAGNOSE → Classify each hole as statistical or structural
Stage 4: FIX → Refine constraints, write directed sequences, or mark unreachable
             └── Repeat from Stage 1
```

The loop terminates when every bin is either:

- COVERED (hit count ≥ at_least), or
- DOCUMENTED AS UNREACHABLE (ignore_bins with comment)

## Stage 2: Reading the coverage report

A Questa/VCS coverage report for a covergroup looks like:

```
Coverage Report: cg_axi_write
  Coverpoint: cp_addr_region
    COVERED:   zero_page     [hits: 847]
    COVERED:   low_range     [hits: 6,203]
    COVERED:   mid_range     [hits: 3,024]
    NOT_COVERED: high_range  [hits: 2]   ← at_least=10; only 2 hits
  Coverpoint: cp_strb
    COVERED:   full (1111)   [hits: 4,519]
    NOT_COVERED: byte_0 (0001) [hits: 7]
    NOT_COVERED: byte_1 (0010) [hits: 6]
    COVERED:   byte_2 (0100) [hits: 15]
    NOT_COVERED: byte_3 (1000) [hits: 8]
    COVERED:   lower_half    [hits: 12]
    COVERED:   upper_half    [hits: 11]
  Cross: cx_addr_strb
    NOT_COVERED: high_range × byte_0 [hits: 0]
    NOT_COVERED: high_range × byte_1 [hits: 0]
    ...
  Group total: 71.4%
```

This report tells you:

- `high_range` addresses are almost never generated (2 hits vs 10 required).
- Individual byte enables are under-sampled.
- The cross bins combining high addresses with byte enables are completely uncovered.

## Stage 3: Classify each hole

**Statistical hole**: The constraint is correct, but the probability of hitting the bin is low. More transactions or distribution biasing will fix it.

**Structural hole**: The constraint PREVENTS hitting the bin. No amount of random stimulus fixes it.

Diagnosis method:

```systemverilog
// Temporarily disable all constraints and randomize with the exact target
txn.randomize() with {
    awaddr inside { [32'hFF00_0000 : 32'hFFFF_FFFC] };  // Force high_range
    wstrb == 4'b0001;                                     // Force byte_0
};
// If this FAILS: structural hole — constraints prevent this combination
// If this SUCCEEDS: statistical hole — the combo is reachable but rarely generated
```

For the `high_range` hole above: the constraint `c_addr_distribution` only assigns 10% weight to addresses above 0x0001_0000. With default probability, hitting `high_range` in the cross is rare. This is a STATISTICAL hole — the fix is distribution biasing.

## Stage 4a: Fix statistical holes — distribution refinement

```systemverilog
// Before: 10% weight on high addresses
constraint c_addr_distribution {
    awaddr dist {
        32'h0000_0000               := 10,
        [32'h0000_0004 : 32'h0000_FFFC] := 70,
        [32'h0001_0000 : 32'hFFFF_FFFC] := 10,   // Too low for reliable coverage
        32'h0000_FFFC               := 10
    };
}

// After: increase high-range weight for targeted regression
constraint c_addr_distribution {
    awaddr dist {
        32'h0000_0000               := 5,
        [32'h0000_0004 : 32'h0000_FFFC] := 40,
        [32'h0001_0000 : 32'hFFFF_FFFC] := 50,   // Raised: target coverage closure
        32'h0000_FFFC               := 5
    };
}
```

Or write a targeted sequence without touching the base class:

```systemverilog
class high_addr_byte_seq extends uvm_sequence #(axi4_lite_write_txn);
    `uvm_object_utils(high_addr_byte_seq)
    task body();
        axi4_lite_write_txn t;
        repeat (50) begin
            t = axi4_lite_write_txn::type_id::create("t");
            start_item(t);
            assert(t.randomize() with {
                awaddr inside { [32'hFF00_0000 : 32'hFFFF_FFFC] };
                wstrb inside { 4'b0001, 4'b0010, 4'b0100, 4'b1000 };
            });
            finish_item(t);
        end
    endtask
endclass
```

Run the targeted sequence in the test that's missing the coverage, then re-measure.

## Stage 4b: Fix structural holes — constraint redesign

If your diagnosis shows the hole is structural (randomize fails even when forced), find the conflicting constraint:

```systemverilog
// Hypothesis: c_addr_word_aligned conflicts with unaligned byte enable
// Test: is a high address with strb=4'b0001 possible given word alignment?
// AXI4-Lite requires word alignment for ALL writes
// → strb=0001 + word-aligned addr is LEGAL in AXI4-Lite
// → But: our constraint ALSO has c_addr_range: soft addr inside [0..64K]
// The soft constraint biases but doesn't block — this is statistical, not structural.

// If we have: constraint c_only_high { addr > 32'hFFFF_FFFF; }
// That IS structural if addr is 32-bit (no value satisfies > max 32-bit value)
// Fix: remove the buggy constraint
```

For genuine structural holes (cross combination that the DUT's spec says can never occur), use ignore_bins:

```systemverilog
cx_addr_strb : cross cp_addr, cp_strb {
    // AXI4-Lite spec: privileged writes only go to high addresses.
    // strb-only (byte writes) to high-security addresses are not supported
    // in our system's memory map.
    ignore_bins high_byte_write =
        binsof(cp_addr.high_range) && binsof(cp_strb.byte_enables);
    // Documentation: "High-range memory is 64-bit aligned only"
}
```

## Closure declaration

Coverage closure is a formal document, not just a number:

```
Coverage Closure Record: AXI4-Lite Write Testbench
Date: 2026-06-30
Engineer: [name]

Coverage Model: cg_axi_write (axi_write_cov.sv)
Goal: cp_addr: 100%, cp_strb: 100%, cx: 100%

Final Coverage: 100% (all bins at_least=10 satisfied)

Excluded bins and rationale:
- cx_addr_strb.high_range × byte_enables: IGNORE_BINS
  Rationale: High-range addresses (0xFF00_0000+) in our memory map are
  write-combined registers that require 32-bit aligned full-word writes.
  Byte-enable sub-word writes to these addresses are architecturally
  prohibited and will never be issued by software. Reference: Memory Map
  Spec rev 3.2 §4.7.
  Formal proof available: h6_no_byte_write_to_highmem.jdb

Signed: [lead engineer]
Reviewed: [verification lead]
```

The sign-off document makes the closure reproducible and auditable. "We ran lots of transactions" does not qualify as closure. "All bins in the documented coverage model were hit at_least 10 times or explicitly excluded with written rationale" does.
