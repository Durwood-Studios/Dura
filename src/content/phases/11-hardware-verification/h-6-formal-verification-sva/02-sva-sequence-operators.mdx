## Why this matters

Lesson H6-1 introduced the core SVA building blocks: `##N`, `|->`, `$rose`, `$fell`. Those are enough for simple handshakes. Real protocols are not simple. Consider AXI4 AWVALID: once asserted it must stay high — with AWADDR stable — until AWREADY is seen. That constraint can't be expressed with a single `##`. The operators this lesson covers — repetition, `throughout`, `within` — are how you write it.

Every complex protocol property that looks hard reduces to a combination of these operators. Knowing them changes SVA from "I can write a two-cycle check" to "I can write the full AXI spec as a set of properties."

## Consecutive repetition — [*N] and [*N:M]

`[*N]` repeats a boolean expression over exactly N consecutive clock cycles:

```systemverilog
// Signal must be high for exactly 4 consecutive cycles
sequence s_4_high;
    valid [*4];         // valid is true on cycles 0, 1, 2, 3
endsequence

// Range: 1 to 4 consecutive cycles
sequence s_burst_len;
    valid [*1:4];       // matches 1, 2, 3, or 4 consecutive cycles
endsequence

// Unbounded upper end — 1 to infinity
sequence s_until_done;
    valid [*1:$];       // at least one cycle; $ = unlimited
endsequence
```

The AXI valid-stable requirement uses this directly:

```systemverilog
// AXI4: once awvalid is asserted, it must stay high until awready
property p_awvalid_stable;
    @(posedge clk) disable iff (!rst_n)
        $rose(awvalid) |-> awvalid [*1:$] ##0 awready;
        //                 ^^^^^^^^^^^^^^^^^^ valid stays high until...
        //                                             ^^ ready arrives same cycle
endproperty
assert property (p_awvalid_stable);
```

Reading this: "Once awvalid rises, it stays high for 1 or more cycles, and at the end of that run, awready is also high."

## Non-consecutive repetition — [->N] and [=N]

Sometimes a condition must happen N times but not necessarily consecutively.

**Goto repetition `[->N]`** — matches exactly N occurrences, ending on the last:

```systemverilog
// Exactly 3 grants issued before request drops
sequence s_three_grants;
    grant [->3];     // grant appears exactly 3 times (non-consecutive OK)
endsequence

property p_req_gets_three_grants;
    @(posedge clk)
        req |-> ##1 grant [->3] ##1 !req;
endproperty
```

The sequence ends on the third `grant` assertion. `[->N]` is "goto" — it advances to the next match.

**Non-consecutive [=N]** — matches N occurrences but allows trailing cycles after the last:

```systemverilog
// grant appears exactly 3 times within 10 cycles (not necessarily last)
sequence s_three_grants_bounded;
    grant [=3] ##[0:5] done;  // 3 grants, then done within 5 cycles after
endsequence
```

**In practice**: use `[->N]` when you care about the ending point, `[=N]` when you care about count but the sequence continues beyond the last occurrence.

## throughout — condition holds across the entire sequence

`throughout` asserts that a condition is true on every cycle of the sequence:

```systemverilog
// Data must remain stable throughout a burst (no changes while valid)
property p_data_stable_during_burst;
    @(posedge clk) disable iff (!rst_n)
        (wvalid && !wready) |->
            ($stable(wdata) && $stable(wstrb)) throughout (wvalid [*1:$]);
endproperty
assert property (p_data_stable_during_burst);
```

Reading this: "If wvalid is asserted and wready isn't (mid-burst), then wdata and wstrb must be stable throughout the run of wvalid."

Another common use — clock enable must stay high during a multi-cycle operation:

```systemverilog
property p_clk_en_during_mult;
    @(posedge clk)
        start_mult |-> clk_en throughout (start_mult ##[1:8] done_mult);
endproperty
```

## within — one sequence contained in another

`s1 within s2` succeeds when sequence s1 completes entirely inside sequence s2:

```systemverilog
// The full AXI read data transfer must complete within the burst window
sequence s_rdata_phase;
    rvalid ##[0:3] rready;    // One rdata transfer
endsequence

sequence s_burst_window;
    ##[1:256] burst_done;     // Burst window
endsequence

property p_rdata_in_burst;
    @(posedge clk)
        start_burst |-> (s_rdata_phase within s_burst_window);
endproperty
```

`within` is less commonly used than `throughout` because it requires both sequences to start on the same cycle, which limits its applicability. Know it for the protocol specs that do need it (specifically, checking that sub-events finish inside a parent event window).

## intersect — both sequences match, same total length

`intersect` requires both sequences to match AND finish in the same clock cycle:

```systemverilog
// req lasts exactly as long as gnt — both must end together
property p_req_gnt_aligned;
    @(posedge clk)
        req |-> req [*1:$] intersect gnt [*1:$];
endproperty
```

This is stricter than `and` (which just requires both to eventually complete). `intersect` is the right operator when two signals must have the same pulse width.

## first_match — stop at earliest completion

When a sequence can match in multiple ways, `first_match` stops at the earliest:

```systemverilog
// Multiple possible end points — stop at first valid ack
sequence s_fast_ack;
    first_match(req ##[1:5] ack);   // Match as soon as ack appears
endsequence
```

Without `first_match`, the sequence engine forks at each possible end point and checks them all. This affects how `|->` interacts with sequences that have `[*]` operators — `first_match` tightens the semantics.

## A complete AXI4 write channel property

Combining everything:

```systemverilog
// AXI4 write channel: AWVALID stable until AWREADY;
//                     WVALID must follow within 0-100 cycles;
//                     WDATA stable throughout each WVALID cycle.
package axi4_pkg;

property p_aw_stable_until_rdy;
    @(posedge clk) disable iff (!rst_n)
        $rose(awvalid) |->
            (awvalid && $stable(awaddr) && $stable(awlen)) throughout
            (awvalid [*1:$] ##0 awready);
endproperty

property p_w_follows_aw;
    @(posedge clk) disable iff (!rst_n)
        awvalid |-> ##[0:100] wvalid;
endproperty

property p_wdata_stable;
    @(posedge clk) disable iff (!rst_n)
        (wvalid && !wready) |->
            $stable(wdata) && $stable(wstrb);
endproperty

endpackage
```

These three properties together cover the core AXI4 write-address + write-data correctness. Each is one line (or close to it) once you know the operators.
