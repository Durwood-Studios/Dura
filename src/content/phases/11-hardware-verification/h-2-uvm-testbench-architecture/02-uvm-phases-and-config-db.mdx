## Why this matters

A UVM testbench can span dozens of components, each needing to set up before others can connect, and connect before any can run. Without an orchestrated setup sequence, components try to connect to handles that don't exist yet. The phase model is UVM's solution: a barrier-synchronized execution protocol that guarantees ordering.

## The full phase sequence

```
build_phase         ← Components create their children (top-down)
connect_phase       ← TLM connections made between existing components
end_of_elaboration  ← One-time sanity checks; all connections exist
start_of_simulation ← Optional pre-run initialization
run_phase           ← Simulation runs; parallel tasks; objections control duration
extract_phase       ← Collect data after sim ends
check_phase         ← Verify collected data
report_phase        ← Print summary
final_phase         ← Tear-down actions (close files, etc.)
```

The simulator calls each phase's method on EVERY component before moving to the next phase. This is the barrier: `build_phase` of every component completes before any `connect_phase` begins.

## build_phase — top-down construction

```systemverilog
class my_env extends uvm_env;
    `uvm_component_utils(my_env)
    my_agent  agent;
    my_scoreboard sb;

    function void build_phase(uvm_phase phase);
        super.build_phase(phase);
        // Create sub-components HERE, not in new()
        agent = my_agent::type_id::create("agent", this);
        sb    = my_scoreboard::type_id::create("sb", this);
        // The agent's build_phase will run AFTER this function returns
    endfunction
endclass
```

Key rule: create sub-components in `build_phase`, not in `new()`. The factory isn't ready in `new()`, and the config DB isn't populated yet.

Top-down means: `uvm_test::build_phase` runs first, then `uvm_env::build_phase`, then each `uvm_agent::build_phase`. Children are always created before the scheduler descends into them.

## connect_phase — wiring TLM ports

```systemverilog
function void connect_phase(uvm_phase phase);
    // By now, both agent and scoreboard exist
    agent.driver.seq_item_port.connect(agent.sequencer.seq_item_export);
    agent.monitor.ap.connect(sb.analysis_export);
endfunction
```

`connect_phase` runs AFTER all `build_phase` calls complete. This guarantees that both ends of every TLM connection exist before any connection is attempted. Trying to connect in `build_phase` fails because the peer component may not exist yet.

## run_phase — the simulation heart

`run_phase` is the only phase that runs time. All other phases are zero-time functions.

```systemverilog
task run_phase(uvm_phase phase);
    my_sequence seq = my_sequence::type_id::create("seq");
    phase.raise_objection(this);    // "I have work to do"
    seq.start(agent.sequencer);
    phase.drop_objection(this);     // "I'm done"
endtask
```

Objections are reference-counted. `run_phase` ends when ALL objections across ALL components drop to zero. This is the mechanism that keeps simulation alive until every component finishes its work.

**Common bugs:**

| Symptom                            | Cause                                    | Fix                                        |
| ---------------------------------- | ---------------------------------------- | ------------------------------------------ |
| Sim ends at time 0                 | No component raises an objection         | Add `raise_objection` before blocking work |
| Sim runs forever                   | An objection is raised but never dropped | Verify `drop_objection` is reached         |
| Sim ends before sequence completes | Objection dropped before sequence starts | Raise before `seq.start()`, drop after     |

## The configuration database

The config DB is UVM's mechanism for passing arbitrary data — virtual interfaces, configuration objects, integers — from the testbench top level into deeply nested components without building constructor argument chains.

**Setting** (from top module or test):

```systemverilog
// From top-level SV module (before run_test)
module tb_top;
    uart_if u_if(.clk(clk), .rst_n(rst_n));
    initial begin
        // Set the interface in the DB for any component whose path contains "uvm_test_top"
        uvm_config_db #(virtual uart_if)::set(null, "uvm_test_top.*", "vif", u_if);
        run_test("my_uart_test");
    end
endmodule
```

**Getting** (from deep inside the component tree):

```systemverilog
class uart_driver extends uvm_driver #(uart_txn);
    virtual uart_if vif;

    function void build_phase(uvm_phase phase);
        // Retrieve the interface from the DB
        if (!uvm_config_db #(virtual uart_if)::get(this, "", "vif", vif))
            `uvm_fatal("DRV", "uart_if not found in config DB — check path and key")
    endfunction
endclass
```

The `set` call signature:

```
uvm_config_db #(T)::set(context, path_pattern, key, value)
```

- `context` — which component is the "root" for the path pattern. `null` means UVM root.
- `path_pattern` — glob pattern for the component hierarchy path. `"uvm_test_top.*"` matches any component under the test.
- `key` — the lookup name. Must match exactly between set and get.

The `get` call:

```
uvm_config_db #(T)::get(this, "", key, variable)
```

- `this` — the requesting component (its path is used for matching).
- `""` — additional path extension (usually empty).
- Returns 1 if found; 0 if not found (the `if (!...)` pattern).

## Configuration objects pattern

For complex configuration (multiple parameters per agent), use a configuration class:

```systemverilog
class uart_agent_cfg extends uvm_object;
    `uvm_object_utils(uart_agent_cfg)
    int baud_rate  = 115200;
    bit parity_en  = 1'b0;
    bit active     = 1'b1;   // 1=active agent, 0=passive (monitor only)
    function new(string name = "uart_agent_cfg");
        super.new(name);
    endfunction
endclass

// In test:
uart_agent_cfg cfg = uart_agent_cfg::type_id::create("cfg");
cfg.baud_rate = 9600;
cfg.active    = 0;   // Passive mode
uvm_config_db #(uart_agent_cfg)::set(this, "env.uart_agent", "cfg", cfg);

// In agent's build_phase:
uart_agent_cfg cfg;
if (!uvm_config_db #(uart_agent_cfg)::get(this, "", "cfg", cfg))
    cfg = uart_agent_cfg::type_id::create("cfg");  // Use defaults
```

This pattern lets tests configure agents without knowing their internal structure.
