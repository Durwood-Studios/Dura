## Why this matters

The constraint solver picks random values for your `rand` fields. But many protocol transactions have DERIVED fields — fields whose values are deterministically computed from the random fields:

- A packet's CRC is computed from its payload.
- A TLP's byte-count field is derived from its length field.
- A register write's expected-read-back value depends on the write data.

These can't be expressed as constraints (they're not random; they're derived). They can't be set before `randomize()` (the random fields aren't assigned yet). `post_randomize()` is called by the simulator automatically after every `randomize()` call, when all `rand` fields have their new values — exactly the right moment.

## post_randomize — the callback

```systemverilog
class ethernet_frame;
    rand bit [7:0]  payload [];   // Variable-size payload
    rand bit [15:0] etype;
    rand bit [47:0] dst_mac;
    rand bit [47:0] src_mac;

    // Derived (not rand)
    bit [31:0] crc32;
    int        frame_length;

    constraint c_payload_size { payload.size() inside { [46:1500] }; }
    constraint c_etype_ipv4   { soft etype == 16'h0800; }

    function void post_randomize();
        // Compute CRC from the randomized payload
        crc32 = compute_crc32(payload);

        // Compute frame_length from all fields
        frame_length = 6 + 6 + 2 + payload.size() + 4;  // dst + src + etype + payload + crc
    endfunction

    function automatic bit [31:0] compute_crc32(bit [7:0] data[]);
        bit [31:0] crc = 32'hFFFF_FFFF;
        foreach (data[i]) begin
            // Simplified CRC-32 — real implementation uses lookup table
            for (int j = 0; j < 8; j++) begin
                if ((crc[0] ^ data[i][j]) == 1'b1)
                    crc = (crc >> 1) ^ 32'hEDB8_8320;
                else
                    crc = crc >> 1;
            end
        end
        return ~crc;
    endfunction
endclass

// After randomize(), the CRC and frame_length are automatically correct:
ethernet_frame f = new();
f.randomize();
// f.crc32 is now computed from f.payload — no extra call needed
```

## pre_randomize — before randomization

`pre_randomize()` fires BEFORE the solver runs. Uses:

- Save the current state before randomization (for comparison).
- Set up external state that the constraints will reference.
- Seed or adjust the randomization context.

```systemverilog
class stateful_txn;
    rand bit [31:0] addr;
    rand int        txn_id;
    int             prev_txn_id;   // Last issued ID (non-random)
    int             next_expected;  // Computed from issue history

    constraint c_id_sequential { txn_id > prev_txn_id; }

    function void pre_randomize();
        // Save current state before the solver changes rand fields
        prev_txn_id = txn_id;   // txn_id still has its old value here
    endfunction

    function void post_randomize();
        // After solver picks new txn_id, derive the expected
        next_expected = txn_id + 1;
    endfunction
endclass
```

The lifecycle per `randomize()` call:

```
1. pre_randomize() fires   (txn_id still has old value)
2. Constraint solver runs  (assigns new values to rand fields)
3. post_randomize() fires  (all rand fields have new values)
```

## Inheritance and super calls

In a derived class, you MUST call `super.post_randomize()`:

```systemverilog
class base_txn;
    rand bit [31:0] data;
    bit [31:0] parity;

    function void post_randomize();
        parity = ^data;   // XOR parity of data
    endfunction
endclass

class extended_txn extends base_txn;
    rand bit [15:0] tag;
    bit [15:0]      tag_checksum;

    function void post_randomize();
        super.post_randomize();   // MUST call first — computes parity
        // Now add the derived class's post-randomize work
        tag_checksum = tag ^ 16'hDEAD;
    endfunction
endclass
```

If you forget `super.post_randomize()`, the base class's derived fields (parity in this example) won't be computed. This is the single most common inheritance bug in post_randomize.

## post_randomize vs constraints — which to use

| Use case                                                         | Right tool      |
| ---------------------------------------------------------------- | --------------- |
| Restrict the range of a random field                             | constraint      |
| Enforce relationships between random fields                      | constraint      |
| Compute a field deterministically from random fields             | post_randomize  |
| Integrate with external state (address map, scoreboard context)  | post_randomize  |
| Generate a CRC, checksum, or hash                                | post_randomize  |
| Conditionally populate optional fields after random choices made | post_randomize  |
| Clamp a value to a runtime-determined range                      | pre + post pair |

Constraints can only express relationships between `rand` fields. post_randomize can call any function, access any external state, and compute anything the constraints cannot.

## A complete example — AXI write burst

```systemverilog
class axi_write_burst;
    rand bit [31:0]  base_addr;
    rand bit [7:0]   beat_count;       // 1-256 beats
    rand bit [2:0]   burst_size;       // bytes per beat: 2^size
    rand bit [1:0]   burst_type;       // 0=FIXED, 1=INCR, 2=WRAP
    rand bit [31:0]  write_data [];    // Randomized payload

    // Derived fields
    bit [31:0] addresses [];   // Per-beat address
    int        byte_count;     // Total bytes in transaction

    constraint c_beat_count   { beat_count inside { [1:16] }; }
    constraint c_burst_size   { burst_size inside { [0:3] }; }  // 1/2/4/8 bytes
    constraint c_incr_align   { burst_type == 1 -> (base_addr % (1 << burst_size)) == 0; }
    constraint c_data_size    { write_data.size() == beat_count; }

    function void post_randomize();
        bit [31:0] addr = base_addr;
        addresses = new[beat_count];

        // Compute per-beat addresses based on burst type
        for (int i = 0; i < beat_count; i++) begin
            addresses[i] = addr;
            case (burst_type)
                1: addr += (1 << burst_size);          // INCR: add stride
                2: addr = wrap_address(addr, burst_size, beat_count); // WRAP
                // FIXED: addr stays the same (no update)
            endcase
        end

        byte_count = beat_count * (1 << burst_size);
    endfunction

    function automatic bit [31:0] wrap_address(
        bit [31:0] current, bit [2:0] size, bit [7:0] count
    );
        int wrap_boundary = (1 << size) * count;
        int wrap_mask = ~(wrap_boundary - 1);
        bit [31:0] wrap_base = current & wrap_mask;
        bit [31:0] offset = (current + (1 << size)) % wrap_boundary;
        return wrap_base | offset;
    endfunction
endclass
```

After `txn.randomize()`, `txn.addresses[]` contains the complete address sequence for the burst — ready to drive directly into a UVM driver.
