## The coordination problem

H5-01 showed a virtual sequence that stored sequencer handles directly as class fields:

```systemverilog
class scenario_seq extends uvm_sequence;
    axi_sequencer  axi_seq;   // Set manually before start()
    apb_sequencer  apb_seq;
    task body();
        fork
            ...axi_seq...
            ...apb_seq...
        join_all
    endtask
endclass
```

This works, but the test class must know about each sequencer and set each field. As the testbench grows to 5-10 agents, the test class becomes a wiring diagram. The cleaner pattern uses a **virtual sequencer**: a dedicated UVM component whose only job is to hold the per-agent sequencer handles.

## The virtual sequencer

```systemverilog
// soc_vseqr.sv
class soc_vseqr extends uvm_sequencer;
    `uvm_component_utils(soc_vseqr)

    // One handle per agent's sequencer
    axi_sequencer   axi_seqr;
    apb_sequencer   apb_seqr;
    irq_sequencer   irq_seqr;
    dma_sequencer   dma_seqr;

    function new(string name, uvm_component parent);
        super.new(name, parent);
    endfunction
endclass
```

It extends `uvm_sequencer` but with a null item type — it doesn't generate items directly. Its only value is the handles it holds.

The environment creates and wires it in `connect_phase`:

```systemverilog
// soc_env.sv
class soc_env extends uvm_env;
    `uvm_component_utils(soc_env)

    axi_agent   m_axi_agent;
    apb_agent   m_apb_agent;
    irq_agent   m_irq_agent;
    dma_agent   m_dma_agent;
    soc_vseqr   m_vseqr;

    function void build_phase(uvm_phase phase);
        m_axi_agent = axi_agent::type_id::create("m_axi_agent", this);
        m_apb_agent = apb_agent::type_id::create("m_apb_agent", this);
        m_irq_agent = irq_agent::type_id::create("m_irq_agent", this);
        m_dma_agent = dma_agent::type_id::create("m_dma_agent", this);
        m_vseqr     = soc_vseqr::type_id::create("m_vseqr", this);
    endfunction

    function void connect_phase(uvm_phase phase);
        // Wire the per-agent sequencers into the virtual sequencer
        m_vseqr.axi_seqr = m_axi_agent.sequencer;
        m_vseqr.apb_seqr = m_apb_agent.sequencer;
        m_vseqr.irq_seqr = m_irq_agent.sequencer;
        m_vseqr.dma_seqr = m_dma_agent.sequencer;
    endfunction
endclass
```

The wiring happens once in the environment. Every test and every virtual sequence benefits.

## The `uvm_declare_p_sequencer macro

Virtual sequences need a typed handle to the virtual sequencer. The `\`uvm_declare_p_sequencer`macro creates a field`p_sequencer` of the declared type, automatically cast and checked at sequence start:

```systemverilog
class soc_boot_scenario extends uvm_sequence;
    `uvm_object_utils(soc_boot_scenario)
    `uvm_declare_p_sequencer(soc_vseqr)   // Creates: soc_vseqr p_sequencer;

    task body();
        // p_sequencer is now a typed soc_vseqr handle
        // Access per-agent sequencers through it:
        apb_reset_seq rst = apb_reset_seq::type_id::create("rst");
        rst.start(p_sequencer.apb_seqr);

        axi_init_seq init = axi_init_seq::type_id::create("init");
        init.start(p_sequencer.axi_seqr);

        // Wait for DMA ready, then trigger a transfer
        wait_dma_ready_seq wait_dma = wait_dma_ready_seq::type_id::create("wait_dma");
        wait_dma.start(p_sequencer.dma_seqr);

        fork
            begin
                dma_transfer_seq dma_xfr = dma_transfer_seq::type_id::create("dma_xfr");
                dma_xfr.start(p_sequencer.dma_seqr);
            end
            begin
                // IRQ monitoring happens concurrently
                irq_monitor_seq irq = irq_monitor_seq::type_id::create("irq");
                irq.start(p_sequencer.irq_seqr);
            end
        join_any
    endtask
endclass
```

The scenario reads like a protocol: reset the APB bus, initialize AXI, wait for DMA ready, then concurrently run DMA transfer while monitoring interrupts.

## Running a virtual sequence from the test

```systemverilog
class boot_test extends uvm_test;
    `uvm_component_utils(boot_test)
    soc_env env;

    function void build_phase(uvm_phase phase);
        env = soc_env::type_id::create("env", this);
    endfunction

    task run_phase(uvm_phase phase);
        soc_boot_scenario boot = soc_boot_scenario::type_id::create("boot");
        phase.raise_objection(this);
        boot.start(env.m_vseqr);   // Start on the virtual sequencer
        phase.drop_objection(this);
    endtask
endclass
```

The test is three meaningful lines: create the scenario, raise objection, start it, drop objection. All agent-level coordination lives in the scenario class.

## Passing the virtual sequencer via config_db

For testbench reuse across multiple environments, set the virtual sequencer in the config DB instead of hardcoding it in the test:

```systemverilog
// In the environment's end_of_elaboration_phase (after connect_phase):
function void end_of_elaboration_phase(uvm_phase phase);
    uvm_config_db #(soc_vseqr)::set(this, "*.vseqr", "vseqr", m_vseqr);
endfunction

// In the test, retrieve it:
task run_phase(uvm_phase phase);
    soc_vseqr vseqr;
    if (!uvm_config_db #(soc_vseqr)::get(this, "", "vseqr", vseqr))
        `uvm_fatal("TEST", "No virtual sequencer in config DB")
    boot.start(vseqr);
endtask
```

This pattern lets the same test class work with different environments (a real environment for full regression, a stub environment for unit tests) by substituting a different virtual sequencer in the config DB.
