## Why power-aware

A normal RTL simulator drives all flops with the supplies always on. Real silicon has multiple power supplies, and parts of the design turn off independently. When a power domain turns off:

- All flops in that domain lose state (unless explicitly retained).
- Outputs of the domain become unknown unless isolated.
- Inputs to the domain from other domains may need level-shifting if voltages differ.

A bug in power-domain interface logic produces silicon that boots wrong, hangs after sleep, or burns power. UPF + power-aware sim is how DV catches these pre-silicon.

## UPF — the power intent

UPF is a separate file from the RTL that describes power topology:

```tcl
# example.upf — power intent for a SoC fragment
create_power_domain TOP -include_scope
create_power_domain PD_CPU -elements {cpu/*}
create_power_domain PD_GPU -elements {gpu/*}

# Supplies
create_supply_set ss_top      -function {power VDD} -function {ground VSS}
create_supply_set ss_cpu_sw   -function {power VDD_CPU} -function {ground VSS}
create_supply_set ss_gpu_sw   -function {power VDD_GPU} -function {ground VSS}

associate_supply_set ss_top    -handle TOP.primary
associate_supply_set ss_cpu_sw -handle PD_CPU.primary
associate_supply_set ss_gpu_sw -handle PD_GPU.primary

# Isolation: outputs of PD_CPU must hold at logic 0 when CPU is off
set_isolation cpu_iso -domain PD_CPU \
    -isolation_signal pmu/cpu_iso_en -isolation_sense high \
    -clamp_value 0 -applies_to outputs

# Retention: these flops keep state across power-down
set_retention cpu_ret -domain PD_CPU \
    -retention_supply ss_top.primary \
    -save_signal pmu/cpu_save \
    -restore_signal pmu/cpu_restore

# Power states
add_power_state PD_CPU.primary \
    -state ON  { -supply_expr { power == \`{FULL_ON, 1.0V} && ground == \`{FULL_ON, 0V}} } \
    -state OFF { -supply_expr { power == \`{OFF}                                  } }
```

Reading this:

- Two switchable domains (CPU, GPU) plus an always-on top domain.
- Each switchable domain has its own supply.
- When CPU is off, outputs must clamp to 0 (the isolation strategy).
- Certain flops retain state (using always-on retention supply) across power-down.
- Power states define when supplies are on or off.

## Power-aware simulation

The simulator reads RTL + UPF and produces a power-aware netlist that models supply behavior:

- When PD_CPU is off, all signals in `cpu/*` become X (unknown).
- Isolation cells force outputs to 0 while CPU is off.
- Retention flops keep their state through the off period and restore it.
- Level shifters between domains adjust voltage levels.

A power-aware sim that violates these constraints produces an X-propagation in the destination domain. Without UPF awareness, the same bug looks like correct behavior in RTL sim and fails only in silicon.

## Common bugs power-aware sim catches

### Missing isolation

```systemverilog
// In RTL (PD_CPU side)
assign cpu_done = ...;   // No isolation; goes directly to PD_TOP

// PD_TOP uses cpu_done:
always_ff @(posedge clk) begin
    if (cpu_done) state <= NEXT;
end
```

When PD_CPU is off, `cpu_done` is X. PD_TOP samples X, and the state machine becomes undefined. Power-aware sim shows this immediately; RTL sim does not.

UPF fix: add `set_isolation` for outputs of PD_CPU; insertion tools add the isolation cells in synthesis.

### Retention vs non-retention flops

A flop marked for retention saves state through power-down. A flop NOT marked must be re-initialized on power-up.

```systemverilog
// Counter that needs to keep counting across sleep
reg [7:0] cycle_count;   // Must be retention
```

If the designer forgot to mark this for retention, the count resets every sleep cycle. Silicon symptom: incorrect timing measurements, lost configuration.

### Power-on sequence

When PD_CPU turns back on:

1. Supply voltages stabilize (~tens of µs).
2. Isolation enable is deasserted (outputs become real).
3. Retention restore signal is asserted (state restored).
4. Reset is released.

Bugs in this sequence cause boot failures. Power-aware sim models the timing.

## Assertions for power transitions

```systemverilog
// Isolation must be enabled before power-down
property p_iso_before_off;
    @(posedge clk)
        $rose(cpu_pwr_req) |-> ##[0:5] cpu_iso_en;
endproperty
assert property (p_iso_before_off);

// State must be saved before turning off
property p_save_before_off;
    @(posedge clk)
        cpu_save |=> ##[0:10] cpu_pwr_off;
endproperty
assert property (p_save_before_off);
```

These assertions express the power sequencing protocol. Power-aware sim runs them with the same UVM machinery from H2-H5.
