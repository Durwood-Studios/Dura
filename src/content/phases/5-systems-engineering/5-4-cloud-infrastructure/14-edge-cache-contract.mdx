## Why this matters

A nearby cache makes public pages fast, but a poorly scoped key serves one learner’s private response to another. Moving work toward the network edge changes latency and trust boundaries, not just geography.

## Start with something familiar

A local library branch can keep popular public books nearby. It should not place a patron’s private account letter on a shared shelf because the envelope looks like other mail.

## The mental model

> Choose which computation and data can safely live at the edge, define cache identity and freshness, and preserve origin authorization. Proximity does not make private data public or stale data correct.

## The mechanism

Edge computing places selected processing closer to clients or data sources. It can reduce some network travel but introduces distributed deployment, capacity, state and observability concerns. A globally nearby function may still wait on a distant authoritative database, so measure the whole request path.

The fixture has public lesson content keyed by lesson/version/language and a private progress endpoint keyed by authenticated owner. Public versioned content can use an explicit shared-cache policy. Private progress should not enter a shared cache under a URL-only key; response directives and actual cache behavior must preserve its confidentiality. RFC9111 defines HTTP cache semantics, including restrictions around authenticated and private responses; custom CDN configuration still needs verification.

A freshness contract distinguishes fresh, stale-but-permitted and unavailable. For a public lesson version, a long-lived immutable asset can be appropriate when its URL changes with content. For a revocable permission or current balance, serving stale state may be unacceptable. Do not use one time-to-live for every endpoint merely for convenience.

The synthetic test sequence is user A requests /progress, then user B requests the same URL. B must never receive A’s response. Additional tests cover a language variant, content-version change, origin outage and cache invalidation. Record hit/miss, response age, cache key dimensions and authorization outcomes without logging private payloads.

A CDN purge request is not automatically proof that every edge has discarded the object. Design versioning or bounded invalidation evidence according to the provider contract. This lesson reviews a request/cache matrix; no edge provider is deployed and no private response is transmitted.
