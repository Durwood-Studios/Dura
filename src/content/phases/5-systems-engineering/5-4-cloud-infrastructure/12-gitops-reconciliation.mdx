## Why this matters

An operator changes a replica count during an incident, then an automated controller changes it back. Without understanding the declared source of state and reconciliation policy, the team can fight its own automation.

## Start with something familiar

A thermostat repeatedly compares the room with a set point. Changing the room once does not change the set point. GitOps similarly needs a declared desired state and a controller that observes the difference.

## The mental model

> GitOps uses versioned declarative desired state, automatic retrieval and continuous reconciliation. A commit or a successful sync command does not by itself prove that the application became healthy.

## The mechanism

OpenGitOps principles distinguish declared/versioned state, automatic pull and continuous reconciliation. A repository used only as a place to store deployment scripts does not automatically satisfy this model. The controller needs controlled read access to its source and appropriately bounded authority over the target.

The fixture declares replicas3 at revisionR1. Actual state is 2 after manual intervention. If the controller still observesR1 and its policy permits repair, it attempts to restore3. To intentionally keep2, change the approved desired state or use the documented incident suspension procedure rather than repeatedly editing the live object.

A reconciliation status should report desired revision, observed revision, drift, apply failures and health evidence. A manifest may apply successfully while pods fail readiness. A repository outage can leave the last known desired state active without proving a new revision was fetched. Surface stale observation rather than showing an unconditional green check.

Review changes before they reach the trusted source, separate environment scopes and avoid committing secrets in plaintext. A compromised repository or overprivileged reconciler can change production; automatic operation does not remove access-control requirements. Rollback means selecting a reviewed prior desired state, but data migrations may need their own recovery process.

For this exercise, the incident owner suspends reconciliation for a time-bounded diagnosis, records the reason, then either commits a reviewed change or resumes the prior declaration. The written record must show which authority was active at each point. No cluster controller or repository mutation is executed by this lesson.
