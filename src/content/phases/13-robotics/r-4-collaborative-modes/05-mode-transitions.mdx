## The gap between mode documentation and transition documentation

After Lessons R4-1 through R4-4, you can document a collaborative cell's safety functions for each of its operating modes:

- **Production mode:** SSM with calculated separation distance and PL d speed monitoring.
- **Setup mode:** HG with three-position enabling device and gravity compensation.
- **Maintenance mode:** SMS with safety-rated stop on any personnel entry.

A risk assessment that documents only the per-mode safety functions is about 70% complete. The other 30% is the transitions: what happens at the moment the cell moves from one mode to another?

The transition from Production to Maintenance is a particularly clear example. During Production, the SSM safety scanner is the primary protection. During Maintenance, the SMS interlocking at the perimeter gate is the primary protection. Between the two — during the transition — neither is yet active. If an operator enters the cell at that moment, what happens?

If the answer is "nothing defined" or "the operator must wait," that is an informal procedural control. Informal controls are residual risk items, not safety functions. A proper transition safety function is an engineered barrier that prevents the transition from completing unless the robot is in a known safe state.

## The operational state machine

The design tool for mode transitions is an **operational state machine** — a formal description of every operating state, every transition between states, and every condition (guard) that must be true for a transition to occur.

For a three-mode collaborative cell:

```
States: SETUP, PRODUCTION, MAINTENANCE, E-STOP

Transitions:
  SETUP → PRODUCTION: guard = (setup program validated) AND (operator outside stop zone) AND (enabling device released)
  PRODUCTION → SETUP: guard = (robot at home position) AND (speed = 0)
  PRODUCTION → MAINTENANCE: guard = (robot at home position) AND (speed = 0) AND (maintenance key inserted) AND (lockout procedure confirmed)
  MAINTENANCE → PRODUCTION: guard = (maintenance key released) AND (all personnel confirmed outside cell) AND (lockout cleared)
  ANY → E-STOP: guard = (e-stop activated) OR (safety scanner trip during invalid transition)
  E-STOP → [any]: guard = (e-stop cause resolved) AND (reset performed by authorized personnel)
```

Each guard in this state machine is a **transition safety function** — a condition checked by the safety controller before permitting the transition. If any guard fails, the transition is rejected and the robot remains in its current state (or enters E-STOP if the rejection is due to a safety event).

## Transition guards as safety functions

Each guard in the state machine must be analyzed as a safety function under the frameworks from Module R3. The guard "operator outside stop zone" during the SETUP → PRODUCTION transition requires:

- A sensor or verification mechanism that confirms operator position.
- A safety-rated input to the safety controller from that sensor.
- The sensor's failure mode analysis (does a sensor failure give a false "operator outside" reading?).
- A PL/SIL target determined by the severity of the hazard if the guard falsely passes.

For a collaborative cell operating at full production speed (v_r = 0.8 m/s, payload 6 kg), the hazard if "operator outside stop zone" passes falsely while an operator is inside is a collision at production speed — a serious-to-fatal hazard. The guard safety function should be rated PLd / SIL 2.

## The two common mode-transition design errors

**Error 1 — Missing transition guards:** The risk assessment documents each mode's safety functions but has no section on transitions. The implicit assumption is that modes transition safely "because the operator follows the procedure." Procedure is a residual control; it is not a safety function.

**Error 2 — Asymmetric transition design:** The transition from a restrictive mode to a less restrictive mode has strong guards; the transition in the other direction does not. Example: entering Maintenance mode requires key switch + lockout confirmation (good), but leaving Maintenance mode requires only key switch release (no confirmation that personnel are clear). The return transition is the higher-risk direction because it reactivates the robot — and it has the weaker guard.

Both errors appear in real collaborative cell risk assessments. Auditors have learned to turn directly to the transition documentation after reviewing the per-mode sections. A risk assessment that doesn't have a mode-transition section at all is immediately flagged for revision.

## The safe-state requirement for transitions

A governing principle for all mode transitions in ISO 10218-1:2025 context: **the robot must be in a known safe state before the new mode's safety functions activate.** "Known safe state" typically means:

- Robot at a defined rest position (home, park, maintenance pose).
- Speed = 0 (confirmed by the safety controller, not just commanded).
- No active trajectories (motion queue empty).
- Active safety functions from the previous mode still engaged until the new mode's functions are confirmed active.

The last point — overlapping safety function activation — is the most commonly missed. If the SSM scanner is deactivated to switch to Maintenance mode, there must be a confirmed-active protection (the SMS interlocked gate or the robot at zero speed with drives disabled) before the scanner deactivates. The gap between "scanner deactivated" and "SMS interlock confirmed" is a protection gap. The transition safety function must close that gap.

## Documenting transitions in the risk assessment

A complete mode-transition section in a risk assessment package includes:

1. **State machine diagram** — all states, all transitions, all guards, labeled.

2. **Transition analysis table** — one row per transition with columns:
   - From state → To state
   - Guards required
   - Safety function implementing each guard (reference to SF-XX in the safety-function design section)
   - PL/SIL target for each guard
   - Safe state required before transition completes

3. **Protection continuity analysis** — confirmation that at no point during any transition are both the previous mode's and the new mode's safety functions simultaneously inactive.

4. **Authorization level for each transition** — which personnel are authorized to initiate which transitions (operator can initiate Production → Maintenance; only authorized maintenance technician can initiate Maintenance → Production; only safety supervisor can clear an E-STOP on a high-severity cell).
