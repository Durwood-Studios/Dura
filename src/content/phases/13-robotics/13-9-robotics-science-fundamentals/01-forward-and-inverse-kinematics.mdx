## Why this matters

Every robotic arm in the world — from a surgical robot threading a needle to a welding bot on an assembly line — must solve the same two math problems thousands of times per second. The first: given the current joint angles, where is my hand? The second: given where I need my hand to be, what joint angles do I set? Getting either calculation wrong produces crashes, damaged parts, or worse.

Understanding kinematics is the difference between treating a robot as a black box you poke at empirically and actually reasoning about its motion. When a path plan fails in simulation, a kinematics-literate engineer reads the error immediately; everyone else reboots and hopes.

## The puppet string analogy

Picture a marionette puppet. You control it from above with strings — each string pulls a specific joint. If you want to know where the puppet's hand is, you trace from the body down each limb, accounting for each joint's angle and each bone's length. That trace — shoulder angle, upper arm length, elbow angle, forearm length — gives you the hand's position. You went from joint angles to end-effector position.

Now invert the problem: a director says "put the hand on this mark." You have to figure out how to pull the strings. There may be several ways to do it (elbow up vs. elbow down), and some target marks may be completely unreachable.

That puppet-tracing calculation is **forward kinematics**. The string-planning calculation is **inverse kinematics**.

> **Forward kinematics (FK) is just the function `joint_angles → end_effector_pose`.
> Inverse kinematics (IK) is its inverse: `end_effector_pose → joint_angles`.**

## Forward kinematics for a 2-DOF planar arm

A two-joint planar arm lives in a plane (z = 0). It has two revolute joints with angles θ₁ and θ₂, and two links of lengths L₁ and L₂.

```python
import math

def forward_kinematics_2dof(theta1_rad: float, theta2_rad: float,
                             L1: float, L2: float) -> tuple[float, float, float]:
    """
    Compute end-effector (x, y, phi) for a 2-DOF planar arm.

    We sum angles because each joint rotates relative to the previous link —
    the elbow angle adds to the shoulder angle in world space.

    Returns: (x, y, orientation_rad)
    """
    # Shoulder joint contributes L1 in the direction of theta1
    x1 = L1 * math.cos(theta1_rad)
    y1 = L1 * math.sin(theta1_rad)

    # Elbow joint contributes L2 in the cumulative direction (theta1 + theta2)
    cumulative_angle = theta1_rad + theta2_rad
    x2 = x1 + L2 * math.cos(cumulative_angle)
    y2 = y1 + L2 * math.sin(cumulative_angle)

    # End-effector orientation equals the sum of all joint angles in a planar chain
    phi = cumulative_angle

    return (x2, y2, phi)

# Example: shoulder at 45°, elbow at -30°, arm lengths 0.5m and 0.4m
x, y, orientation = forward_kinematics_2dof(
    math.radians(45), math.radians(-30), L1=0.5, L2=0.4
)
print(f"End-effector: x={x:.3f}m  y={y:.3f}m  phi={math.degrees(orientation):.1f}°")
# End-effector: x=0.597m  y=0.182m  phi=15.0°
```

For a 6-DOF industrial arm, you extend this by chaining **homogeneous transformation matrices** — one 4×4 matrix per joint. The Denavit-Hartenberg (DH) parameterization provides a systematic way to build those matrices from four parameters per joint (a, d, α, θ).

## Inverse kinematics: same problem, harder direction

Given a target position (xₜ, yₜ), what are θ₁ and θ₂?

```python
def inverse_kinematics_2dof(x_target: float, y_target: float,
                             L1: float, L2: float) -> list[tuple[float, float]]:
    """
    Solve IK for a 2-DOF planar arm analytically.

    The cosine rule gives us theta2. But cos is even — cos(θ) == cos(-θ) —
    so two solutions always exist: elbow-up and elbow-down.

    Returns a list of (theta1, theta2) solutions in radians.
    Empty list means the target is out of reach.
    """
    # Distance to target (must be within reach envelope)
    dist_sq = x_target**2 + y_target**2
    dist = math.sqrt(dist_sq)

    # Reachability check — outside the annulus [|L1-L2|, L1+L2] is unreachable
    if dist > L1 + L2 or dist < abs(L1 - L2):
        return []  # no solution

    # cos(theta2) from the cosine rule on the triangle formed by L1, L2, and dist
    cos_theta2 = (dist_sq - L1**2 - L2**2) / (2 * L1 * L2)

    # Two geometric solutions (elbow up and elbow down)
    solutions = []
    for sign in [1, -1]:
        sin_theta2 = sign * math.sqrt(1 - cos_theta2**2)
        theta2 = math.atan2(sin_theta2, cos_theta2)

        # theta1 follows from geometry of the triangle
        k1 = L1 + L2 * cos_theta2
        k2 = L2 * sin_theta2
        theta1 = math.atan2(y_target, x_target) - math.atan2(k2, k1)

        solutions.append((theta1, theta2))

    return solutions

# Target: reach to (0.6, 0.4) with the same arm lengths
solutions = inverse_kinematics_2dof(0.6, 0.4, L1=0.5, L2=0.4)
for i, (t1, t2) in enumerate(solutions):
    print(f"Solution {i+1}: θ1={math.degrees(t1):.1f}°  θ2={math.degrees(t2):.1f}°")
```

For 6-DOF arms, analytical solutions exist only for specific geometries (like a spherical wrist). General 6-DOF arms often require numerical IK — iteratively adjusting joint angles using the **Jacobian** until the end-effector converges on the target.

## The Jacobian and singularities

The Jacobian matrix J maps joint velocities to end-effector velocities: ẋ = J · q̇

```python
def jacobian_2dof(theta1_rad: float, theta2_rad: float,
                  L1: float, L2: float) -> list[list[float]]:
    """
    Compute the 2x2 Jacobian for a planar 2-DOF arm.

    Each column answers: "if I move only joint i, how fast does
    the end-effector move in x and y?"
    """
    c1 = math.cos(theta1_rad)
    s1 = math.sin(theta1_rad)
    c12 = math.cos(theta1_rad + theta2_rad)
    s12 = math.sin(theta1_rad + theta2_rad)

    J = [
        [-(L1*s1 + L2*s12),  -L2*s12],  # dx/dtheta1, dx/dtheta2
        [ (L1*c1 + L2*c12),   L2*c12],  # dy/dtheta1, dy/dtheta2
    ]
    return J

def determinant_2x2(J: list[list[float]]) -> float:
    # det(J) == 0 means columns are linearly dependent — arm is at a singularity
    return J[0][0]*J[1][1] - J[0][1]*J[1][0]

# Singularity occurs when the arm is fully extended (theta2 == 0 or pi)
J_singular = jacobian_2dof(math.radians(30), 0.0, L1=0.5, L2=0.4)
print(f"Determinant at full extension: {determinant_2x2(J_singular):.4f}")
# Determinant at full extension: 0.0000  ← singularity
```

At a <VocabTooltip slug="singularity">singularity</VocabTooltip>, the Jacobian loses rank: moving the end-effector in some direction requires infinite joint velocities. Real controllers detect near-singular configurations using a **manipulability measure** (√det(JJᵀ)) and either stop, warn, or reroute the path.

## What you learned

- Forward kinematics chains link transformations to compute end-effector pose from joint angles — a deterministic, always-solvable calculation.
- Inverse kinematics reverses that mapping; a single target pose typically has multiple valid joint-angle solutions (elbow-up vs. elbow-down), and some poses are unreachable.
- The Jacobian matrix relates joint velocities to end-effector velocities; its determinant signals singularities where control breaks down.
- Joint space (angles) and task space (Cartesian pose) are dual representations: FK converts from joint space to task space, IK goes the other direction.
- Kinematic singularities are geometric configurations, not software bugs — they are avoided through workspace planning and manipulability monitoring.
