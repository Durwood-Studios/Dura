## Why this lesson is applied, not theoretical

Lessons R1-1 through R1-4 gave you the vocabulary and its history. This lesson applies them. The exercise: read a stylized composite data sheet (representative of real UR/FANUC CR/ABB CRB class cobots) and annotate it from an ISO 8373:2021 perspective.

The composite reflects real vendor marketing language. The gaps, folk terms, and implicit assumptions below are real gaps, folk terms, and implicit assumptions found in real data sheets.

## The composite data sheet

```
COBOTEK PRO-10
Collaborative Industrial Robot
Payload: 10 kg
Reach: 1300 mm
Repeatability: ±0.03 mm
TCP Speed: 1.5 m/s max
Weight: 33 kg
Mounting: Any angle
Degrees of Freedom: 6

SAFETY FEATURES
Collaborative by design — no safety cage required
Integrated force torque sensing at all joints
Emergency stop (Cat 0)
Safe torque off (STO) — SIL 2 / PLd
Speed and force limiting
Teach pendant with 3-position enabling switch

COLLABORATIVE FEATURES
True collaborative operation
Smooth curved surfaces — no pinch risk
Meet and assist, assembly assist, and inspection modes

CERTIFICATIONS
CE marked (Machinery Directive)
UL listed
ISO 10218-1:2025 compliant
```

## Annotating the data sheet

### What is stated correctly in ISO 8373 terms

**Payload** — stated as 10 kg. This is the ISO 8373:2021 / ISO 9283:1998 payload rating. Missing: the reach at which this is rated, and whether it's the rated payload or the nominal payload at full reach. A risk-assessment author needs to request the payload-vs-reach curve.

**Degrees of freedom: 6** — ISO 8373 term, correctly used. A 6-axis vertically articulated robot per lesson R1-2.

**Emergency stop (Cat 0)** — "Cat 0" references IEC 60204-1:2016's stop category classification. Cat 0 is immediate removal of power (uncontrolled stop). This is correctly stated. Note: this is a stop category, not a safety function. The safety FUNCTION is the emergency stop input and monitoring logic; Cat 0 describes the actuated response.

**Safe torque off (STO) — SIL 2 / PLd** — STO is an IEC 61800-5-2 safety function. SIL 2 per IEC 62061 and PLd per ISO 13849 are the reliability ratings. The claim "SIL 2 / PLd" asserts approximate equivalence — recall from Lesson R3 that this equivalence is approximate. For a risk assessment: confirm which framework was actually analyzed (and under which document the certificate was issued), and whether the claim is a re-labeling or a dual-framework analysis.

**ISO 10218-1:2025 compliant** — conformance to the current robot-safety standard. The claim is appropriate here; many older data sheets cite ISO 10218-1:2011, which does not contain the 2025 cybersecurity overlay requirements.

### What uses folk vocabulary

**"Collaborative by design — no safety cage required"** — this is folk language. ISO 8373:2021 does not define "collaborative by design" as a property. "No safety cage required" is a conditional statement (depends on the mode and application), presented as an unconditional hardware guarantee. A risk assessment cannot accept this claim at face value.

What the statement should say: "Designed to support collaborative operation per ISO 10218-1:2025 modes (SMS, HG, SSM, PFL). No physical guarding is required ONLY for applications configured and validated for a specific collaborative mode with the required safety functions. Application-level validation is the integrator's responsibility."

**"Smooth curved surfaces — no pinch risk"** — ISO 8373:2021 has no "no pinch risk" property. Pinch risk is a hazard category in ISO 12100 Annex B. The statement is a design-intent claim, not a performance specification. An end-effector with a sharp fixture, added by the integrator, can create pinch points regardless of the arm's smooth surface.

**"Meet and assist, assembly assist, and inspection modes"** — these are vendor-branded operating modes. They map to ISO 10218-1:2025 collaborative modes:

- "Meet and assist" = SMS (Safety-rated Monitored Stop) with an assist trigger
- "Assembly assist" = HG (Hand Guiding) with the enabling switch
- "Inspection modes" = either SSM or SMS depending on whether the robot moves during inspection

A risk assessment must explicitly state which ISO 10218-1:2025 mode each vendor mode corresponds to, because the safety function requirements follow from the ISO mode, not from the vendor label.

**"True collaborative operation"** — this phrase appears in vendor literature universally and means nothing in ISO 8373:2021 terms. "True" is not a standard modifier. The question is which mode(s) are configured and validated.

### What is missing for a risk assessment

Five fields a risk assessment author must verify or supplement:

1. **Payload-vs-reach curve** — stated payload (10 kg) without the reference reach. For any application at a reach other than the reference, the integrator must consult the curve.

2. **Pose accuracy (AP)** — the ±0.03 mm figure is repeatability (RP). If any trajectory is offline-programmed (not taught), pose accuracy is the relevant metric and is not stated.

3. **Annex A force/pressure thresholds** — the data sheet says "speed and force limiting" without specifying the configured limits. For a PFL application, the integrator must obtain the force/pressure configuration and validate it against ISO 10218-1:2025 Annex A body-region limits per RIA TR R15.806. A data sheet mention of "force limiting" is not a PFL validation.

4. **Functional safety documentation for each safety function beyond STO** — STO is rated at SIL 2 / PLd. What about the emergency stop chain, the speed monitoring, the enabling-switch circuit? Each safety function requires its own PL/SIL documentation. A data sheet that certifies only one function is incomplete for a full safety-function design per ISO 13849 / IEC 62061.

5. **Cybersecurity attestation per ISO 10218-1:2025** — the data sheet claims ISO 10218-1:2025 compliance. The 2025 standard includes cybersecurity requirements (secure boot, signed firmware updates, teach-pendant authentication, safety-controller network segmentation). A 10218-1:2025 conformance claim requires documentation of how these four overlay requirements are met. The data sheet is silent on this.

## The takeaway

A vendor data sheet is marketing-informed engineering documentation. It is not a risk assessment input. It becomes a risk-assessment input only after it has been read critically, supplemented with the five fields above, and aligned to the applicable standard's vocabulary.

An engineer who hands a vendor data sheet to an auditor as evidence of collaborative mode compliance will not have a productive day.
