## Why this matters

A robot appears in a simulation window while the ROS node receives no usable sensor data. Rendering a model, bridging messages and agreeing on time are separate integration steps.

## Start with something familiar

A model railway can look complete while its control panel is disconnected. Seeing the train and receiving a trustworthy position report are different observations.

## The mental model

> A simulator supplies model-based observations through configured interfaces. Verify the world/model, message bridge and clock before interpreting a successful-looking animation as an integration result.

## The mechanism

Gazebo provides simulation infrastructure; ROS integration commonly uses ros_gz packages to connect selected interfaces. A bridge maps supported message types between systems. It does not automatically make every topic, frame or timestamp compatible. Use the documented Gazebo/ROS distribution combination and record exact package versions rather than mixing a Classic tutorial with a different release family.

For a synthetic mobile robot, record the world/model revision, sensor configuration, topic names, message types, frames and time source. Simulation time can pause or run at a rate different from wall time. ROS nodes configured to use simulated time must receive the appropriate clock stream. If one component uses wall time and another uses simulation time, a transform lookup may fail even though both clocks are internally valid.

A bounded acceptance table is:

| Stage | Observation required |
| --- | --- |
| Model loaded | Expected geometry/joints and declared physics/sensor configuration |
| Bridge active | Intended topic/type direction is present and values actually arrive |
| Time aligned | Participating nodes use the declared time basis and stamps progress as expected |
| Pause/resume | Time-dependent processing handles paused and resumed simulation |
| Missing sensor | Application exposes unavailable data rather than inventing a current reading |

A GUI screenshot covers only part of the first row. The same world file can produce different behavior if plugins, physics settings or initial conditions differ, so retain those inputs with logs. No simulated collision-free trajectory establishes real-world contact limits, actuator performance or physical safety approval.

This lesson reviews an integration contract; it does not claim Gazebo was installed or run. The existing robotics lab package uses URsim for a different controller-integration purpose. Choose the simulator according to the property being investigated, and record what its model does not represent.

- Keep frame and clock identities consistent.
