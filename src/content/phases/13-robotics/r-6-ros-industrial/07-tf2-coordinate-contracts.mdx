## Why this matters

A camera reports an object one meter ahead, while the robot base is somewhere else and has moved since the image was captured. Copying the coordinates and changing the frame label produces a plausible number with the wrong meaning. The time and frame are part of the observation.

## Start with something familiar

“Two blocks east” means little until you know where the speaker started. If the speaker was on a moving bus, when they said it also matters. A robot's coordinate frame is that starting point together with axis directions.

## The mental model

> A point's coordinates, source frame and observation time travel together. A transform converts that point into a target frame using the relevant relationship at that time; renaming the frame is not a conversion.

## The mechanism

A **coordinate frame** defines an origin and axes. A **stamped observation** includes a timestamp, so a moving relationship can be evaluated at the observation's time. tf2 maintains relationships among frames over time; a **transform buffer** retains the history available to answer requests. A transform includes rotation as well as translation in general. This exercise deliberately uses aligned axes, so only translation is needed.

At time10s, camera's origin is0.4m forward of base, with the same axis directions. A camera point `(1.0, 0.2, 0.0)` converts to base coordinates `(1.4, 0.2, 0.0)`. Reverse conversion subtracts0.4 rather than adding it again. Units here are meters and seconds, and the frame relationship is a supplied teaching fixture.

This complete Python3 example checks the arithmetic without requiring ROS:

```python
def camera_to_base(point, camera_origin_in_base):
    if len(point) != 3 or len(camera_origin_in_base) != 3:
        raise ValueError("expected three coordinates")
    return tuple(a + b for a, b in zip(point, camera_origin_in_base))

point = (1.0, 0.2, 0.0)
origin_at_image_time = (0.4, 0.0, 0.0)
assert camera_to_base(point, origin_at_image_time) == (1.4, 0.2, 0.0)
assert camera_to_base((0.0, 0.0, 0.0), origin_at_image_time) == origin_at_image_time
print("translation fixture passed")
```

The function's contract assumes finite numeric values and aligned axes; it is not a general rigid-body transform implementation. If the camera rotates, use the full transform, not this addition shortcut. The earlier kinematics lesson supplies the rotation model.

For a tf2 lookup, distinguish target from source. Asking for target `base_link`, source `camera_link`, at the image timestamp requests the relation needed to express camera-frame data in base coordinates at that time. A latest-available query answers a different question and may be wrong for an older observation on a moving system. A timeout bounds how long a lookup waits for evidence; it does not make an unavailable historical transform true.

An **extrapolation** failure means the requested time is outside the usable transform history. A disconnected frame tree, missing frame or clock mismatch can also prevent a valid lookup. Define a discard, deferred-processing or diagnostic policy for these outcomes. Do not catch every exception and return an identity transform: that silently claims the two frames coincide. Coordinate conversion also does not establish collision safety, localization accuracy or authorization for physical motion.

## What you learned

- Coordinates need frame identity and observation time to be meaningful.
- Target/source direction determines how a transform is applied.
- Missing history and disconnected frames are explicit evidence failures.
- A translation fixture teaches the contract without pretending to validate a physical robot.
