## Why this matters

A planned trajectory succeeds in MoveIt, but the controller never executes it. URsim can help investigate controller integration while still leaving physical robot properties untested.

## Start with something familiar

A flight simulator can exercise cockpit procedures without proving an actual aircraft’s mechanical condition. A controller simulator likewise answers a useful but bounded set of questions.

## The mental model

> URsim supplies a simulated Universal Robots controller environment. Record the controller/driver/program state separately from planning success and from physical robot assurance.

## The mechanism

The official UR driver documentation describes starting URsim, connecting a driver and running an External Control program for the relevant workflow. The simulator version, URCap/program, network endpoint, driver configuration and controller state all belong to the reproducible setup. Use a fixed isolated simulator endpoint and never substitute a physical robot address merely to complete this lesson.

The [Dura robotics lab](/labs/robotics) includes a ROS2 launch package, plan-only client, explicit simulator execution step and a detailed evidence template. Its local trajectory tests were run; its ROS/URsim integration has not been executed in the authoring environment. Follow the package’s version recording and acceptance instructions before claiming your own end-to-end run.

A useful evidence chain is:

| Stage | Evidence |
| --- | --- |
| Simulator available | Recorded image/version, isolated endpoint and responsive controller environment |
| Driver connected | Actual connection/status and required controller activation |
| External Control ready | Program/URCap configuration and running state required by the selected workflow |
| Plan valid for the model | Correct group/joints/state and inspected planned trajectory |
| Execution outcome | Controller action acceptance and final result, distinguished from plan success |

When execution times out, requesting cancellation does not prove a stopped system. Retain acknowledgement and final state evidence; avoid automatic motion retries after an uncertain outcome. A driver reconnect also does not prove the prior command’s final status.

URsim integration does not establish physical contact forces, stopping distance, payload handling, gripper success or application safety. The teaching lab uses joint transfers, not a verified physical pick-and-place. A professional handoff should explicitly list these exclusions and identify what separate physical assessment would be required by the responsible team.
