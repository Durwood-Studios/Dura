## Why test execution needs its own lesson

Designing the test matrix (Lesson 2) and specifying the FPMD (Lesson 3) are intellectual tasks. Executing the test campaign is an operational task with its own failure modes. The failure modes are not about the physics — they're about process discipline under time pressure, in a live cell with production schedule urgency.

The three most common execution failures that invalidate test campaigns:

1. **Fixture drift.** The FPMD is clamped to a stand. Between runs, someone bumps the stand and the height changes 15 mm. The remaining runs measure a different scenario than the matrix entry specifies. No one notices.

2. **Trajectory variation.** The robot's actual trajectory deviates from the programmed trajectory due to a configuration change, a payload difference, or a mode switch. The measurements don't bound the production trajectory.

3. **Labeling errors.** Measurement 18 is recorded in row 19 of the spreadsheet. The margin calculation for row 18 uses wrong data. The report looks consistent internally.

None of these are catastrophic if caught. All three are invisible if test execution is informal.

## Step 0: Pre-campaign setup

Before touching the robot:

### Freeze the application configuration

The robot program, payload, end-effector, and cell layout must match the production configuration exactly. Lock the configuration:

- Take a photograph of the cell layout with a measuring tape visible.
- Record the robot program checksum or version number.
- Weigh the end-effector with payload.
- Record the robot controller settings (speed override, force limits, collaborative mode parameters).

Any change during the campaign invalidates measurements taken before the change. If a change is necessary, document it and note which measurements must be repeated.

### FPMD baseline verification

Before the first run, verify the FPMD against its calibration certificate:

- Apply a known static load (a calibration weight). The FPMD should read within ± uncertainty.
- Record the baseline verification result.
- Repeat after the campaign's last run.

If the post-campaign verification fails, the campaign data is suspect and may require re-test.

## Step 1: Fixture design and positioning

The FPMD must be positioned at the body-region location specified in the test matrix. This requires a mechanical fixture.

**Fixture requirements:**

- Rigid enough that robot contact doesn't shift the fixture (a lightweight stand bends; use clamped steel fixtures).
- Adjustable in height and angle to position the FPMD at arbitrary body-region locations.
- Position-repeatable within ±5 mm between runs to ensure the same contact geometry.

**Height reference table (approximate, for adult 50th percentile):**

| Body region     | Approximate height from floor | Notes                                                     |
| --------------- | ----------------------------- | --------------------------------------------------------- |
| Top of skull    | 1700 mm                       | Standing operator                                         |
| Forehead        | 1620 mm                       | Standing operator                                         |
| Chest / sternum | 1300 mm                       | Standing operator                                         |
| Abdomen         | 1100 mm                       | Standing operator                                         |
| Hand / finger   | Variable                      | Depends on task posture; measure from task fixture height |
| Knee            | 480 mm                        | Standing operator                                         |

These are reference values for standing 50th-percentile operators. If the application has operators seated, crouching, or in non-standard postures, measure the actual posture during the lifecycle walkthrough and set the fixture accordingly.

**Documentation per fixture position:** photograph the fixture in position with a measuring tape from floor to FPMD center. File with the test record under the test matrix entry ID.

## Step 2: Trajectory programming

For each test matrix entry, verify that the robot trajectory used for testing bounds the production trajectory. "Bounds" means:

- **Speed**: the test speed equals or exceeds the production speed at the contact point.
- **Approach angle**: the test approach angle represents the contact angle that produces the highest contact force/pressure for this scenario.
- **Payload**: the test payload equals or exceeds the production payload (higher payload → higher effective mass → higher peak contact force).

Test at the production trajectory where possible. If the production trajectory is known to vary (e.g., depends on part location from a vision system), test at the worst-case bounds.

**Repeatability check:** run the approach trajectory three times before data-taking. Verify that the robot returns to the same pre-contact position each time (within the robot's pose repeatability spec). If trajectory repeat errors are significant, identify the source before data collection.

## Step 3: Data acquisition settings

The data acquisition system (usually the FPMD's built-in logger or an external DAQ) must be set to:

- **Sample rate**: minimum 1 kHz for forces above 100 N contact velocity. For higher-velocity contacts (> 500 mm/s), 2–5 kHz is appropriate.
- **Time window**: capture from 200 ms before expected contact to 500 ms after.
- **Trigger**: the FPMD force signal crossing a pre-trigger threshold (e.g., 2 N) to auto-trigger capture.
- **Storage format**: raw numerical data (not graph images — auditors need the numbers).

## Step 4: Measurement execution per test matrix entry

For each row in the test matrix:

1. **Record entry ID** and the Annex A body region / contact type from the matrix.
2. **Position fixture** per the documented fixture position for this entry. Photograph. Verify height with measuring tape.
3. **Arm the DAQ** — start the acquisition trigger.
4. **Execute robot trajectory** — run the trajectory from the home position through the contact point and return.
5. **Capture data** — the DAQ auto-triggers on contact. Verify trigger fired and data was captured.
6. **Extract peak force and peak pressure** from the captured time series. The peak force is the maximum force reading in the contact event. Peak pressure = peak force / measured contact area.
7. **Compare to threshold** — look up the Annex A threshold for this body region and contact type.
8. **Record result** in the measurement log.
9. **Repeat** for a total of three runs. If all three pass, the entry is complete. If any run fails, the entry fails.

**Real-time documentation per run:**

| Field                      | Value                  |
| -------------------------- | ---------------------- |
| Matrix entry ID            | e.g., M-07             |
| Body region                | e.g., Hand, dorsal     |
| Contact type               | e.g., Transient        |
| Run number                 | e.g., 1 of 3           |
| FPMD height from floor     | e.g., 920 mm           |
| Approach speed at contact  | e.g., 450 mm/s         |
| Payload                    | e.g., 2.7 kg           |
| Peak force (N)             | e.g., 78 N             |
| Contact area (cm²)         | e.g., 0.85 cm²         |
| Peak pressure (N/cm²)      | e.g., 91.8 N/cm²       |
| Force threshold (N)        | e.g., 160 N            |
| Pressure threshold (N/cm²) | e.g., 310 N/cm²        |
| Force margin               | e.g., +82 N (51%)      |
| Pressure margin            | e.g., +218 N/cm² (70%) |
| Pass / Fail                | e.g., Pass             |

## Step 5: Worst-case bounding

Not every permutation of speed × payload × trajectory needs a separate measurement. Use worst-case bounding to identify the minimum set of measurements that covers the full production envelope:

- **Highest speed** produces the highest peak force for transient contact — test at production maximum.
- **Largest payload** increases the effective mass at the end-effector — test at the maximum payload in the production envelope.
- **Worst-approach angle** — the angle that produces maximum force for a given trajectory; typically the perpendicular approach. Test the worst approach if the trajectory is not constrained.

If measurements at worst-case conditions pass with margin ≥ 10%, that bounds the sub-worst-case conditions by construction. Document the bounding argument explicitly: "Measurement M-07 at 450 mm/s and 2.7 kg bounds all production conditions at speeds ≤ 450 mm/s and payloads ≤ 2.7 kg per the effective-mass force-scaling relationship."

## Step 6: Post-campaign FPMD verification

After the last measurement run:

- Repeat the calibration weight verification from Step 0.
- If the reading is within ± uncertainty, the campaign data is considered valid.
- If the reading has drifted beyond uncertainty, the source of drift must be investigated. Measurements taken after the last known-good verification point may need to be repeated.
