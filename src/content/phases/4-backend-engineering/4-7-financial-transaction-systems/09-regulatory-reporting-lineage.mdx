## Why this matters

A report contains a plausible total, but nobody can reconstruct which records, rules or adjustments produced it. Reporting systems need reproducible lineage and controlled submission evidence, not just a spreadsheet that looks right.

## Start with something familiar

A laboratory result is useful when another reviewer can trace the sample and calculation. A regulatory figure similarly needs its source population, definition, transformation and approval record.

## The mental model

> A reporting pipeline binds a versioned obligation and reporting period to reconciled source data, transformations, review and submission acknowledgement. Schema acceptance is not proof that the reported business meaning is correct.

## The mechanism

Actual reporting obligations depend on jurisdiction, entity type, product and current rules. The Bank of England’s reporting guidance illustrates that the applicable returns and submission requirements are specific; this exercise does not create a universal filing template or deadline.

The fictional internal training rule includes settled transactions effective during period P and excludes pending transactions. Records are S1 settled 1000, S2 settled 500 and P1 pending 700, all in the same declared currency/minor units. The report total is 1500, with two included records and one excluded pending record. If S2 is corrected to 400 before final approval, regenerate the report as1400 and retain the superseded version and reason.

Record rule/version, period boundary and timezone, source snapshot, inclusion/exclusion logic, transformation revision, adjustments, reviewer and output identity. Reconcile included totals to the ledger and explain exclusions. A manual adjustment needs authorization and traceability; it must not silently replace the source record to make totals match.

Submission states should distinguish prepared, validated, approved, transmitted, accepted and rejected under the recipient protocol. A transport success or schema acceptance does not establish substantive correctness. If a correction is needed after submission, follow the actual amendment/resubmission process while preserving the original submission and acknowledgement.

Test boundary timestamps, duplicate records, missing currency, unsettled states and changed definitions. Keep confidential source data under controlled access and retain evidence according to the applicable policy. The supplied numbers are a teaching reconciliation, not a real regulatory return or legal interpretation.

### Automate the declared control, not the legal interpretation

The following local control implements only the fictional settled-only rule. It rejects duplicate IDs, mixed currencies and invalid amounts before producing a versioned total. Save the source snapshot and this rule identity with the result; an automated pass does not establish that the rule is legally applicable.

```python
def training_report(rows, currency):
    seen = set()
    included = []
    for row in rows:
        if row["id"] in seen or row["currency"] != currency:
            raise ValueError("duplicate or currency mismatch")
        seen.add(row["id"])
        if type(row["amount_minor"]) is not int or row["amount_minor"] < 0:
            raise ValueError("invalid amount")
        if row["status"] not in ("settled", "pending"):
            raise ValueError("unsupported state")
        if row["status"] == "settled":
            included.append(row)
    return {"rule": "training-settled-v1", "currency": currency,
            "ids": [row["id"] for row in included],
            "total_minor": sum(row["amount_minor"] for row in included)}

rows = [{"id": "S1", "currency": "USD", "amount_minor": 1000, "status": "settled"},
        {"id": "S2", "currency": "USD", "amount_minor": 500, "status": "settled"},
        {"id": "P1", "currency": "USD", "amount_minor": 700, "status": "pending"}]
assert training_report(rows, "USD")["total_minor"] == 1500
assert training_report(rows, "USD")["ids"] == ["S1", "S2"]
rows[1]["amount_minor"] = 400
assert training_report(rows, "USD")["total_minor"] == 1400
for invalid in [rows + [rows[0]], [dict(rows[0], currency="EUR")]]:
    try:
        training_report(invalid, "USD")
        raise AssertionError("invalid population accepted")
    except ValueError:
        pass
print("reporting control checks passed")
```

RegTech automation can make approved controls repeatable and exceptions visible. Ownership of the obligation, approved definitions, effective dates, change review and human sign-off remain necessary. This control does not select the population by timestamp: the fixture supplies it. A real pipeline must test period boundaries and capture that selection evidence too.
