## Why this matters

A payment retry changes a balance twice, and a correction overwrites the old record. A ledger should make the accounting effect and its history inspectable, not merely store the latest number.

## Start with something familiar

Moving water between two marked containers changes both sides of the record. Accounting entries likewise describe corresponding effects, although real account types determine how debits and credits affect balances.

## The mental model

> Each journal entry has equal total debits and credits in a declared currency. Balance is a necessary structural check, not proof that the right accounts, amount or business event were recorded.

## The mechanism

For a simplified business receiving1000 minor currency units from a customer for a service, debit cash1000 and credit revenue1000. Debit does not universally mean increase and credit does not universally mean decrease; their effect depends on account type. Use a documented chart of accounts and explicit currency/minor-unit rules.

This fixture validates journal structure and stores an immutable tuple per event ID. It uses synthetic data and no payment network.

```python
journal = {}

def post(event_id, lines):
    entry = tuple(lines)
    if event_id in journal:
        if journal[event_id] != entry:
            raise ValueError("event ID reused with different content")
        return
    if not entry or any(type(amount) is not int or amount <= 0 or side not in ("debit", "credit") for account, side, amount in entry):
        raise ValueError("invalid line")
    debits = sum(amount for account, side, amount in entry if side == "debit")
    credits = sum(amount for account, side, amount in entry if side == "credit")
    if debits != credits:
        raise ValueError("unbalanced entry")
    journal[event_id] = entry

sale = [("cash", "debit", 1000), ("revenue", "credit", 1000)]
post("sale-1", sale)
post("sale-1", sale)
assert len(journal) == 1
post("reverse-sale-1", [("cash", "credit", 1000), ("revenue", "debit", 1000)])
assert len(journal) == 2
for event_id, bad in [("bad", [("cash", "debit", 1000), ("revenue", "credit", 900)]), ("sale-1", [("cash", "debit", 2000), ("revenue", "credit", 2000)])]:
    try:
        post(event_id, bad)
    except ValueError:
        pass
    else:
        raise AssertionError("invalid posting accepted")
assert len(journal) == 2
print("ledger checks passed")
```

A reversal is a new linked event, not deletion of the original. Preserve source event, effective time, posting time, reason and reviewer according to the system’s accounting controls. A production implementation needs atomic durable posting, account/currency validation, concurrency control and authorization; the in-memory fixture establishes none of those deployment properties.

Reconcile ledger entries to external statements and business records. An entry can balance while posting to the wrong revenue account or duplicating a transaction under a new ID. Trial-balance equality therefore does not replace reconciliation, review or an accounting policy.
