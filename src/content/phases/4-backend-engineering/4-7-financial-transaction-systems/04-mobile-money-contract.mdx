## Why this matters

A mobile-money request times out after the provider accepts it. Retrying without the original reference can create uncertainty or duplicate business effects. An integration needs a correlation and reconciliation contract.

## Start with something familiar

A customer keeps a receipt number when asking whether a delayed order was fulfilled. A stable transaction reference serves the same purpose across asynchronous API calls and callbacks.

## The mental model

> Pin the provider’s adopted API version and correlate request, callback and status retrieval. A standards-shaped message is not proof that every provider supports the same operation or state behavior.

## The mechanism

The GSMA Mobile Money API defines common objects and request/response flows. Providers adopt particular versions and capabilities, so verify their authentication, account-identifier formats, supported transaction types, callback rules and reversal semantics. Do not assume an endpoint exists merely because another provider implements it.

The fictional adapter submits a1000-minor-unit transfer with client referenceC7. It receives an accepted correlationR7, then the connection fails before the client records the result. A later callback referencesR7. The application must correlate the callback to the original request and reconcile status using the provider’s documented mechanism; it must not invent a second transaction just to obtain a clearer response.

Record currency and amount representation exactly. Some APIs express decimal strings rather than integer minor units; the adapter must convert using a declared currency exponent and reject excess precision instead of rounding silently. For this exercise, the currency has two decimal places:1000 minor units correspond to the string10.00. This is not true for every currency.

Authenticate callbacks and validate that account, environment and transaction references match the intended operation. Redact phone numbers or other account identifiers from routine logs. A reversal request is a separate authorized operation with its own reference and result; requesting one is not proof it completed.

Before deployment, run the provider’s sandbox scenarios for timeout-after-acceptance, duplicate callback, invalid account, insufficient funds and reversal uncertainty. This lesson supplies an adapter evidence table, not a live provider connection. The GSMA specification informs the questions, while the actual provider contract governs supported behavior.
