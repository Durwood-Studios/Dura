## Why this matters

A directory contains thousands of data files, but readers cannot tell which belong to a complete snapshot or what a changed column means. Cheap object storage does not automatically create a trustworthy analytical table.

## Start with something familiar

A warehouse full of unlabeled boxes is not an inventory system. Storage becomes usable when contents, versions, ownership and accepted changes are documented and enforced.

## The mental model

> A data lake needs schema, catalog, snapshot/transaction and lifecycle contracts on top of storage. Separate raw ingestion from curated publication and make incomplete or incompatible data observable.

## The mechanism

Raw data preserves a source representation under controlled access. Curated data applies validated schema, quality and business definitions. These are logical stages, not guarantees conferred by folder names such as bronze or gold. A catalog helps discovery and metadata, but it does not alone enforce every reader/writer constraint.

The synthetic ingest publishes files F1 andF2 as snapshot S1 only after both are written and a manifest references their checksums and schema V1. A reader should use that committed manifest, not list the directory during upload and assume every visible file is a complete table. A failed F2 upload must not silently publish a partial S1.

Table formats such as Delta Lake provide transaction-log and schema features under their documented protocols. Those mechanisms differ from plain object-file listing and have version/engine compatibility requirements. This lesson does not install or validate a particular table-format runtime.

A schema change from amount_minor integer to amount_decimal string changes meaning and downstream handling. Do not enable automatic schema merging as a substitute for review. Version the contract, validate producers/consumers and decide how historical snapshots remain interpretable. Partitioning can improve selected reads but excessive tiny files or unsuitable keys can create operational costs.

Access, retention, lineage and deletion must cover raw copies, curated tables and exported artifacts. Reconcile row counts and rejected records before publication. A successful object upload is storage evidence, not proof of a correct, complete or governed dataset.
