## Why this matters

A compiled artifact is unfamiliar, and an analyst guesses its purpose from one constant. Reverse engineering becomes reliable when observations lead to testable hypotheses rather than confident stories.

## Start with something familiar

A mechanic can infer how a sealed device works from inputs, outputs and internal parts, then test the explanation against another input. The explanation should change when the evidence disagrees.

## The mental model

> Inspect the permitted artifact, record its environment and derive a behavioral hypothesis. Confirm it with independent inputs and distinguish implementation observations from claims about the whole program.

## The mechanism

The authorized artifact here is a tiny function authored for this lesson. CPython’s dis module exposes bytecode instructions, but bytecode is an implementation detail that changes across interpreter versions. Record the interpreter version and do not make tests depend on exact opcode names or offsets.

```python
import dis
import sys

def sample(value):
    if value < 0:
        return 0
    return value * 2 + 1

print(sys.version)
dis.dis(sample)
observed = {value: sample(value) for value in [-2, -1, 0, 1, 4]}
assert observed == {-2: 0, -1: 0, 0: 1, 1: 3, 4: 9}
print("behavior checks passed")
```

Before looking at the source, use a separately supplied output table or disassembly to propose a rule: negative inputs map to 0; nonnegative inputs map to 2x+1. Test a boundary and an input not used to form the hypothesis. A constant2 in a binary alone would not establish that rule; control flow and data flow matter.

Static inspection examines representation without executing the artifact. Dynamic observation runs selected inputs in a controlled environment. Unknown artifacts may have side effects, so do not execute an arbitrary downloaded program merely to see what happens. This exercise executes only the supplied source function with no file or network operations.

Document artifact identity, interpreter/build environment, observations, inferred behavior and untested domains. This function’s behavior on integers does not establish behavior for every Python object. Reverse engineering can support compatibility, debugging and authorized security analysis; licensing and authorization boundaries still apply to real artifacts.
