## Why this matters

A scanner reports an access-control issue, but the finding lacks a controlled demonstration of which identity can read which resource. A useful security test establishes scope, a reproducible boundary violation and a verified mitigation.

## Start with something familiar

A building inspector checks a particular locked door with permission and records which key opened it. Trying every door in unrelated buildings is a different activity. A scoped penetration test likewise needs authority, boundaries and evidence.

## The mental model

> Authorization is permission to perform a specific action on a specific resource. In a scoped test, demonstrate the smallest relevant violation, then verify that the fix blocks it while preserving legitimate access.

## The mechanism

The permitted target for this lesson is the following in-process Python fixture, with synthetic users and documents. There is no network target, credential discovery or real personal data. The test question is whether caller alice can retrieve bob’s document merely by changing its identifier.

```python
DOCUMENTS = {"a1": {"owner": "alice", "text": "A"}, "b1": {"owner": "bob", "text": "B"}}

def vulnerable_get(caller, document_id):
    return DOCUMENTS.get(document_id)

def protected_get(caller, document_id):
    document = DOCUMENTS.get(document_id)
    if caller is None or document is None or document["owner"] != caller:
        return None
    return document

assert vulnerable_get("alice", "b1")["text"] == "B"
assert protected_get("alice", "b1") is None
assert protected_get("alice", "a1")["text"] == "A"
assert protected_get(None, "a1") is None
assert protected_get("alice", "missing") is None
print("authorization fixture passed")
```

The vulnerable function ignores caller identity. The protected function enforces ownership on every resource lookup. In a real service, caller identity must come from verified authentication, not a user-controlled owner field or an arbitrary request parameter. Returning None is a fixture convention; a real API needs deliberate status/error semantics and protection against unintended information disclosure.

A finding records scope, prerequisite identity, exact input, expected denial, observed disclosure and impact. Preserve only the minimum synthetic evidence needed. Severity depends on actual exposure and data sensitivity; do not assign a dramatic rating solely because a pattern has a familiar name.

Retest negative and positive cases after the change. A fix that denies everyone prevents the observed leak but breaks the legitimate contract. Broader penetration testing includes additional surfaces and methods; this one boundary exercise is introductory practice, not a complete engagement or permission to test public services. Real engagements require their own authorization, rules, timing, data handling and stop conditions.
