## Why this matters

A tester reports that a form is broken, but nobody knows which input, browser state or expected behavior produced the observation. Manual exploration is valuable when it discovers risks and leaves evidence another person can reproduce.

## Start with something familiar

A mechanic records the conditions under which a noise appears rather than merely saying the car sounds wrong. A test charter similarly focuses exploration while leaving room to follow unexpected behavior.

## The mental model

> A charter defines a risk, scope and timebox. A finding separates expected behavior, observed behavior and reproducible conditions. Passing explored cases does not prove that unvisited states work.

## The mechanism

Use this fictional local task editor: the requirement says a saved task survives reload, empty titles are rejected, and keyboard users can create and remove tasks. The fixture has a Save button that accepts whitespace, a delete control reachable only by pointer and a simulated failed-storage condition that still displays Saved. These are supplied observations, not claims about Dura’s current UI.

Write a30-minute charter: explore task durability and input boundaries in the local fixture, using normal, empty and whitespace titles; keyboard-only navigation; reload; and failed storage. State the environment, build revision and initial storage state. Keep a brief session log of attempted cases, observations, questions and blocked areas.

For a useful defect report, include the smallest reproduction sequence, expected and actual results, relevant sanitized evidence and impact. “Saved label appears after simulated storage failure; reload loses task” is more actionable than “persistence unreliable.” Do not put private learner data into screenshots or logs when a synthetic title reproduces the problem.

Distinguish an observation from a cause: the disappearing task is observed; the exact failed persistence call requires further investigation. Prioritize by impact and exposure rather than by how interesting the bug seems. Some findings should become automated regressions once the behavior is clear; automation then protects the discovered contract rather than replacing exploratory judgment.

Security testing also requires an explicit authorized scope. This charter does not authorize probing arbitrary websites or real user records. Use the supplied local scenario for boundary reasoning. More advanced penetration testing requires a dedicated target, rules of engagement and evidence-handling procedure; this introduction does not claim that capability.
