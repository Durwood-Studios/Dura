## Why this matters

You'll see numbers like "256 GB" and "8 MB" everywhere — phone storage, video files, RAM. The relationships between them aren't arbitrary. They come from a simple fact: computers count in twos, not tens.

Once you see the pattern, file sizes stop being magic numbers and start being predictable.

## Start with something familiar

Imagine counting eggs in cartons of ten or cartons of twelve. The number of cartons changes even when the eggs do not.

## The mental model

> A unit tells you how many bytes one labeled quantity represents; the unit changes the number, not the underlying capacity.

## Decimal and binary units

A kilobyte (kB) is 1000 bytes. A kibibyte (KiB) is 1024 bytes, or two multiplied by itself ten times. A mebibyte (MiB) is 1024 KiB: 1,048,576 bytes. File sizes can be any number of bytes; they do not have to be powers of two.

| Decimal unit | Bytes | Binary unit | Bytes |
| --- | --- | --- | --- |
| kB | 1000 | KiB | 1024 |
| MB | 1,000,000 | MiB | 1,048,576 |
| GB | 1,000,000,000 | GiB | 1,073,741,824 |

For example, 2 KiB contains 2 × 1024 = 2048 bytes. The same quantity in bytes has not changed when you give it a different unit.

## Why capacity labels differ

A decimal 1 TB drive contains 1,000,000,000,000 bytes before filesystem overhead. Dividing by 1,073,741,824 gives about 931 GiB. Some software uses binary units while labeling them GB; other software uses decimal units. Neither number alone means the drive lost that amount of data. Check the unit and allow for filesystem overhead before comparing capacities.
