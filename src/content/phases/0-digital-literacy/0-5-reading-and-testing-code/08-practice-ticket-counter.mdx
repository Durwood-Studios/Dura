## Why this matters

You can now read values, decisions, loops, and functions. This review combines those ideas around one requirement so you can check your reasoning without installing tools or connecting to a service.

## Start with something familiar

Imagine checking a printed admission policy against what the door attendant actually says. Your job is to compare the rule and the behavior, not guess the author’s intent. Reviewing code follows the same pattern.

## The mental model

> Trace inputs through the code, compare results with the requirement, and preserve the smallest mismatch as a regression example: a case to rerun after the repair.

## The mechanism

The requirement is: three or more tickets returns Enter; fewer returns Wait. A returned value ends that function call, so a later return in the same function is not reached. The code below uses `>` for strictly greater than, which excludes equality. The loop supplies counts 2, 3, and 4.

```javascript
function admission(ticketCount) {
  if (ticketCount > 3) {
    return "Enter";
  }
  return "Wait";
}
for (let count = 2; count <= 4; count = count + 1) {
  console.log(admission(count));
}
```

Expected outputs are Wait, Enter, Enter. Actual outputs are Wait, Wait, Enter. The mismatch at 3 isolates the boundary error. Replacing > with >= includes equality and satisfies all three examples. These examples are evidence for this rule; they are not a proof about every possible input.

## Guided practice

Before the final check, write a four-field report for the input 3. Then predict the repaired function’s result for 0 tickets.
