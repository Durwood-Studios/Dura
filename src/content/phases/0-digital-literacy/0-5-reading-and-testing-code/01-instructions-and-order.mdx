## Why this matters

When a program produces the wrong answer, changing random lines hides the cause. Following one instruction at a time lets you explain the result before you touch the code.

## Start with something familiar

Imagine a recipe that says to pour water into a cup and then add tea. Reversing the steps changes what happens. A program is also a sequence of instructions, and their order matters.

## The mental model

> A trace is a record of each instruction and the visible result it produces. Read from top to bottom unless an instruction explicitly changes that order.

## The mechanism

JavaScript is the language used in the examples. `console.log(...)` displays the value inside the parentheses; it does not ask the user a question. Quotation marks mark text. A semicolon ends an instruction. The numbers at the left in a written trace are your notes, not code to type.

```javascript
console.log("Fill cup");
console.log("Add tea");
console.log("Serve");
```

The output is Fill cup, then Add tea, then Serve, on separate lines. Nothing in this program measures a real cup: these instructions display text only.

## Guided practice

Predict the output if the last two instructions exchange places. Write all three lines before revealing the answer.

You can complete this exercise on paper or in your head, including offline. Predict first; then open the answer.

<details>
  <summary>Reveal the practice answer</summary>

Fill cup, Serve, Add tea. Execution follows the written order; it does not repair a recipe that makes no sense.

</details>
