## Why this matters

A program finishing without an error does not prove it did the right job. You need a requirement to decide what the answer should be before looking at what the program produced.

## Start with something familiar

Imagine ordering two sandwiches and receiving three. The bag arrived successfully, but it does not match the order. A test compares what should happen with what did happen.

## The mental model

> Expected results come from the requirement. Actual results come from running or tracing the program. A mismatch is evidence to investigate.

## The mechanism

The requirement is: delivery adds two credits to itemCost. Read the function below as an implementation to inspect, not as the definition of correct behavior. For an input of 5, the expected total is 7. Trace the instructions independently to find the actual result.

```javascript
function addDelivery(itemCost) {
  return itemCost + 3;
}
console.log(addDelivery(5));
```

The actual result is 8. The expected result is 7. The extra credit is a mismatch caused by the added constant. Changing the expected answer to 8 would hide the defect rather than satisfy the requirement.

## Guided practice

For an input of 0, record the expected and actual totals separately. Is an empty purchase a useful test of this stated requirement?

You can complete this exercise on paper or in your head, including offline. Predict first; then open the answer.

<details>
  <summary>Reveal the practice answer</summary>

Expected is 2 and actual is 3. Zero is a useful test because the stated rule still adds two. A different business rule for empty purchases would need to be specified explicitly.

</details>
