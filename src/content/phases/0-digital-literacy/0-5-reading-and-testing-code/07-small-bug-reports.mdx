## Why this matters

A report saying “it is broken” leaves the next person guessing. A small, precise example lets another learner reproduce the problem and verify a repair.

## Start with something familiar

Imagine giving directions to a misplaced book: the room, shelf, and title are useful; “somewhere in the building” is not. A reproducible bug report narrows the search in the same way.

## The mental model

> A useful report records the setup, exact steps or input, expected result, and actual result. Hypotheses are labeled separately from observations.

## The mechanism

Use four fields: Setup describes where the issue happened; Steps give the smallest repeatable sequence; Expected cites the requirement; Actual records the observation. A hypothesis is a possible explanation that still needs testing. Do not include passwords, access keys, or someone else’s personal data in examples.

```javascript
function addDelivery(itemCost) {
  return itemCost + 3;
}
console.log(addDelivery(5));
```

A useful report says: Setup: this standalone JavaScript example. Steps: call addDelivery with 5. Expected: 7, because delivery adds 2. Actual: 8. Hypothesis: the added constant is wrong. The hypothesis is supported by inspection, but the actual observation remains the displayed 8.

## Guided practice
