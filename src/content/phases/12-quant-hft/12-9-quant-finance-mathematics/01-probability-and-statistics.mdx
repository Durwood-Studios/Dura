## Why this matters

Every trading decision is a bet under uncertainty. Before you write a single line of strategy code, the question you have to answer is: _am I seeing a real pattern or noise?_ Probability and statistics are the formal language for answering that question. Quant teams at every major firm — Citadel, Two Sigma, Renaissance — live in these tools every day, not because it is academic, but because bad statistics means bad trades and real money loss.

Beyond individual trades, statistics shape how you evaluate an entire strategy. A backtest that looks profitable might be fooling you. The difference between a genuine edge and a lucky run of random outcomes is measurable — but only if you know what to measure. The concepts in this lesson form the evaluation layer under every signal, model, and portfolio decision you will ever make.

## You already know this intuitively

Imagine you flip a coin 100 times and get 55 heads. Is the coin biased? Your gut says "probably not — that could happen by chance." But what if you got 80 heads? Now you start to doubt. The statistical machinery in this lesson formalizes that gut intuition: it tells you exactly _how surprised you should be_ by a given outcome, given your assumptions about the world.

Trading signals work the same way. If a strategy beats the market 55% of the time on 100 trades, you should ask the same question you asked about the coin. Statistics gives you the tool to answer it rigorously.

> **Mental model: probability is just counting outcomes, formalized.**
> _A probability distribution is a complete description of all possible outcomes and how likely each one is._

## Distributions: the shape of uncertainty

### The normal distribution

The <VocabTooltip slug="normal-distribution">normal distribution</VocabTooltip> (the "bell curve") describes variables where many small independent forces add up. It is defined by two numbers: the mean μ (center) and standard deviation σ (spread).

```python
import numpy as np
import statistics

# Simulate daily returns for a hypothetical strategy
# In practice this comes from your backtest engine
np.random.seed(42)
daily_returns = np.random.normal(loc=0.0008, scale=0.012, size=252)

mean_return = np.mean(daily_returns)
std_return  = np.std(daily_returns)

# Annualize: sqrt(252) is the standard trading-days factor
# We scale by time because variance grows linearly, so std grows as sqrt
annualized_mean = mean_return * 252
annualized_std  = std_return * np.sqrt(252)

print(f"Daily mean:  {mean_return:.4f}")
print(f"Daily std:   {std_return:.4f}")
print(f"Ann. return: {annualized_mean:.2%}")
print(f"Ann. vol:    {annualized_std:.2%}")
```

### The log-normal distribution

Stock _prices_ cannot go negative, but stock _returns_ (percentage changes) can. The <VocabTooltip slug="log-normal-distribution">log-normal distribution</VocabTooltip> captures this: if the logarithm of a variable is normally distributed, the variable itself is log-normal.

```python
# Returns (percentage changes) follow an approximately normal distribution
# Prices follow an approximately log-normal distribution
# This is why we almost always work in log-returns, not raw prices

price_t0 = 100.0
daily_log_returns = np.random.normal(loc=0.0005, scale=0.015, size=252)

# Reconstruct the price path via cumulative sum of log-returns
# exp(sum of log-returns) = product of (1+r) for each day
price_path = price_t0 * np.exp(np.cumsum(daily_log_returns))

print(f"Start price: {price_t0:.2f}")
print(f"End price:   {price_path[-1]:.2f}")
print(f"Min price along path: {price_path.min():.2f}")  # always > 0
```

### Fat tails: why standard deviation lies

Financial returns have <VocabTooltip slug="fat-tails">fat tails</VocabTooltip> — extreme events happen far more often than a normal distribution predicts. The <VocabTooltip slug="kurtosis">kurtosis</VocabTooltip> of a distribution measures this. Normal distributions have kurtosis = 3; real return distributions often have kurtosis of 5–10.

```python
from scipy import stats

# Real S&P 500 daily returns have kurtosis >> 3
# This simulates a fat-tailed distribution using Student's t
fat_tailed_returns = stats.t.rvs(df=4, loc=0.0005, scale=0.012, size=252)

kurt = stats.kurtosis(fat_tailed_returns, fisher=False)  # Fisher=False gives raw kurtosis
skew = stats.skew(fat_tailed_returns)

print(f"Kurtosis: {kurt:.2f}  (normal = 3.0)")
print(f"Skewness: {skew:.2f}  (normal = 0.0)")

# Implication: a 5-sigma move happens ~1 in 1.7M days under normal assumptions
# but much more frequently under fat-tailed reality
days_in_5sigma_normal = 1 / stats.norm.sf(5)  # sf = survival function = P(X > x)
days_in_5sigma_t4     = 1 / stats.t.sf(5, df=4)
print(f"5-sigma event frequency (normal): 1 in {days_in_5sigma_normal:,.0f} days")
print(f"5-sigma event frequency (t-dist): 1 in {days_in_5sigma_t4:,.0f} days")
```

## The Sharpe ratio: signal quality in one number

The <VocabTooltip slug="sharpe-ratio">Sharpe ratio</VocabTooltip> measures return per unit of risk. It is the single most common summary statistic for evaluating a strategy.

```python
def sharpe_ratio(returns: np.ndarray, risk_free_rate: float = 0.0) -> float:
    """
    Annualized Sharpe ratio from daily returns.

    We subtract the risk-free rate because we only get credit for returns
    *above* what a T-bill would give us — that is the true reward for taking risk.
    """
    excess = returns - risk_free_rate / 252  # daily risk-free
    if excess.std() == 0:
        return 0.0
    # Multiply by sqrt(252) to annualize a daily Sharpe
    return (excess.mean() / excess.std()) * np.sqrt(252)

sr = sharpe_ratio(daily_returns)
print(f"Sharpe ratio: {sr:.2f}")
# Rule of thumb: >1 is decent, >2 is excellent, >3 is exceptional (and rare)
```

## Hypothesis testing: is this signal real?

A <VocabTooltip slug="hypothesis-testing">hypothesis test</VocabTooltip> asks: assuming our strategy has _no_ edge (null hypothesis), how likely is it that we would see results at least this good by chance?

```python
# t-test: is our mean return significantly different from zero?
# H0: mean return = 0 (no edge)
# H1: mean return != 0 (there is an edge)
t_stat, p_value = stats.ttest_1samp(daily_returns, popmean=0)

print(f"t-statistic: {t_stat:.3f}")
print(f"p-value:     {p_value:.4f}")

# p-value < 0.05 means: IF there were no edge, seeing this result by
# chance would happen less than 5% of the time — conventional evidence threshold
if p_value < 0.05:
    print("Reject H0: evidence of a real edge (at 5% significance level)")
else:
    print("Fail to reject H0: could be noise")
```

The <VocabTooltip slug="p-value">p-value</VocabTooltip> is the probability of seeing your results (or more extreme) _assuming the null hypothesis is true_. It is NOT the probability that your strategy is profitable. This is the most common misinterpretation in quantitative finance.

### Type I and Type II errors in trading

| Error type               | Definition                         | In trading terms                     |
| ------------------------ | ---------------------------------- | ------------------------------------ |
| Type I (false positive)  | Reject H0 when it is true          | Trade a signal that has no real edge |
| Type II (false negative) | Fail to reject H0 when it is false | Miss a real edge and don't trade it  |

Trading biases toward Type I errors: overfitting and data mining make strategies _look_ significant when they are not.

## What you learned

- A <VocabTooltip slug="log-normal-distribution">log-normal distribution</VocabTooltip> models stock prices (bounded below at zero); working in log-returns is the standard convention because it makes returns approximately normal
- <VocabTooltip slug="fat-tails">Fat tails</VocabTooltip> (kurtosis > 3) mean extreme market moves are far more common than normal distribution models predict — standard deviation alone understates risk
- The <VocabTooltip slug="sharpe-ratio">Sharpe ratio</VocabTooltip> normalizes return by volatility; values above 1 indicate a strategy earning more excess return per unit of risk than most asset classes
- A <VocabTooltip slug="p-value">p-value</VocabTooltip> measures how surprising your results would be under the null hypothesis, not the probability your strategy is profitable
- The multiple testing problem means running many signals inflates false discoveries — the more signals you test, the more you expect to pass by luck alone
