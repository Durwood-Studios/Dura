## Why this matters

Your order-management system creates and destroys Order objects on every fill, cancel, and new order arrival. Each `new Order(...)` calls `malloc`, which — even in a fast implementation — costs 20–100 ns and may acquire a lock. On a busy book with 500,000 order events per second, those allocations alone consume 10–50 ms of CPU time per second. Worse, the objects returned by malloc are scattered across virtual memory, so the order-ID lookup table incurs TLB misses on every access.

The industry solution is to never call malloc on the hot path at all. Allocate everything at startup into a pool. Reuse objects without returning memory to the OS.

## The arena allocator

The simplest correct allocator is a bump-pointer arena: a large contiguous block of memory with a pointer that advances forward with each allocation. Deallocation is a no-op; the entire arena is freed at once.

```cpp
#include <cstddef>
#include <cstdlib>
#include <cassert>
#include <new>
#include <span>

// Bump-pointer arena: O(1) alloc, O(1) reset, no per-object free.
// Invariant: all objects in the arena have the same lifetime as the arena.
class Arena {
public:
    explicit Arena(std::size_t capacity)
        : _base{static_cast<std::byte*>(std::aligned_alloc(64, capacity))}
        , _cursor{_base}
        , _end{_base + capacity} {
        if (!_base) throw std::bad_alloc{};
    }

    ~Arena() { std::free(_base); }

    // Allocate sz bytes aligned to align. Returns nullptr if out of space.
    [[nodiscard]] void* alloc(std::size_t sz, std::size_t align = alignof(std::max_align_t)) noexcept {
        // Align _cursor up to the requested alignment
        std::uintptr_t cur = reinterpret_cast<std::uintptr_t>(_cursor);
        std::uintptr_t aligned = (cur + align - 1) & ~(align - 1);
        std::byte* new_cursor = reinterpret_cast<std::byte*>(aligned) + sz;
        if (new_cursor > _end) [[unlikely]] return nullptr;
        _cursor = new_cursor;
        return reinterpret_cast<void*>(aligned);
    }

    // Reset: all memory is reclaimed in O(1). No destructors called.
    // Only safe when all objects' destructors are trivial or already called.
    void reset() noexcept { _cursor = _base; }

    std::size_t used()      const noexcept { return static_cast<std::size_t>(_cursor - _base); }
    std::size_t remaining() const noexcept { return static_cast<std::size_t>(_end - _cursor); }

    // Disable copy/move — arena owns its memory
    Arena(const Arena&) = delete;
    Arena& operator=(const Arena&) = delete;

private:
    std::byte* const _base;
    std::byte*       _cursor;
    std::byte* const _end;
};

// Construct a T in-place in the arena
template <typename T, typename... Args>
T* arena_new(Arena& a, Args&&... args) {
    void* p = a.alloc(sizeof(T), alignof(T));
    if (!p) [[unlikely]] throw std::bad_alloc{};
    return ::new (p) T{std::forward<Args>(args)...};
}
```

The arena is the workhorse for read-side-heavy data: market data handlers allocate parsed message structs into a per-tick arena, process them, then reset the entire arena at the end of each tick. Zero fragmentation, guaranteed contiguous layout, excellent TLB behavior.

## The typed object pool

When objects have non-trivial lifetimes — orders that arrive and are cancelled at different times — a bump-pointer arena does not suffice. You need a pool that supports individual deallocation while keeping objects contiguous and avoiding malloc:

```cpp
#include <array>
#include <cstdint>
#include <limits>

struct Order {
    uint64_t order_id;
    int64_t  price;        // ticks × 10000
    int32_t  qty;
    int32_t  filled;
    uint8_t  side;         // 0 = bid, 1 = ask
    uint8_t  status;       // 0 = new, 1 = partial, 2 = filled, 3 = cancelled
    uint16_t _pad;
};

// Fixed-capacity typed object pool using a free-list.
// All Order objects live in a contiguous array — cache-friendly.
template <typename T, std::size_t Capacity>
class ObjectPool {
public:
    ObjectPool() {
        // Initialize free list: each slot points to the next free slot
        for (std::size_t i = 0; i < Capacity - 1; ++i)
            _free_next[i] = static_cast<uint32_t>(i + 1);
        _free_next[Capacity - 1] = NONE;
        _free_head = 0;
    }

    // Allocate one T, construct it with args. Returns nullptr if pool is full.
    template <typename... Args>
    T* alloc(Args&&... args) noexcept {
        if (_free_head == NONE) [[unlikely]] return nullptr;
        uint32_t slot = _free_head;
        _free_head = _free_next[slot];
        return ::new (&_slots[slot]) T{std::forward<Args>(args)...};
    }

    // Return T to the pool. Calls destructor.
    void free(T* p) noexcept {
        p->~T();
        uint32_t slot = static_cast<uint32_t>(
            reinterpret_cast<std::aligned_storage_t<sizeof(T), alignof(T)>*>(p) - _slots);
        _free_next[slot] = _free_head;
        _free_head = slot;
    }

    bool empty() const noexcept { return _free_head == NONE; }

private:
    static constexpr uint32_t NONE = std::numeric_limits<uint32_t>::max();

    // All T objects live in this contiguous array — guaranteed cache locality
    alignas(64) std::aligned_storage_t<sizeof(T), alignof(T)> _slots[Capacity];

    // Free-list: _free_next[i] = index of next free slot after slot i
    uint32_t _free_next[Capacity];
    uint32_t _free_head;
};

// Usage: pre-allocate at startup, use on the hot path
ObjectPool<Order, 1'000'000> order_pool;

void on_new_order(uint64_t id, int64_t price, int32_t qty, uint8_t side) {
    Order* o = order_pool.alloc(id, price, qty, 0, side, 0);
    if (!o) [[unlikely]] { /* pool exhausted — log and reject */ return; }
    // Register in order-ID map, insert into book...
}

void on_cancel(Order* o) {
    // Remove from book...
    order_pool.free(o);  // O(1) — just updates the free-list pointer
}
```

The key property: `_slots` is a contiguous array. Every Order object lives within this block. When the order-ID hash table points to an Order, the pointer is always within a known memory region, so the TLB needs only enough entries to cover `Capacity × sizeof(Order)` bytes — a predictable, pre-allocatable footprint.

## std::pmr: wiring pool allocators into standard containers

C++17's `std::pmr` (polymorphic memory resources) lets you plug custom allocators into `std::vector`, `std::list`, `std::unordered_map`, and other containers without template gymnastics:

```cpp
#include <memory_resource>
#include <vector>
#include <array>

// Pre-allocated 8 MB backing buffer — no malloc at all
alignas(64) std::array<std::byte, 8 * 1024 * 1024> buf;

// monotonic_buffer_resource is the std::pmr equivalent of Arena
std::pmr::monotonic_buffer_resource mono_res{buf.data(), buf.size()};

// Use it with a standard container
std::pmr::vector<int64_t> prices{&mono_res};  // uses buf, not the global heap
prices.reserve(65536);                          // no malloc — allocates from buf

// For a pool of same-size objects, unsynchronized_pool_resource is faster:
std::pmr::unsynchronized_pool_resource pool_res{&mono_res};
// unsynchronized = single-threaded; pool_res does not lock
std::pmr::vector<Order*> active_orders{&pool_res};
```

`monotonic_buffer_resource` wraps a fixed buffer and is the fastest possible allocator: a bump pointer with no thread synchronization and no free. `unsynchronized_pool_resource` adds a per-size free-list on top of a backing resource, enabling deallocation without the OS.
