## Why this matters

AI APIs charge per token. A sloppy prompt can cost 10x more than a tight one. Understanding token economics is the difference between an AI feature that's profitable and one that bankrupts your budget.

## Start with something familiar

A taxi meter charges for measurable travel rather than how useful the trip was. Repeating a journey runs the meter again.

## The mental model

> Token billing measures model-specific input and output usage; estimate each rate separately and include repeated calls in the budget.

## What a token costs

The following fictional tiers are arithmetic fixtures, not current vendor quotes. Rates are dollars per million tokens, split between input and output:

```text
Example medium:  $3 / 1M input,  $15 / 1M output
Example large:    $15 / 1M input, $75 / 1M output
Example standard:           $2.50 / 1M input, $10 / 1M output
Example small:      $0.15 / 1M input, $0.60 / 1M output
```

Input and output can have different prices. Their ratio is a provider pricing decision, not a fixed law. Generation is sequential, but actual billing also depends on model, modality, cache use, and service options. Check the current [OpenAI pricing](https://openai.com/api/pricing/) or [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) before budgeting.

## Estimating costs before you run

```javascript
function estimateCost(inputText, expectedOutputTokens, model) {
  const pricing = {
    "medium": { input: 3, output: 15 },
    "standard": { input: 2.5, output: 10 },
    "small": { input: 0.15, output: 0.6 },
  };

  const rates = pricing[model];
  // Rough English-text estimate only; use the provider tokenizer/count endpoint for billing.
  const inputTokens = Math.ceil(inputText.length / 4);
  const inputCost = (inputTokens / 1_000_000) * rates.input;
  const outputCost = (expectedOutputTokens / 1_000_000) * rates.output;

  return {
    inputTokens,
    outputTokens: expectedOutputTokens,
    totalCost: inputCost + outputCost,
  };
}
```

## Cost optimization strategies

**1. Choose the right model.** In these fixtures, the small tier input rate is 20 times lower than the medium tier rate. If your task is simple classification, use the smallest model that works.

**2. Shorter prompts.** Every token in your system prompt is charged on every request. A 500-token system prompt across 100K daily requests costs real money.

**3. Cache repeated context.** Provider prompt caching can discount eligible repeated input, but cache writes, minimum lengths, expiry, and hit rates affect the total. Measure the actual cache behavior before assuming savings.

**4. Set max_tokens wisely.** Don't set max_tokens to 4096 when you expect 100 tokens. Lower limits mean the model stops sooner.

**5. Model routing.** Use a cheap model for easy tasks and a powerful model for hard ones. A classifier routes each request.

## Context window math

```text
Context window = input tokens + output tokens

If your context window is 200K tokens and your input is 180K,
you have at most 20K tokens for the response.
```

Exceeding the window causes an error. Always leave headroom for the response.

## What you learned

- AI APIs charge per token. Output costs 3-5x more than input due to sequential generation.
- The biggest cost lever is model selection. Use the cheapest model that works for the task.
- Estimate costs before running. Cache repeated context. Set max_tokens conservatively.
