## Why this matters

A language model appears accurate during training but cannot reproduce that performance when generating text. One possible cause is information leakage: a position saw the later token it was meant to predict. Computing a small attention row makes that architectural boundary visible.

## Start with something familiar

In a closed-book prediction game, a player may read the clues already revealed but cannot turn over tomorrow’s answer card. A causal attention mask enforces that rule even when training processes many positions together.

## The mental model

> Attention mixes value vectors using query–key scores. A causal mask excludes future positions before normalization; it is not a filter applied after future information has already entered the result.

## The mechanism

A transformer represents each token position as a vector. Learned projections produce queries Q, keys K and values V. For one query, dot products with keys give compatibility scores; dividing by the square root of key dimension moderates their scale. Softmax turns the allowed scores into nonnegative weights summing to one. The output is their weighted sum of value vectors.

For causal self-attention at position i, only positions j at or before i are allowed. Set disallowed scores to negative infinity before softmax. Position information distinguishes order; attention alone does not encode which token came first. Multiple heads learn different projections. A full transformer block also has feed-forward transformations, residual connections and normalization; this scalar demonstration is only the attention mixing step.

The example accepts already-scaled scores and scalar values. It uses a numerically stable softmax: subtracting the maximum allowed score preserves the normalized weights. At position 1, the third entry is in the future. Its enormous score must have no effect.

```python
import math

def causal_mix(scores, values, position):
    if len(scores) != len(values) or not 0 <= position < len(scores):
        raise ValueError("invalid attention row")
    allowed = scores[:position + 1]
    peak = max(allowed)
    weights = [math.exp(score - peak) for score in allowed]
    total = sum(weights)
    return sum(weight * value for weight, value in zip(weights, values)) / total

assert math.isclose(causal_mix([0, 0, 100], [2, 6, 1000], 1), 4)
assert math.isclose(causal_mix([0, math.log(3), 100], [2, 6, 1000], 1), 5)
assert causal_mix([0, 100], [2, 999], 0) == 2
print("attention checks passed")
```

This finite-input fixture is not a production tensor implementation. In a real implementation, check padding masks, batches, tensor dimensions, finite values and behavior if no keys are allowed. Decoder-only language models use causal attention; encoder attention need not exclude later input positions. Do not apply one architecture’s mask rule indiscriminately to all transformer uses.

## Practice

At position 1, allowed scores are 0 and 0 and values are 2 and 6. A future value is 1000. Predict the output before running the example. Would multiplying the future weight by zero only after including it in the softmax denominator give the same result?
