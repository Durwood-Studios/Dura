## Why this matters

Streaming can show useful output before generation finishes. It does not guarantee a sub-second start or shorten total generation time. Measure time to first useful output, completion time, and interruption behavior for your workload.

## Start with something familiar

Hearing a radio sentence as it arrives feels faster than waiting for a recording, even if both finish at the same time.

## The mental model

> Streaming reduces time to visible output; transport chunks are arbitrary byte boundaries, so preserve decoder and event-parser state.

## How streaming works

Instead of waiting for the full response, the API sends **Server-Sent Events** (SSE) — small chunks of JSON, each containing a few tokens.

```text
data: {"type":"content_block_delta","delta":{"type":"text_delta","text":"A "}}
data: {"type":"content_block_delta","delta":{"type":"text_delta","text":"closure "}}
data: {"type":"content_block_delta","delta":{"type":"text_delta","text":"is "}}
data: {"type":"message_stop"}
```

An SSE event ends with a blank line and can contain multiple `data:` lines. The simplified display above omits those blank separators; a real parser must preserve partial events across network chunks. This example handles Anthropic text deltas; other providers use different event schemas.

## Consuming a stream in JavaScript

```javascript
// Server-side example: keep the provider key out of the browser.
// The caller receives errors and can keep any text already displayed.
async function streamResponse(url, body, apiKey, onText) {
  const response = await fetch(url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "x-api-key": apiKey,
      "anthropic-version": "2023-06-01",
    },
    body: JSON.stringify({ ...body, stream: true }),
    signal: AbortSignal.timeout(30000),
  });
  if (!response.ok || !response.body) {
    throw new Error(`Streaming request failed: ${response.status}`);
  }
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let pending = "";
  let fullText = "";
  let hasStopped = false;
  try {
    while (!hasStopped) {
      const { done, value } = await reader.read();
      pending += done ? decoder.decode() : decoder.decode(value, { stream: true });
      // SSE ends an event with a blank line, not a network-chunk boundary.
      let boundary;
      while ((boundary = /\r?\n\r?\n/.exec(pending))) {
        const frame = pending.slice(0, boundary.index);
        pending = pending.slice(boundary.index + boundary[0].length);
        const data = frame.split(/\r?\n/)
          .filter((line) => line.startsWith("data:"))
          .map((line) => line.slice(5).replace(/^ /, ""))
          .join("\n");
        if (!data) continue;
        const event = JSON.parse(data);
        if (event.type === "error") throw new Error("Provider interrupted the stream");
        if (event.type === "message_stop") { hasStopped = true; break; }
        if (event.type === "content_block_delta" && event.delta?.type === "text_delta") {
          fullText += event.delta.text;
          onText(fullText);
        }
      }
      if (done) break;
    }
    if (!hasStopped) throw new Error("Stream ended before completion");
    return fullText;
  } finally {
    await reader.cancel();
    reader.releaseLock();
  }
}
```

The key objects: `ReadableStream`, `getReader()`, `TextDecoder`. The stream delivers raw bytes; you decode them, split on newlines, parse the SSE events, and extract the text deltas.

## Building a streaming UI

The pattern for any streaming UI:

1. Show a typing indicator or cursor immediately.
2. As each delta arrives, append it to the displayed text.
3. On completion, finalize the message and enable actions (copy, share).
4. On error mid-stream, show what you have + an error message.

## Error handling mid-stream

Streams can break partway through — network errors, API timeouts, context overflow. Always:

- Wrap the reader loop in try/catch.
- Save partial output so the user sees what was generated.
- Show a clear "generation interrupted" message.

## What you learned

- Streaming shows tokens as they arrive, reducing perceived latency. Time-to-first-token is the key metric.
- SSE delivers `data:` lines with JSON deltas. Parse with ReadableStream + TextDecoder.
- Always handle mid-stream errors: save partial output and show a clear interruption message.
