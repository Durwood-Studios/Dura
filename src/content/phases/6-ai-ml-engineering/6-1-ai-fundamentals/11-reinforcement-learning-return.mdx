## Why this matters

An agent earns more points by repeating a cheap action instead of finishing the task. Before selecting a learning algorithm, specify what the environment rewards, when an episode ends and whether those incentives match the real objective.

## Start with something familiar

A delivery driver can optimize parcels delivered or stops visited. Rewarding stops alone may encourage visiting an easy location repeatedly. A measurable proxy can be maximized while the intended service deteriorates.

## The mental model

> A policy chooses actions from available information; actions influence later states and rewards. Return combines rewards over time. Maximizing a specified return does not guarantee that the reward captures the intended human goal.

## The mechanism

In a simple Markov decision process, a state summarizes information needed for the modeled transition. An action changes the environment, which emits a reward and next state. A policy is a rule or distribution for selecting actions. A terminal state ends the episode. Real tasks may only expose observations rather than a fully informative state.

For rewards r1,r2,r3 and discount gamma, finite return is r1 + gamma*r2 + gamma²*r3. Discounting changes the relative weight of later rewards; it is not a certificate that delays or harms are acceptable. With gamma 0.5, route A rewards[0,0,8] and route B[2,0,0] both have return 2. With gamma 1, A returns 8 and B2.

```python
def discounted_return(rewards, gamma):
    if not 0 <= gamma <= 1:
        raise ValueError("gamma outside finite-episode contract")
    result = 0
    for reward in reversed(rewards):
        result = reward + gamma * result
    return result

assert discounted_return([0, 0, 8], 0.5) == 2
assert discounted_return([2, 0, 0], 0.5) == 2
assert discounted_return([], 0.5) == 0
assert discounted_return([0, 0, 8], 1) == 8
print("return checks passed")
```

This computes a finite observed return; it does not learn a policy or estimate expected performance. Learning needs repeated experience, an exploration policy and an evaluation design. Exploration tries actions to learn their consequences, but a real system needs constraints and a safe environment; do not explore hazardous actions merely because an algorithm requests them.

Now consider a game awarding+1 for entering any room and+5 for completing delivery. If revisiting a room is rewarded and the episode never terminates, the agent may exploit repetition. A repair may change reward semantics or termination, but must be evaluated for new loopholes. Keep outcome metrics such as successful deliveries separate from training reward so reward improvement cannot conceal task failure.
