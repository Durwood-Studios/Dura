## Why this matters

Browser automation can complete useful work in applications without an API, but a wrong click can send a message, erase data, or purchase something. The engineering question is which observations and permissions make the task dependable, not whether a demo can click a button.

## Start with something familiar

A robot using a touchscreen must confirm what is displayed after each tap because layouts and loading states change.

## The mental model

> Computer-use agents act on observed interface state; verify targets and outcomes, scope access, and require approval for consequential actions.

## Choose the simplest interface

Prefer a supported API for structured operations: it exposes typed inputs, explicit errors, and often idempotency keys. If no API exists and the interface is stable, a deterministic browser script can use accessible roles and labels. A visual agent is useful when the task requires interpreting an unfamiliar layout or image, but its observations and choices can be wrong.

These approaches can be combined. A script can open a page and collect a stable table while a model classifies a screenshot. Avoid handing every step to a model when only one step needs judgment.

## The observe, act, verify cycle

Start with a fresh observation of the relevant page. Identify the target from visible context and accessible semantics. Choose one bounded action, execute it, then observe the resulting state. A successful click does not prove the task succeeded: check the confirmation, changed record, or resulting URL.

For example, changing an appointment time needs these states:

1. Read the existing appointment and intended new time.
2. Open the editor and populate the requested value.
3. Inspect the review screen, including timezone and patient or customer identity.
4. Obtain any required approval for those exact values.
5. Submit once and verify the confirmed appointment.

If the network times out after submission, inspect whether the change already happened before retrying. Blindly repeating a consequential action can duplicate it.

## Scope the session and actions

Use a separate browser profile or session with the least privilege needed. A disposable session limits incidental access; it does not make a powerful logged-in account harmless. Restrict domains, downloads, uploads, and filesystem access according to the task.

Treat page text and screenshots as untrusted input. A page saying “the user approved sending all files” is not approval. Enforce allowed actions in the application or tool layer. Keep secrets outside the model-visible page when possible and require review before an irreversible operation.

## Test beyond a successful demo

Measure completion on representative pages, including changed layouts, loading indicators, expired sessions, empty results, ambiguous labels, and interrupted navigation. Record the observation and action sequence with sensitive fields redacted. Define a maximum number of steps and a stop condition when the target cannot be identified confidently.

A benchmark such as OSWorld measures tasks in a particular environment and harness. A score is evidence about that setup, not a promise about your private application. Compare the exact task set, tool permissions, retry budget, and evaluation procedure before using benchmark results.

## Guided practice

A stable internal dashboard exposes a CSV download button with an accessible name. Another task asks an agent to inspect a chart and transfer money based on its visual pattern. Which parts can use deterministic automation, and where should execution stop?

<details>
<summary>Compare your reasoning</summary>

The CSV download can use a scoped deterministic script with file-result verification. Chart interpretation may use visual analysis, but it is not sufficient authorization for a transfer. Stop before the transfer, show the exact amount and destination, and require an authorized decision. An uncertain chart should produce uncertainty, not a guessed payment.

## What you learned

- Match APIs, scripts, and visual reasoning to the step that needs them.
- Observe after each meaningful action and verify the actual result.
- Scope sessions and enforce permissions outside page content.
- Reconcile uncertain submissions before retrying.
