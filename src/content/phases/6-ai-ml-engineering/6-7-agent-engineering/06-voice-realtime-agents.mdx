## Why this matters

Voice agents are the emerging customer-facing surface of the 2025-2026 wave. Real-time conversational AI moved from research demos to production over the past 12 months, and "voice mode" is now table stakes for support, sales, and accessibility products.

The architectural choices look superficially similar to text agents but the constraints are unforgiving: humans notice latency above ~600ms, get frustrated above 1.5s, and abandon the call above 3s. The compliance footprint is different too — voice modality often falls outside the HIPAA-eligibility umbrella that text endpoints have.

This lesson covers the two architectural approaches, the provider landscape (mid-2026), the latency budget that defines "production-ready," and the compliance gotchas you'll otherwise discover the hard way.

## Two architectural approaches

### 1. Pipeline (STT → LLM → TTS)

The classic approach: a speech-to-text model transcribes user audio, a text LLM generates a response, a text-to-speech model speaks it back. Three separate services chained.

```
[user audio] → STT (Whisper, Deepgram) → text → LLM (Claude, GPT-5) → text →
TTS (ElevenLabs, OpenAI TTS) → [agent audio]
```

**Strengths:** swap any component independently. Use whichever STT/LLM/TTS you prefer. Compliance is per-component — you can pick HIPAA-eligible STT and TTS even if a particular LLM modality isn't covered.

**Weaknesses:** higher latency (each hop adds round-trip time), loses prosody and emotional cues between STT and LLM (the LLM sees text, not tone), can't handle overlapping speech naturally.

### 2. End-to-end speech-to-speech

A single model takes audio in, produces audio out. The model "hears" intonation, pause, hesitation, and "speaks" with prosody. Notable production examples: OpenAI's `gpt-realtime`, Google's Gemini Live native audio.

```
[user audio] → end-to-end speech model → [agent audio]
```

**Strengths:** lower latency (single API call, no chaining), better prosody (model picks intonation; can express emotion), native interrupt handling, can detect emotional cues in user speech and respond accordingly.

**Weaknesses:** locked into the provider's modality (can't swap STT/TTS), compliance gaps (audio modality often not covered under the same BAA as text), more expensive per minute than pipeline.

- **Translation, multi-lingual** → Gemini Live (70 languages) or `gpt-realtime-translate`.

## The latency budget

Voice perception research has settled on rough thresholds humans care about:

- **< 200 ms** turn-taking → indistinguishable from human conversational rhythm.
- **200-600 ms** → noticeable but acceptable; feels "thoughtful."
- **600 ms - 1.5 s** → users start to wonder if it's broken.
- **> 1.5 s** → users repeat themselves or hang up.
- **> 3 s** → call abandonment rate spikes.

OpenAI Realtime's ~500ms TTFB US lands in the "noticeable but acceptable" band. A pipeline with three serial network hops typically lands at 800ms-1.5s end-to-end depending on geography, model choice, and TTS streaming behavior — survivable but not delightful.

What gets you closer to the natural-conversation threshold:

- **End-to-end models** save the inter-component round-trips. The biggest single win.
- **Streaming TTS** starts speaking as soon as the first text tokens arrive, instead of waiting for the full response. Saves 500ms-1s of perceived latency.
- **Region-local endpoints**. A round-trip to a US-east endpoint from APAC adds 200-300ms before anyone says a word.
- **VAD (voice activity detection) tuning.** Aggressive VAD interrupts faster; conservative VAD waits to confirm. Tune per use case.

## Interrupt handling

Production-grade voice agents must handle interruption — the user barging in mid-sentence. The major end-to-end APIs (OpenAI Realtime, Gemini Live) ship with interrupt handling: the model stops speaking, listens to the user, resumes (or adjusts) when they finish.

Two failure modes still need explicit handling:

1. **Cross-talk** — both speaking at once. End-to-end models often "yield" silently when they detect user speech, which is the right behavior but creates dead air. Surface a visual cue in the UI ("listening...") so users don't repeat themselves.
2. **Mid-thought resumption** — user interrupts to clarify, then says "ok go on." The agent should resume meaningfully, not restart its sentence. Most 2026 production deployments solve this with explicit "I'll continue" affordances in the agent's persona ("Let me know when you're ready and I'll pick up from where we were on...").

For pipeline deployments, you implement VAD + interrupt manually:

```javascript
// Pseudo-code for a pipeline voice agent
async function handleAgentTurn(userAudioStream, agentAudioOut) {
  let cancelled = false;
  vad.onSpeechStart(() => {
    cancelled = true;
    agentAudioOut.flush();
  });

  const userText = await stt.transcribe(userAudioStream);
  if (cancelled) return; // user already started talking again

  const stream = llm.streamResponse(userText);
  for await (const token of stream) {
    if (cancelled) break;
    await tts.streamSynthesize(token, agentAudioOut);
  }
}
```

## Compliance — the gotcha

OpenAI Realtime's audio modality is **not HIPAA-eligible under BAA as of May 2026.** Azure OpenAI's text endpoints are eligible; the audio path isn't.

Practical implication: if your voice agent ever touches Protected Health Information (PHI), the end-to-end approach with OpenAI Realtime is off the table. You need either:

- **Pipeline with all HIPAA-eligible components** — eligible STT (Azure Speech, AWS Transcribe Medical, Deepgram with BAA), eligible LLM (Azure OpenAI text endpoint, AWS Bedrock with appropriate model), eligible TTS (Azure Speech, Amazon Polly with BAA).
- **On-premise model deployment** for the speech path.

Same kind of analysis applies for GDPR (data residency), SOC 2 (audit trail of audio recordings), and industry-specific regulations (PCI for payment voice flows, FINRA for financial-services voice).

The pattern: voice agents often discover compliance constraints the text version didn't have. Engage compliance early, not after the demo lands.

## What you learned

- **Two architectures**: pipeline (STT→LLM→TTS, swappable components, per-component compliance) vs end-to-end speech-to-speech (single model, lower latency, richer prosody, provider-locked).
- **Provider landscape mid-2026**: OpenAI Realtime + `gpt-realtime` (GA, $32/M audio-in / $64/M audio-out, ~500ms TTFB), Gemini Live (70 languages, GA-ish), no Anthropic GA voice endpoint, classic component vendors (Deepgram, ElevenLabs, Whisper, AssemblyAI) remain canonical for pipeline.
- **Latency thresholds**: <200ms natural, 200-600ms acceptable, 600ms-1.5s "is it broken," >1.5s users repeat, >3s call abandonment. Streaming TTS + region-local endpoints + end-to-end models are the recovery levers.
- **Interrupt handling** is solved in production for major end-to-end APIs; cross-talk and mid-thought resumption still need explicit UI affordances ("listening...") and agent-persona affordances ("Let me know when you're ready").
- **Compliance is voice's distinct surface.** OpenAI Realtime's audio modality is NOT HIPAA-eligible under BAA as of May 2026. PHI-touching voice goes pipeline with HIPAA-eligible components. Engage compliance early.
