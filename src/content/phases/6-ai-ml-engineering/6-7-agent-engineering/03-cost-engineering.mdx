## Why this matters

Agents burn money in ways workflows don't. An agent that loops takes ten times the tokens of one that doesn't. A coding agent given a generous context window will fill it. A multi-step agent that re-reads the same system prompt on every turn pays for it every turn unless you've explicitly cached.

The teams that ship agents profitably in 2025-2026 share a discipline: every agent has a **per-task budget**, every model call is **routed to the cheapest model that can do the job**, every long-lived prompt is **cached**, and any non-interactive workload runs through a **batch API**. The savings depend on task mix, quality requirements, cache hit rate, and provider terms; no fixed percentage applies.

This lesson walks through each lever with current (mid-2026) numbers, then shows how they stack.

## Start with something familiar

A road trip budget includes detours and return travel, not just the first tank of fuel.

## The mental model

> Agent costs accumulate across context growth, tool use, retries, and parallel work; enforce run-level budgets and measure useful outcomes.

## The five cost levers

The order matters — apply them in this sequence for biggest-bang-for-effort:

1. **Model routing** — pick the smallest model that reliably solves each turn. 40-70% reported savings.
2. **Prompt caching** — never re-pay for static prefixes (system prompts, tool definitions, in-context docs).
3. **Batch APIs** — for non-interactive workloads, accept a 24h SLA in exchange for ~50% off.
4. **Hard caps in the harness** — enforce a per-task token / cost ceiling so a loop can't drain the account.
5. **Prompt shrinkage** — remove tokens that don't earn their cost (verbose system prompts, redundant tool descriptions, oversized few-shot examples).

We'll cover the first four in depth. Prompt shrinkage is universal LLM hygiene and doesn't need agent-specific treatment.

## Lever 1 — Model routing

A useful production lever when measured task quality supports it. Most agent turns don't need the smartest model; they need the cheapest one that gets it right.

**Concrete 2026 pattern (coding agents):**

| Model      | Role in the agent                                | Cost / MTok (in / out) |
| ---------- | ------------------------------------------------ | ---------------------- |
| Opus 4.7   | Coordination, planning, hard reasoning           | $5 / $25               |
| Sonnet 4.6 | Implementation — writing code, calling tools     | $3 / $15               |
| Haiku 4.5  | File navigation, triage, classification, routing | $1 / $5                |

Same agent, three models, picked per turn. The orchestrator decides "this is a triage step" → Haiku; "this is a code generation step" → Sonnet; "this requires planning across the whole codebase" → Opus.

```javascript
// Simplified routing layer
function pickModel(turn) {
  if (turn.kind === "triage" || turn.kind === "classify" || turn.kind === "file-nav") {
    return "claude-haiku-4-5";
  }
  if (turn.kind === "implementation" || turn.kind === "tool-call") {
    return "claude-sonnet-4-6";
  }
  // "plan", "review", "ambiguous-decision"
  return "claude-opus-4-7";
}

async function runTurn(turn, messages) {
  const model = pickModel(turn);
  return await client.messages.create({ model, messages, ... });
}
```

A common refinement: **adversarial review across providers**. Use a different vendor's frontier model (GPT-5-class) as the reviewer of code another model wrote. The two models disagreeing on something is a strong signal to slow down. The two agreeing is a strong signal to ship.

## Lever 2 — Prompt caching across providers

Every major provider supports caching the static prefix of a prompt. The exact mechanics differ.

| Provider      | Mechanism                                                                              | Discount                                          | TTL                                          | Gotcha                                                                       |
| ------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------- |
| **Anthropic** | Explicit `cache_control` blocks                                                        | 0.10× (90% off) cached input                      | 5 min default; 1h with write-cost premium    | Cache write costs more than uncached; only saves on the read                 |
| **OpenAI**    | Automatic on prompts ≥ 1,024 tokens                                                    | Roughly 25-50% off cached input (model-dependent) | Short, auto-managed                          | You don't control what gets cached; ordering of message content matters      |
| **Gemini**    | Implicit (auto, 75% off on 2.5+ models) AND explicit (manual lifecycle, up to 90% off) | 75-90%                                            | Manual lifecycle (explicit); auto (implicit) | Explicit cache adds a per-MTok-per-hour storage cost — a unique pricing axis |
| **DeepSeek**  | Automatic                                                                              | Strong default                                    | Auto                                         | Less control than Anthropic / Gemini                                         |

**The Anthropic pattern in code:**

```javascript
const response = await anthropic.messages.create({
  model: "claude-sonnet-4-6",
  max_tokens: 1024,
  system: [
    {
      type: "text",
      text: SYSTEM_PROMPT, // long, static
      cache_control: { type: "ephemeral" }, // mark for caching
    },
  ],
  tools: TOOLS_DEFINITION.map((t) => ({
    ...t,
    cache_control: { type: "ephemeral" }, // cache tool defs too
  })),
  messages: [
    {
      role: "user",
      content: [
        {
          type: "text",
          text: IN_CONTEXT_DOCS, // long, static
          cache_control: { type: "ephemeral" },
        },
        { type: "text", text: userMessage }, // dynamic — NOT cached
      ],
    },
  ],
});
```

**Where caching most pays off in agent workloads:**

- **System prompt** — usually 500-5,000 tokens, identical every turn. Cache it.
- **Tool definitions** — same set of tools across the agent's life. Cache them.
- **In-context documents (RAG injections, file contents)** — large and static within a session. Cache them.
- **Few-shot examples** — large and static. Cache them.

The pattern: anything that doesn't change between turns of the same agent run, mark for caching. The savings compound across long sessions — a 50-turn agent run with a 4K-token static prefix saves the cost of 200K tokens of input.

## Lever 3 — Batch APIs

For non-interactive agent workloads (overnight analyses, scheduled report generation, bulk classification, evaluation runs against regression sets), batch APIs trade latency for cost.

| Provider                      | Discount                    | SLA       | Notes                                             |
| ----------------------------- | --------------------------- | --------- | ------------------------------------------------- |
| **Anthropic Message Batches** | 50% off on input AND output | Up to 24h | No volume threshold; combines with prompt caching |
| **OpenAI Batch API**          | ~50% off                    | 24h       | Combines with caching                             |
| **Gemini Batch API**          | ~50% off                    | Variable  | Available for most Gemini models                  |

```javascript
// Anthropic Messages Batches — bulk classification example
const batch = await anthropic.messages.batches.create({
  requests: candidateMessages.map((msg, i) => ({
    custom_id: `classify-${i}`,
    params: {
      model: "claude-haiku-4-5",
      max_tokens: 100,
      messages: [{ role: "user", content: `Classify: ${msg}` }],
    },
  })),
});
// Poll batch.id; results return within 24h, billed at 50% off.
```

When to reach for batch:

- **Eval runs against your regression set** (lesson 02) — perfect fit, you'd never run those interactively.
- **Nightly digest / report generation** — your readers don't care if the report finished at 2am or 6am.
- **Bulk classification / extraction** — pipelining work that has no user waiting.
- **Synthetic data generation** — same.

When NOT to use batch:

- **Anything a user is waiting for in real time.** A 24h SLA is fine for a nightly job; it's a disaster for a chat reply.

## The stacking math

Caching and batching combine multiplicatively. Walk the math for an Anthropic Sonnet 4.6 workload:

| Optimization                             | Effective input cost                           |
| ---------------------------------------- | ---------------------------------------------- |
| Base rate                                | $3 / MTok                                      |
| Caching only (90% off on cached portion) | $0.30 / MTok on cached input                   |
| Batch only (50% off)                     | $1.50 / MTok                                   |
| **Caching + Batch**                      | **$0.15 / MTok on cached input** — ~5% of base |

For the simplified example with80% cacheable input, a90% cache discount and50% batch discount, the weighted input cost is0.8×0.1×0.5 +0.2×1×0.5 =0.14 of base cost, an86% saving before cache writes and other fees. Verify the current provider rates, write costs, eligibility, and turnaround terms before budgeting.

The discipline: design your agent so the **cacheable prefix is long** and the **dynamic suffix is short**. Move tool definitions, system prompts, and few-shot examples to the front. Append only the user's actual message at the end.

## Lever 4 — Hard caps in the harness

The fail-deadly mode for agents is the unbounded loop. The agent decides to keep going, the keep-going decision keeps validating itself, and you wake up to a $4,000 single-task bill.

The mitigation is structural: **the agent harness, not the model, enforces the ceiling.**

```javascript
class TaskBudget {
  constructor({ maxTokens, maxCostUsd, maxTurns, maxWallClockMs }) {
    this.usedTokens = 0;
    this.usedCostUsd = 0;
    this.turns = 0;
    this.startedAt = Date.now();
    this.maxTokens = maxTokens;
    this.maxCostUsd = maxCostUsd;
    this.maxTurns = maxTurns;
    this.maxWallClockMs = maxWallClockMs;
  }

  recordTurn({ inputTokens, outputTokens, costUsd }) {
    this.usedTokens += inputTokens + outputTokens;
    this.usedCostUsd += costUsd;
    this.turns += 1;
  }

  enforce() {
    if (this.usedTokens >= this.maxTokens) throw new BudgetError("tokens");
    if (this.usedCostUsd >= this.maxCostUsd) throw new BudgetError("cost");
    if (this.turns >= this.maxTurns) throw new BudgetError("turns");
    if (Date.now() - this.startedAt >= this.maxWallClockMs) throw new BudgetError("wall_clock");
  }
}

// In the agent loop:
const budget = new TaskBudget({
  maxTokens: 500_000,
  maxCostUsd: 0.4,
  maxTurns: 50,
  maxWallClockMs: 10 * 60 * 1000,
});

while (!done) {
  budget.enforce();
  const turn = await runTurn(/* ... */);
  budget.recordTurn(turn.usage);
  // ...
}
```

The most useful number to pick is `maxCostUsd` — the **cost-per-task budget**. Production teams now set this explicitly and tune it per task class. "Max $0.40 per SWE-bench-style code-fix attempt." "Max $0.05 per support classification." When the budget hits zero, the harness raises, the agent stops, and a fallback path (escalate to human, return partial result, retry from checkpoint) takes over.

## A worked end-to-end example

Take a coding-agent task: "fix the failing test in this file."

**Without optimization:**

- Opus 4.7 for every turn.
- No caching of system prompt, tool definitions, or file contents.
- 40 turns; average 8K input + 1.5K output per turn.
- Input: 40 × 8K × $5/MTok = $1.60. Output: 40 × 1.5K × $25/MTok = $1.50. **Total: $3.10 per task.**

**With routing + caching:**

- Haiku 4.5 for file-nav + triage (16 turns), Sonnet 4.6 for implementation (20 turns), Opus 4.7 for planning + review (4 turns).
- 90% of input is the static system+tools+file prefix; cached.
- Cached input billed at 0.10× rate-card; dynamic input at full rate-card.
- Input: 4 × (0.8K dyn + 7.2K cached at 0.10×) × $5 = $0.058 + 20 × (0.8K dyn + 7.2K cached) × $3 = $0.092 + 16 × (0.8K dyn + 7.2K cached) × $1 = $0.024. Output stays at full rate-card: 4 × 1.5K × $25 + 20 × 1.5K × $15 + 16 × 1.5K × $5 = $0.15 + $0.45 + $0.12. **Total: ~$0.91 per task.**

**A ~70% reduction**, without changing what the agent does — only how the harness arranges to do it.

(Batch is excluded because this example is interactive. For eval runs against a regression set of 1,000 similar tasks, batch would cut another ~50%, bringing per-task cost to roughly $0.45 of which most is output tokens that aren't discounted by caching.)
