## Why this matters

An aircraft is built from 6 million parts, each manufactured to a specific design revision, installed in a specific configuration, and documented in a permanent record. When the aircraft comes in for maintenance 10 years later, the maintenance team needs to know exactly which configuration was installed — which revision of each component, which modification status. The maintenance manual tells them what to inspect; the aircraft's configuration record tells them what's actually there.

Configuration management is the discipline that keeps the design baseline (what engineering says the hardware should be) synchronized with the production baseline (what is actually being manufactured) and the delivered baseline (what was actually shipped). When these three fall out of sync — when the design has been revised but the production router hasn't been updated, or when production has made an undocumented deviation — the result is field maintenance based on wrong assumptions about what's installed.

## AS9100D §8.1.2 — What the standard requires

ISO 9001:2015 §8.1 (operation planning and control) contains no specific CM requirement. AS9100D §8.1.2 adds:

> "The organization shall establish, implement and maintain a configuration management process that includes, as appropriate to the product or service: (a) configuration management planning; (b) configuration identification; (c) configuration change management; (d) configuration status accounting; (e) configuration audits."

These five elements are the AS9100D CM system:

### (a) Configuration management planning

A documented plan that identifies:

- Which products and product components are subject to CM (the "configuration items")
- Who owns the CM process
- Which documentation is the authoritative design baseline
- The process for recording configuration status

CM planning is typically a QMS procedure that references the product-specific configuration management plan for major programs.

### (b) Configuration identification

Each configuration item receives a unique identifier that links the physical hardware to its design documentation. For a machined component, the configuration identifier is typically:

- Part number + drawing revision level
- Lot or serial number
- Applicable special process specifications and their revision levels

Configuration identification creates the mapping from "serial number 00123" to "Part No. 7892-A, Drawing Rev C, built per Process Spec PS-3 Rev 2." Without this mapping, you cannot perform maintenance against the correct manual or identify the scope of a field service bulletin.

### (c) Configuration change management

The formal process for managing engineering changes:

1. **Engineering Change Proposal (ECP)** — the initiator (engineering, manufacturing, customer) identifies a proposed change to the design baseline.
2. **Impact assessment** — the change is assessed for downstream effects: manufacturing tooling, quality inspection plans, supplier purchase orders, deployed hardware.
3. **Configuration Control Board (CCB) approval** — a multi-disciplinary team (engineering, manufacturing, quality, contracts, customer representative) reviews and approves or rejects the change.
4. **Effectivity planning** — the change is given an effectivity point: "effective at serial number 1150" or "effective at lot date code 26Q3." Effectivity controls when the change becomes incorporated in production.
5. **Cascade to production documentation** — the approved change is cascaded to all affected documents: manufacturing router, inspection plan, SPC control charts, supplier purchase orders, qualification records.
6. **Engineering Change Order (ECO) release** — the formal release that authorizes production to begin building to the new configuration.

Step 5 (cascade to production documentation) is where most CM failures occur. The engineering system has been updated; the manufacturing system has not been updated because the cascade process was not documented or executed.

### (d) Configuration status accounting

The documented record of the current approved configuration of each configuration item, and the history of changes to that configuration. Status accounting answers: "What configuration is this hardware currently built to?" and "What changes have been incorporated since initial design baseline?"

Status accounting is the bridge between the as-designed and as-built configurations. The as-designed configuration is the current approved design baseline. The as-built configuration is the actual configuration incorporated in manufactured hardware. When they diverge (a configuration deviation is accepted, or a change is in transition), status accounting documents the divergence.

### (e) Configuration audits

Two types of configuration audits:

- **Functional Configuration Audit (FCA)** — verifies that the product's performance meets the functional requirements of the design baseline. Performed before the design baseline is finalized.
- **Physical Configuration Audit (PCA)** — verifies that the actual product built matches the engineering documentation. The PCA walks the physical hardware against the drawing, the manufacturing router, the inspection records, and the configuration status account.

The PCA is the most operationally significant for suppliers. An AS9100D supplier customer may require a PCA on the first article as part of the First Article Inspection (FAI) process (per AS9102).

## The as-designed / as-built gap

The most common CM finding in an AS9100D supplier audit: the as-designed configuration (current engineering drawings) and the as-built configuration (what is on the production floor and in outgoing inspection) are not synchronized.

Sources of the gap:

| Gap Source                                           | Example                                                                     | CM Process That Prevents It                               |
| ---------------------------------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------- |
| Engineering change not cascaded to manufacturing     | Drawing revised Rev B → Rev C; manufacturing router still reads Rev B       | §8.1.2(c) change management cascade step                  |
| Drawing revision at inspection but not at production | Inspector uses Rev C drawing; machinist uses Rev B setup sheet              | Configuration identification on each document             |
| Supplier's sub-tier not updated                      | Part spec updated; Tier 2 supplier never notified                           | Purchase order revision and supplier notification process |
| Undocumented manufacturing deviation                 | Operator used a non-spec material because correct material was out of stock | Deviation/waiver process (§8.3.6 in AS9100D)              |
