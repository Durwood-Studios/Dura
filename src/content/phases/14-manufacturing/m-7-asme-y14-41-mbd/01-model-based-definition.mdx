## Why this matters

A supplier can make the wrong part from a convincing 3D view. The missing information may be a tolerance, a material note, or the rule identifying which revision controls. A useful receiving review proves that the package is complete and usable before manufacturing or inspection programming begins.

## Start with something familiar

Imagine receiving a recipe as a photograph of the finished meal. The shape is visible, but the ingredients and cooking instructions are missing. A geometry file can have the same limitation: the model needs linked requirements and an agreed status, not only an attractive display.

## The mental model

> A product definition is a controlled set of geometry and requirements. File format, semantic completeness, revision, and contractual authority are separate checks.

## Geometry, PMI, and authority

Model-based definition uses the digital model as part of the product definition. Product manufacturing information (PMI) includes dimensions, geometric tolerances, datum references, notes, and related requirements. A datum is a specified reference for interpreting a geometric requirement. Geometry alone does not tell an inspector every allowable deviation.

ASME Y14.41 addresses digital product definition practices; it does not automatically make every drawing non-authoritative. A released package may designate a model, a drawing, or a controlled combination. Read the package's precedence and revision instructions. When documents conflict, preserve the discrepancy and request a controlled clarification; selecting the more convenient tolerance is not resolution.

## Readable is different from machine-interpretable

Graphical PMI can look correct on screen while semantic PMI associates structured tolerances with particular model features. STEP AP242 supports model-based exchange, but an AP242 filename does not prove that a particular export contains every required PMI item or that a receiving tool imports it correctly. Native CAD, JT, and other formats also require an agreed capability check; the format name does not establish authority.

For a receiving test, identify one critical feature, inspect its displayed tolerance, query its semantic association, and compare its units and datum order with the released requirement. Keep the source revision, exporter/importer versions, and discrepancy record. Repeat against the defined acceptance sample or complete characteristic set; one successful feature does not validate the entire package.

## A concrete handoff

Suppose package BRACKET-C declares model revision C authoritative for geometry and PMI, with drawing C carrying material and finish notes. A supplier exports a shop-floor drawing. That derived drawing may help communication, but it cannot silently replace either controlling source. The inspection record must identify which released characteristic was checked and which supporting note applied. A model-only workflow is not complete if required material information was left behind.

## Guided practice

Package A says drawing B controls tolerances; model C is reference geometry. The model has a tighter hole tolerance than the drawing. Which requirement can the inspector choose, and what needs clarification?
