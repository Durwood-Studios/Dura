## Why this matters

Two offline devices increment a shared counter and later exchange state. Adding their totals double-counts updates already seen by both. A merge rule must match the data type’s semantics.

## Start with something familiar

Two clerks each keep their own tally column. Combining the largest known value for each clerk avoids counting a copied tally twice. Summing whole copied sheets does not.

## The mental model

> A grow-only counter stores one monotonically increasing component per replica and merges componentwise maximum. Its convergence properties depend on those rules; they do not solve arbitrary edits, deletion or access control.

## The mechanism

For replicas A and B, state maps replica identity to its local cumulative increments. A replica changes only its own component and never decreases it. The visible count is the sum of components. Merge takes the maximum known value for each identity.

```python
def merge(left, right):
    return {key: max(left.get(key, 0), right.get(key, 0)) for key in left.keys() | right.keys()}

a = {"A": 2}
b = {"B": 3}
combined = merge(a, b)
assert sum(combined.values()) == 5
assert merge(combined, b) == combined
assert merge(a, b) == merge(b, a)
assert merge(merge(a, b), {"A": 4}) == merge(a, merge(b, {"A": 4}))
print("CRDT checks passed")
```

Idempotence means merging the same state again changes nothing. Commutativity means merge order does not matter. Associativity means grouping merges does not matter. These algebraic properties support convergence when replicas eventually receive the relevant updates under the model’s assumptions.

Replica identity must be stable and uniquely owned for local increments. Reusing an identity after losing its component state can break the intended increment semantics. This fixture does not implement durable replica management, hostile-value validation or network delivery.

A decrement is not supported by this grow-only design. Other CRDTs have different state and rules, such as separate positive/negative components or observed-remove metadata. Do not delete a component and expect the same convergence guarantee. A merged count also says nothing about who was authorized to increment it.

Use the smallest data type whose semantics match the product. Collaborative text, inventory reservations and financial balances have constraints beyond a grow-only counter; CRDT branding does not remove the need to analyze invariants and conflict meaning.
